# 分析报告：开发历程、技术演进与当前状态

- 对应底稿：`retrieval-report.md` 第 4、6、7 节
- 分析日期：2026-10-14

---

## 执行摘要

这是一个**长周期、单人主导、技术债沉重但持续有真实工程投入**的独立项目。它的开发史呈现明显的双峰结构：2018–2020 的 Steam 抢先体验期（最高在线 257 人），以及 2022 年下半年因健康中断后短暂回归的高强度冲刺（0.14 系列，两个月内发布 20+ 个版本）。此后项目完全停滞——**最后一次构建是 2023-05-20**，截至今日已静默三年五个月。

从工程角度看，0.14.0 是一次真正的技术断代：从 .NET Framework 时代迁移到 .NET Core + MonoGame 3.8，代价是体积暴涨与跨平台回归风险，但换来了多线程稳定性与本地化 mod 能力的扩展点。开发者在 0.15.0 规划中已经把问题诊断得很清楚（生态位过薄 → habitat 系统），却没有机会实施。

## 一、开发阶段划分

### 阶段 A：网站时代（2007 / 2011 – 2018）

| 特征 | 内容 |
|------|------|
| 起点 | 开发者自述"以某种形式做了大约 8 年"，2011 年起持续投入 |
| 分发 | 官网 alpha 免费下载，需 Microsoft XNA 3.1 运行库，0.4.1 版本仅 43.5 MB |
| 早期里程碑 | 2012-05-27 首个可记录 Windows 版本（0.x） |
| 众筹 | Indiegogo 灵活筹款，目标 $25,000，**实际 $1,016 / 43 人**；档位 $10（谢谢）到 $200（灾难设计者/生物群系） |
| 开发者表态 | "我们完全清楚这次众筹远达不到最初过于乐观的 $25k 目标……但这并不意味着 Species 就此终结。哪怕自掏腰包，我们也会把这游戏做出来" |

**分析**：$1,016 的众筹结果（完成率 4%）本应是一个终止信号。开发者选择继续自费开发，且在众筹页面公开承认失败并解释原因，这种透明度在独立游戏众筹中并不常见。从 2012 到 2018 的 6 年跨度、数十个 alpha 版本，说明这是一份**以个人兴趣驱动、可随时暂停的长期业余项目**——这为后来的中断埋下了结构基础。

---

### 阶段 B：Steam 抢先体验（2018-09-28 – 2020-09）

**关键数据**
- 历史最高同时在线：**257 人（2019-01-15）**
- 2018-09 首发月峰值 52 → 2018-12 峰值 56 → **2019-01 峰值 257（首发红利 + Vinesauce 等 UP 主传播）** → 2019-03 降至 67 → 此后长期在 20–40 区间

**工程进展**
- **0.11.2.0（2018-11-21）**：macOS 版本发布（由 Jared 与 Jay 两位志愿者协助测试）；大量平衡性调整——扩大存活能力曲线、修正尾部基因对生物的实际影响、调整头部 "Eat Rate" 对氧气吸收的影响、修正捕食抑制系统导致肉食生物无食可吃的问题
- **0.12.0.x（2019-04 ~ 09）**：
  - 修复长期困扰的 **`ArithmeticException`**（腿部动画相关，官方称"游戏中最常见的崩溃原因"）
  - 引入**多线程原型**，官方提供独立可执行文件供测试
  - UI 全面改造以支持可变字号字体
  - New World 界面从"数字微调器构成的密不透风的墙"重构为四段式：Quickstart / Starting Creatures / World Editor / Advanced Settings
  - 季节系统（湿季/旱季）
- **0.13.1.0（2020-06-23）**：**Play as Creature**——以选中个体视角游玩，自动追踪直系亲属，官方承认这会让 AI 的缺陷"暴露无遗"
- **0.13.2.x（2020-09-16 ~ 17）**：捕食行为大改（超出探测范围时潜伏接近以节约能量）、大量多线程竞态崩溃修复（Behaviour Tree 并发修改、目标/combatInstance 置空）

**分析**：这一阶段是**工程修复期而非功能扩张期**。官方在 Early Access 问卷中把"进化模拟"列为最高优先级，与实际投入一致。值得注意的是多线程化是在 2019 年就开始的，说明性能瓶颈很早就被识别为阻碍"数百生物同屏"这一核心卖点的硬约束。

### 阶段 C：停滞（2020-09 → 2022-06）

- **0.13.2.2（2020-09-17）** 是这一阶段最后的版本记录
- 玩家侧感知为"没有游戏或新闻更新约 4 年"

**官方解释**（来源：2022-06-19 公告 "I'm back"）
> "简要说：我曾遭受未经治疗的精神疾病，现在正在接受治疗。多亏找到了合适的药物，我的动力和精力比很多年都要好，正急切地重新投入开发。对我看起来像是抛弃了这款游戏，我感到抱歉……我没有任何借口，对不起。"

**分析**

这是全项目**信息透明度最高的一次官方沟通**，也是理解项目状态的关键。需要注意几点：

1. 停滞并非技术失败或商业失败导致，而是**个人健康原因**。这意味着项目没有"设计死亡"，存在复活的技术可能性
2. 开发者的措辞"我本应更好地沟通我的情况"说明此前的沟通失败（而非承诺失败）是主要遗憾
3. 玩家社区对 2022 年这次回归的反馈整体是正面的——多条评测提到"如果你不介意崩溃和无更新，这是款好游戏""Quasar你有这个实力"

**可信度**：高（开发者本人一手陈述）

---

### 阶段 D：回归冲刺（2022-06 → 2023-05）

这是全项目**工程密度最高的时期**，约 11 个月内可见 0.14.0 → 0.14.2.6 二十余个版本。

#### D1. 技术断代：MonoGame 3.8 迁移（0.14.0，2022-08-14 → 08-31）

官方对 0.14.0 的自评相当坦率：
> "0.14.0 构建在一个与 0.13 完全不同的基础上。MonoGame 3.8 在底层相比之前的版本有显著变化，我完全预计这会造成问题，**特别是 Linux 和 Mac 构建，我此前无法测试**。这次底层变更也会导致它占用比之前多得多的硬盘空间：当前版本体积为 687 MB，我可能还需进一步增加以确保跨平台……"

0.14.1 公告补充技术基线：**基于 .NET Core 与 MonoGame 3.8**。

#### D2. 稳定性宣称（0.14.1，2022-08-31）

> "0.14.1 明显比 0.13.X 系列更稳定。几乎所有已知崩溃和大量非预期行为都已修复。**在低性能情况下仍有一些已知崩溃会发生，因此建议保持两位数 FPS 获得最佳效果。注意：保持高 FPS 最有效的方式是降低生物数量上限。**"

#### D3. 功能更新密度（2022-09 单月）

| 版本 | 日期 | 关键变更 |
|------|------|---------|
| 0.14.1.2 | 09-03 | 重新让 Predator/Prey 起始状态可行；草地与地表植被能量翻倍；修复围栏附近觅食 AI 死循环；修复 Linux 启动崩溃 |
| 0.14.1.5 | 09-05 | 生物头顶任务进度条（进食/睡眠/战斗/窒息/孵化/妊娠）；修复半成品 NaN 崩溃 |
| 0.14.1.6 | 09-07 | **Gene Cycling**（逐基因人工选择）——官方标注为"实验性功能，测试中效果不理想" |
| 0.14.1.7 | 09-09 | **Nursery TURBOCHARGE**；树木遮荫 |
| 0.14.1.9 | 09-13 | **Creature AI 提速约 17%**；修复存档/读档 IndexOutOfRange |
| 0.14.1.10 | 09-17 | **dietary pie chart 加入 clade diagram 与 satellite map**；多项战斗/围栏/多线程崩溃修复 |
| 0.14.1.12 | 09-28 | 生命体、尸体、蛋、树等对象的**内存池化重构** |
| 0.14.1.14 | 10-02 | 修复 0.14.1.12 引入的**内存泄漏**（导致连续冻结最终无响应） |

#### D4. 本地化与音乐（0.14.2.0，2022-10-10）

- 首次**支持本地化 mod**，无任何玩法改动
- 新增 3 首曲目，由 Discord 社区用户 **Poliostasis** 制作

#### D5. 官方路线图（2022-10-24，"Where to next? — 0.15.0"）

这是**最后一份有据可查的官方开发方向**，核心判断是：

> "最近我在推动疲劳、睡眠、温度和对环境要素的暴露，都需要成为远比现在更重要的生存需求。让我们把这些机制统一到 **'habitat'（栖境）** 这把伞下。最终，**habitat 在生存与选择压力上的重要性将几乎与食物相当**，生物必须在两者之间取得平衡才能活得足够久去繁殖。"
>
> "不幸的是，我发现**当前的植被模型完全不足以支撑我对这些的计划，它最后一次让我失望**。"
>
> "树木需要保持高性能。它们不是模拟的中心：它们的角色不值得它们痛饮 FPS 之泉。**树木应该进化。可进化的树木大概是第二高被请求的功能，紧随飞行之后**。它一直都在计划中，尽管从未作为游戏的核心。"

**分析**：这段话暴露了设计层面的一个关键依赖问题——**植被/树木模型是 habitat 系统的前置依赖**。要实现 habitat，就必先重做植被；而树木不能消耗过多性能，于是提出"轻量化但可进化"的方案。这个思路是清晰且合理的，但它意味着 0.15.0 是一个**涉及底层模型替换的大版本**，而非增量更新。开发者在回归后仅剩约 7 个月有效开发窗口，最终未能启动它。

## 二、技术栈演进分析

```
Microsoft XNA Game Studio（2007–2019，Windows 独占）
        │
        ├── MonoGame 开源框架（2019 前后，为跨平台铺路）
        │      └── Steam Mac/Linux 版本发布（2018-11 起）
        │
        └── .NET Core + MonoGame 3.8（2022-08，0.14.x 全面迁移）
                 ├── 多线程（2019 起持续投入）
                 ├── Behaviour Tree AI
                 ├── 对象内存池化（0.14.1.12）
                 └── 本地化 mod 扩展点（0.14.2.0）
```

**SteamDB 检测到的完整技术栈**
MonoGame Engine ｜ XNA Engine ｜ FreeImage SDK ｜ NVIDIA Texture Tools SDK ｜ SDL SDK ｜ SteamworksNET SDK ｜ dotnet SDK

**平台支持演进**
| 版本 | Windows | macOS | Linux | Steam Deck |
|------|---------|-------|-------|-----------|
| Alpha (2012) | ✅ 独占 | ❌ | ❌ | — |
| 2018-11 (0.11.2.0) | ✅ | ✅ 首次 | — | — |
| 2019+ (0.12.x) | ✅ | ✅ | ✅ 首次 | — |
| 2022-08 (0.14.x) | ✅ | ✅ | ✅ | ✅ Playable |

**分析**：从 XNA 到 MonoGame 的迁移是这类项目的典型风险——XNA 于 2014 年实质停止更新，开发者选择 MonoGame 是必然选择，但 2022 年的最终迁移显示这拖了很长时间，且迁移本身消耗了回归后的绝大部分开发窗口。**0.14.0 的技术债清偿与 0.15.0 的功能开发发生了资源竞争**，这可能正是 0.15.0 从未启动的直接原因。

## 三、当前状态判定

| 维度 | 状态 | 依据 |
|------|------|------|
| 代码活跃度 | **实质停止** | 最后构建 2023-05-20，静默 3 年 5 个月 |
| 抢先体验状态 | **名义仍在 EA** | Steam 仍标注 Early Access，官方 EA 问卷承诺"大约三年"，实际已 8 年 |
| 1.0 版本 | **无迹象** | 0.15.0 规划公开后再无更新 |
| 玩家规模 | **近乎停摆** | 当前在线 2–6 人，月峰值 6–15（2019-01 峰值为 257） |
| 社区 | **存在但休眠** | 12,149 关注者；0.14.2.0 的本地化 mod 机制是最后的社区扩展点 |
| 商业状态 | **半休眠** | 未下架、未促销、未降价；价格与 2018 年发布时一致 |

**判定：应视为事实上的 abandonware（事实弃养软件），但非官方宣布。**

判定依据的强弱说明：
- **强证据**：最后构建时间（2023-05-20）、Steam 官方"3 年多未更新"提示、连续 3 年月峰值个位数至十位数
- **弱证据/待验证**：开发者个人现状、官网/论坛/开发博客是否仍在线（本次研究未直接抓取验证）、是否有站外开发

**信息缺口**：由于未直接访问 speciesgame.com / speciesdevblog.wordpress.com / 官方论坛，本次无法确认这些官方渠道当前是否仍可访问、是否有更新的表态。**这是本研究最重要的未验证项**，建议在引用本文档的商业判断前补做此验证。

## 四、可供二次开发参考的经验教训

1. **单人多线程模拟的规模天花板**：从 2019 年多线程原型到 2022 年才完成迁移，中间跨越了三次大版本重构，说明性能债的偿还成本极高
2. **引擎选型应前置**：XNA 的技术债最终吞掉了整个 2022 年开发窗口
3. **底层模型替换需独立立项**：植被模型重做若与功能开发并行，0.15.0 很可能被无限推迟
4. **通信是独立项目**：2020–2022 的静默中，开发者的实际状态对社区完全不可见，直接导致玩家将其判定为 abandonware——这与健康原因无关，纯粹是沟通问题

## 五、建议深入方向

1. **验证官方渠道现状**：直接抓取 speciesgame.com、speciesdevblog.wordpress.com 最新文章日期、论坛最后发帖时间——原因：这是判定"项目是否真正死亡"的最后一块拼图
2. **精读 2022-10-24 的 0.15.0 规划原文**：habitat 系统的完整设计推理目前只有摘要片段——原因：它代表了作者对"生态位过薄"这一核心问题的正式解答思路
3. **追踪 GitHub/社区 fork 动向**：MonoGame 技术栈降低了二次开发的门槛，社区 fork 或续作可能性存在——原因：这是评估该模拟思路生命周期的关键指标

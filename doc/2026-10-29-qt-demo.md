# Qt 演示程序 demo_gui

生态活体与世界地图的双视图演示。玩家接管其中一个个体，用方向键替它挑地方活；
它死了可以重选。世界照 sim 的那套场景配置跑，同一个种子下两边的数字对得上。

## 构建与运行

```powershell
# 构建（含 Qt 演示程序）
pwsh -File scripts/build.ps1 -Gui

# 运行
build\demo_gui.exe
```

`-Gui` 会打开 `GAMEV2_BUILD_GUI` 并把 `-DCMAKE_PREFIX_PATH` 指到 Qt 6.12 的
`msvc2022_64` 目录。目录不在默认位置时用 `-QtPrefix <dir>` 指定：

```powershell
pwsh -File scripts/build.ps1 -Gui -QtPrefix D:\path\to\Qt\6.12.0\msvc2022_64
```

运行前 Qt 的 bin 目录要在 PATH 上，否则找不到 `Qt6Core.dll`：

```powershell
$env:PATH = 'D:\Qt\Qt5.15.2Windows\6.12.0\msvc2022_64\bin;' + $env:PATH
```

不装 Qt 也能构建：`GAMEV2_BUILD_GUI` 默认 OFF，`find_package(Qt6)` 整块跳过，
默认构建链路不受影响。

## 界面

左页两个视图，右侧一列面板。

### 生态活体

64×64 的格网，跑着一整季生态。

- **底色**是每格的承载力，越绿越肥——承载力是这个世界的人口上限所在。
- **角色精灵**是个体。一人一张小图，身份由它在种群里的位次决定（见下节）。
- **黄圈**是玩家接管的个体，脚下压一圈暗影，人群里一眼能挑出来。
- **黄箭头**是它这一季打算往哪走。移动到季末才结算，没有这个箭头，按键像是
  没反应。

### 世界地图

世界生成器的产物，256×256。右侧面板可切十个图层：群系、高程、降水、温度、
地脉强度、地貌、洞天、渡劫场、地层岩性、矿脉。在图上点一格，右下角给出这格的
群系、地貌、高程、降水、温度与地脉强度。

### 面板

- **世界**：预设（evolve / persist / fragile）、种子、速度、重开、换个体。
  默认预设为 persist——evolve 的寿命基准只有 8 季，个体活不过十季。
- **玩家**：当前接管个体的身份、年龄、坐标、适应力、本季存活率与四项性状。
- **种群**：季号、种群总数、杂合度、近交系数，外加一条种群曲线。

## 角色精灵

个体不再画成白点，改用 `assets/sprites/characters` 里的 22 个角色。

### 素材怎么进程序

`CMakeLists.txt` 用 `qt_add_resources` 把 22 张静态精灵与 22 个动画图集打进
可执行文件，路径是 `:/assets/sprites/characters/...`。不依赖运行目录——换个
地方启动 exe 也不会找不到素材。

### 画多大、锚在哪

| 对象 | 素材 | 尺寸 | 锚点 |
| --- | --- | --- | --- |
| 人群个体 | `individual/<角色>.png` | 16×16（32 的 1/2） | 底部居中 |
| 玩家 | `anim/<角色>/atlas/atlas.png` | 32×32（原尺寸） | 底部居中 |

两处都用**整数倍**缩放：像素画按非整数倍缩小会糊，32 → 16 正好一半，最近邻
取样每个源像素变成 2×2 的方块。锚点取底部居中（pivot 0.5, 0.9375），脚落在
个体坐标上、身体朝上，与图集 manifest 里的 pivot 一致。

人群用半尺寸是被格网逼出来的：64×64 的格网在 780px 的视图里每格只有 12px，
原尺寸的精灵一个就占两格多，6000 个个体会把地图糊成一团。半尺寸下人物还有
15px 高，看得出是个穿袍子的修士。

### 谁是谁

| 组 | 判定 | 精灵 |
| --- | --- | --- |
| 九境 | 适应力在种群里的分位，分位越高境界越高 | `realm1` … `realm9` |
| 四修 | 速度最快 / 体型最大 / 繁殖最强 / 感知最灵各出一人 | `path_sword` / `path_body` / `path_alchemy` / `path_talisman` |
| 宗门职位 | 玩家的适应力分位，散修 → 宗主 | `office1_sect_master` … `office9_rogue` |

**适应力只看种群内部的名次**，不看绝对值——适应力的绝对值随季节漂，只有名次
是稳定的。玩家面板上的「身份」就是这个职位。

四道极致者会盖掉原本的境界：他们是人群里唯一几个「看得出修行方向」的个体。

### 动画

只有玩家在动：原尺寸的图集帧，待机 4 帧、行走 6 帧，12fps。移动要到季末才
结算，因此行走动画由**位置变化**触发，而不是按键那一刻。

12fps 的定时器每帧重画整个视图，但静态部分已经烘进离屏画布（见下节），每帧
只贴一张纹理。Canvas Painter 没有 QPainter 的脏矩形缓存，与其算脏区不如
每帧合成一张缓存纹理——代价反而更小。人群是静态的，不参与动画。

## 渲染后端：Qt Canvas Painter

生态活体图从 `QWidget` + `QPainter` 换成了 `QCanvasPainterWidget`——Qt 6.12
正式转正的硬件加速 2D 绘制（CMake 里是 `Qt6::CanvasPainter`）。世界地图与种群
曲线仍是 `QWidget` + `QPainter`：十张 256×256 的图 CPU 光栅毫无压力，迁过去
只是徒增风险。

### 为什么要缓存静态场景

Canvas Painter 没有 QPainter 的脏矩形缓存。一万一千个精灵每帧重画一遍，光是
命令录制就压不住；而且这些精灵除玩家外都不动，一季才换一次位置。

所以静态部分（承载力底色 + 人群）烘进一张**离屏画布**
（`QCanvasOffscreenCanvas`），只在种群变动或控件改尺寸时重画一次。每帧的活儿
只剩三笔：

1. 把离屏画布当纹理贴上去（一次 `drawImage`）；
2. 画玩家的脚下暗影、动画精灵与黄圈；
3. 画意图箭头。

### 三个坑

- **纹理上传要放在 `prePaint()`。** `paint()` 执行时渲染通道已经开着，那会儿
  建纹理容易踩到驱动的限制。
- **`addImage()` 的缓存按 `QImage::cacheKey()` 索引。** 动画帧不能每次现切——
  现切每次都是新图，缓存永远不中，纹理会一轮轮地堆起来。`SpriteBook` 因此
  把切好的帧缓存起来反复取用。
- **离屏画布的缩放比恒为 1，坐标是设备像素。** 控件这边是逻辑像素，两者差一个
  `devicePixelRatio()`。画布按 `size() * devicePixelRatio()` 建，画的时候整体
  `scale()` 一次，不必逐处换算。

另外 `QCanvasPainterWidget` 换顶层窗口后纹理全没了，`graphicsResourcesInvalidated()`
要把句柄清空，下次 `prePaint()` 重建。

### 换掉之后

Canvas Painter 没有 CPU 后端，依赖 RHI。本机走 D3D11（`qt.rhi.rub`），渲染
正常。换到没有可用 RHI 后端的机器（远程桌面、某些虚拟机）会画不出来，这是
迁移换来的代价。

## 选个体窗口

开局与玩家死亡时弹出。表格十列：年龄、剩余寿命、适应力、存活率、坐标、体型、
速度、寿命、韧性。列头可点，点了就按那一列排序。

**默认按存活率从高到低排**，第一行就是全种群最能活的那一只。原因见下面的
「已知限制」：这个世界的个体每季都有两三成的死亡率，挑错一只，玩家就会被死亡
弹窗反复打断。

实测：同一局里，存活率 0.999 的个体从第 1 季接管到第 67 季一直活着；同一局里
存活率 0.16 的个体第 3 季就死了。

## 操作

| 按键 | 作用 |
| --- | --- |
| 方向键 / WASD | 让玩家走一步（每季结算时生效） |
| 「换个体」 | 重选一个个体接管 |
| 「重开」 | 换种子与预设重开一局 |

移动的步长与其它个体同一套公式（`1 + Speed` 性态），被接管不会换来额外机动。
方向键在会吃掉方向键的控件（下拉框、数字框、输入框、表格）有焦点时归那个控件，
不会顺手把下拉框的值也改了。

## 为什么必须动核心

玩家要操控一个个体，而 `MovementSystem` 每季按随机流推所有个体一步。要让键盘
接管，必须让被接管的个体退出随机流。

`MovementSystem` 因此多了一个受控实体的钩子：

```cpp
void set_controlled(EntityId e) noexcept;   // 该实体不再参与随机游走
void clear_controlled() noexcept;
```

**受控实体照常抽签，只是把抽到的方向丢掉。** 省掉这一抽，后面每个实体的随机
序列就都错位一格——受控与否，世界轨迹不再是同一条。丢掉方向这件事由
`Ecology::set_controlled_entity` 转发，`Ecology` 是持有 `MovementSystem` 的
那一层。

## 场景配置为什么抽成库

`sim`（无界面）与 `demo_gui`（有界面）跑同一个世界。两份实现会让那些实测出来
的调平衡数字各走各的——界面上看到的种群曲线就与 `sim` 打印的对不上，而「对不上」
恰恰是玩家唯一会去核对的事。

于是位点蓝图、遗传与环境参数、初始种群铺法都搬进了
`include/gamev2/demo/scenario.hpp`（实现 `src/demo/scenario.cpp`，库目标
`demo_scenario`）。`sim/main.cpp` 改用它之后，同种子同参数的输出与搬移前
逐字节相同。

## 已知限制

- **个体每季都有两三成的死亡率。** 这是生态模型本身的样子，不是演示程序引入的：
  `sim` 打印的每季 `died` 占 `pop` 两成上下，同一个种子下 `demo_gui` 与 `sim`
  的数字一致。所以接管之后玩家随时可能死，这是设计里的事。
  应对办法就是挑一只强的——选人窗口默认按存活率降序，第一行通常有 0.99 以上。
  被接管的个体不再随机游走（位置由玩家写），实测不动、也不影响它活得长短。
- **生态格网与世界地图是两套坐标。** 前者是 64×64 的环境场，后者是 256×256 的
  世界生成产物，两者没有接起来——`ecology` 模块自带一套气候与资源场，不读
  `worldgen` 的结果。
- **人群把承载力底色盖住了。** 一季跑下来种群上万，六千多个 16px 的精灵铺在
  780px 的视图上，底色几乎看不见。地形信息并没有丢——挤的地方就是肥的地方，
  稀疏处露出的底色就是贫瘠处——但要看「哪一格承载力是 2.1」这种细节，得看
  低密度区。把人群缩到 8px 能换回底色，代价是人物只剩 7px 高、看不出是个
  修士（`src/gui/sprites.cpp` 的 `kCrowdSize`）。
- **世界生成要几秒。** 启动时在事件循环起来之后才生成，窗口先亮出来；生成期间
  界面无响应（鼠标变等待光标）。「重开」同样要重新生成。
- 演示程序本身没有存档，重开就是重开。

## 验证

- `sim` 重构后与重构前的输出逐字节相同（`sim evolve 12 12345`）。
- 八个测试套件全绿，共 655 个测试。
- 实际运行验证：选人 → 接管 → 推进季节 → 方向键移动 → 死亡 → 重选 → 切视图 →
  点格检视。实测数据：玩家个体从第 1 季活到第 67 季（存活率 0.999），按方向键后
  坐标 y 从 16.8 变到 18.8（步长 1 + Speed = 2.04），点格给出
  `(170, 78) 群系：恶地 地貌：凡地 高程 65 降水 13 温度 152 地脉强度 0`。
- 角色精灵改造后实测（种子 20261016、persist 预设）：第 94 季种群 12256，
  画面上仍是 22 个角色的缩略精灵；玩家面板的身份随种群位次变化（实测见过
  长老 → 宗主）；按右方向键后坐标 x 从 60.8 变到 62.9（步长 1 + Speed =
  2.04），玩家脚下的黄圈同步位移 26px；同一季内连续三帧的玩家精灵像素不同，
  待机/行走动画在跑。
- 截图与点击是脚本化的（`agent-temp/win.ps1`）：弹窗是模态的，合成鼠标事件
  收不到，改用 `postclick` 直接给窗口发 `WM_LBUTTONDOWN/UP` 才点得动「接管」。
- Canvas Painter 迁移后实测（种子 20261016、persist 预设）：回读帧缓冲（919×791）
  里承载力底色、上万个角色精灵、玩家精灵、黄圈与意图箭头齐全；把渲染出的玩家
  头部像素拿去和 22 个角色的图集逐帧做模板匹配，最佳匹配是 `office7_outer_m2`
  第 8 格，与所选个体的适应力分位算出的职位（外门弟子）一致，锚点偏移
  dx=0 dy=1——精灵落在 pivot 算出的位置；连拍 8 帧，玩家区域逐帧像素确有变化，
  待机/行走动画在跑。
- 迁移的坑记一笔：`QWidget::grab()` 与 `QRhiWidget::grabFramebuffer()` 能回读
  RHI 合成层的内容，桌外的 `PrintWindow` 抓不到（抓到的只有窗口框架）。所以
  截图要在进程内做。

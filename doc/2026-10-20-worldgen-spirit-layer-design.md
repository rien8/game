## 0. 本文定位

既有 worldgen 模块生成的是一个**纯自然世界**：高程、降水、温度、水文、群系、
土壤、岩层、洞穴、矿脉、含水层。它对设定里的「灵气」一无所知——代码里
`grep 灵气` 零命中。

设定文档 §13 声明自己是纯设定文档，不规定代码怎么写，但同时留下了一条硬线索：

> 地貌与地脉走向的描述刻意保持在「可被地形生成逻辑容纳」的层次

本模块的职责，就是把设定里**可由地形生成承载**的那一部分落成代码：

```
地脉（地下的水系）
  └─ 灵脉（地脉上浓度抬升的一段，分四等）
      └─ 灵眼（灵脉的地表出露点，有流量与纯度）
          └─ 灵域（灵眼周围按浓度衰减，分五等）
              └─ 洞天（福地之上人工开辟）
```

**本文只定设计，不含实现。** 实现计划另出，参照
`doc/plans/2026-10-19-worldgen-implementation.md` 的格式。

### 0.1 明确不在本模块职责内的

设定里有大量内容属于**模拟与叙事**而非地形生成，列为非目标，理由沿用既有设计
文档 §1.2 的口径：

- 势力：七宗、散修、大燧王朝、载域、《脉律》配额、盟约仲裁
- 人口：凡人聚落、灵根分布、伪灵根比例
- 生物：灵兽演化、兽潮、鬼修、魔修
- 经济：灵石收支、丹药产出、灵材价格
- 剧情：枯墟之谜、魔修复起、王朝觉醒

这些都需要**时间推演**（渡劫要抽干方圆百里、兽潮要几十年蔓延、灵潮要千年一轮），
而不是一次性的空间生成。worldgen 产出的地形与灵气分布是它们的**初始条件**，
不是它们本身。

### 0.2 三条不可让步的设定红线

设定 §12 逐条列了九条红线。落到本模块的设计上，有三条会直接决定数据结构：

1. **不可凭空造灵气**（红线 1）→ 灵气浓度必须**从灵眼流量衰减而来**，
   不能直接用噪声画一片「灵区」。浓度场是灵眼的函数。
2. **每一次繁荣都要有对应的消耗**（红线 9）→ 洞天必须携带**年耗灵石**，
   且这个消耗要从世界的灵石存量里扣，不能只写「这里有个洞天」。
3. **稀缺性不因剧情需要让路**（红线 8）→ 灵脉的**数量是硬约束**，
   不是「大概多点少点」。设定给了三个数：龙脉 1、主脉 9、支脉约 40。

## 1. 与既有框架的关系

### 1.1 纯追加，不回写

新阶段一律追加在既有十阶段之后（编号 11..17），**只读**既有输出，**不回写**
群系、降水、温度等任何既有字段。

理由：

- 既有十阶段的顺序已被验证，且设计文档 §11.4 已把「顺序无编译期保障」列为
  已知风险。再插队只会扩大这个风险面。
- 设定里「六类地貌」是**独立于 DF 群系的一轴**（§4.1 的表是灵气性质，不是气候
  性质）。福地可以落在沙漠群系上，瘴域可以落在针叶林上。让灵气回写群系会把
  两个正交的轴压成一条，反而丢掉了设定。
- 地脉的五行属性要读岩层（阶段 7），洞天要读灵域，而灵域来自灵眼、灵眼来自
  灵脉、灵脉来自地脉——这条链本身是严格单向的，不需要任何回边。

代价要认：灵气层**不能**改变地表自然地理。设定里「灵潮搅动 → 浊域」这类
因果在本模块是**单向投影**（灵气层读地形），不是地形被灵气改变。这是取舍，
不是缺陷。

### 1.2 阶段顺序

```
   既有十阶段（1..10，不动）
   ┌───────────────────────────────────────────────┐
   │ elevation → rainfall → temperature            │
   │   → hydrology → biomes → soils → strata       │
   │   → caverns → deposits → finalize_aquifers    │
   └───────────────────┬───────────────────────────┘
                       │ 单向读取
   ┌───────────────────▼───────────────────────────┐
   │ 11 make_spirit_tide     灵潮周期状态          │
   │ 12 make_ley_network     地脉网络（图 + 栅格） │
   │ 13 make_spirit_veins    灵脉品阶 / 灵眼       │
   │ 14 make_spirit_domains  灵域分等 / 浓度场     │
   │ 15 make_historical_scars 历史疤痕 / 灵气压制  │
   │ 16 make_land_types      六类地貌              │
   │ 17 make_cave_heavens    洞天                  │
   └───────────────────────────────────────────────┘
```

依赖边（读 → 写），与 §1.3 的表一一对应：

```
  spirit_tide + elevation + hydrology + strata  →  ley_network
  ley_network + elevation                       →  veins
  eyes + spirit_tide                            →  domains
  veins + eyes + elevation + domains            →  historical_scars
  domains + ley_element + scars                 →  land_types
  land_types + domains + veins                  →  cave_heavens
```

**阶段 15 在 16 之前**：六类地貌是**结果**，不是原因。死地之所以是死地，是因为
它先是「越采塌陷」或「渡劫失败」或「枯眼周边」；浊域之所以是浊域，是因为它
先是「灵潮搅动区」。先定地貌再补疤痕，会让两套规则抢同一批格子。

**阶段 17 最后**：洞天只落在福地上，需要阶段 16 的结论。

### 1.3 逐阶段读写契约

- **阶段 11 `make_spirit_tide`** — 读 `params.spirit_year`；写 `spirit_tide`
- **阶段 12 `make_ley_network`** — 读 `elevation`、`sea_level`、`downstream`、`flow`、
  `stone`；写 `ley_channels`、`ley_nodes`、`ley_strength`、`ley_depth`、`ley_element`
- **阶段 13 `make_spirit_veins`** — 读 `ley_channels`、`ley_nodes`、`elevation`；写 `veins`、
  `eyes`、`vein_rank`、`vein_id`、`eye_flow`
- **阶段 14 `make_spirit_domains`** — 读 `eyes`、`spirit_tide`；写 `domain_grade`、
  `domain_concentration`
- **阶段 15 `make_historical_scars`** — 读 `veins`、`eyes`、`ley_nodes`、`elevation`、
  `domain_grade`；写 `scars`、`scar_kind`、`spirit_suppression`
- **阶段 16 `make_land_types`** — 读 `domain_grade`、`domain_concentration`、`ley_element`、
  `scars`、`spirit_suppression`、`eyes`；写 `land_type`、`eye_purity`
- **阶段 17 `make_cave_heavens`** — 读 `land_type`、`domain_grade`、`veins`、
  `domain_concentration`；写 `cave_heaven`、`cave_heavens`

编排仍只写在 `generate_world()` 一处（既有设计 §8.2 的约束），新阶段追加在
`finalize_aquifers()` 之后。

**每个字段只有一个写入者**：既有十阶段里，十三个网格各自只被一个阶段写过
（既有设计 §2.1 的阶段表），这个不变式值得延续——它让「重跑某个阶段」不会
静默抹掉别的阶段的成果。本表遵守同一条规则，代价见 §3.3、§3.5、§3.6 里三处
**因果倒置的处理**：凡是「先发生的事导致后发生的结果」的地方，都让**先发生
的那一步在更早的阶段里完成**，而不是让后面的阶段回写前面的字段。

## 2. 数据模型

### 2.1 为什么是「图 + 栅格」两套

设定 §2.1 对地脉的描述是拓扑性的，不是标量场：

> 灵气沿地脉**流动**，有方向、有流速、有压差。

而 §2.2 把灵脉定义成地脉上**的一段**：

> 地脉之上灵气浓度显著抬升的一段

段、方向、汇流，这些都不能用 `Grid<T>` 表达——网格只能回答「这格是什么」，
回答不了「这格属于哪条通道的第几段、往哪流、上面汇进来多少」。

但既有框架的每个网格字段都是稠密 `Grid<T>`，空间查询（某格浓度多少、属哪种
地貌）也必须落在网格上。

**结论：两套并存，各司其职。**

- **图**（`LeyChannel` / `LeyNode`）持有拓扑：谁流向谁、汇了多少、一段有多长。
- **栅格镜像**持有空间查询：每格的强度、埋深、属性、浓度、地貌。

镜像由图单向导出，不允许反向修改。这条约束和既有设计 §8.2「就地改写而非阶段
函数链」是同一个思路：依赖方向单向，读取方便即可。

### 2.2 类型定义

新增文件 `include/gamev2/world/spirit.hpp`。不放进既有 `enums.hpp`——那里的
枚举全部服务于地表/地下自然层，灵气层自成子系统，挤在一起会让两个子系统
互相牵连。

```cpp
/// 地脉属性。五行为主，异质稀有（设定 §2.1）。
/// 计数：none 1 + 五行 5 + 异质 7 = 13。
enum class Element : std::uint8_t
{
    none,
    metal, wood, water, fire, earth,
    thunder, ice, wind, light, dark, sound, poison,
};

inline constexpr std::size_t kElementCount = 13;

/// 灵域分等（设定 §2.4）。
enum class DomainGrade : std::uint8_t
{
    barren,    ///< 废域：几近无灵，凡人域
    thin,      ///< 薄域
    medium,    ///< 中域
    thick,     ///< 厚域
    blessed,   ///< 福地：可开洞天
};

/// 六类地貌（设定 §4.1）。与 Biome 正交，不互相覆盖。
enum class LandType : std::uint8_t
{
    blessed,   ///< 福地
    miasma,    ///< 瘴域
    yin,       ///< 阴地
    dead,      ///< 死地
    turbid,    ///< 浊域
    mundane,   ///< 凡地
};

/// 历史疤痕。设定只点名了三种具象（枯墟、渡劫废墟、沸海）；
/// 第四种「枯眼周边」是枯眼的必然后果。
enum class Scar : std::uint8_t
{
    none,
    sinkhole,      ///< 越采塌陷（枯墟式）
    tribulation,   ///< 渡劫失败
    turbid,        ///< 灵潮搅动（沸海式）
    depleted_eye,  ///< 枯眼周边
};

/// 灵潮周期阶段（设定 §2.6）。
enum class TidePhase : std::uint8_t
{
    tide,     ///< 灵潮期：约 300 年
    decline,  ///< 衰退期：约 500 年
    trough,   ///< 谷底期：约 200 年
};

/// 灵脉品阶（设定 §2.2）。数值即排序，dragon 最大。
enum class VeinRank : std::uint8_t
{
    none = 0,
    barren = 1,  ///< 荒脉：残余矿化，储量极低
    branch = 2,  ///< 支脉：郡县级
    main = 3,    ///< 主脉：跨州级
    dragon = 4,  ///< 龙脉：贯通全境
};
```

节点与实体：

```cpp
/// 灵脉编号、节点编号、灵眼编号的哨兵值。
/// 沿用既有 kNoDownstream 的做法：不用 optional，因为这些字段
/// 与地脉图是一一对应的稠密索引，哨兵比 optional 省一半体积。
inline constexpr std::uint32_t kNoVein = 0xFFFFFFFFu;
inline constexpr std::uint32_t kNoNode = 0xFFFFFFFFu;
inline constexpr std::uint32_t kNoEye = 0xFFFFFFFFu;
```

```cpp
/// 地脉节点。节点是三维的：cell 给出地表投影，depth 给出埋深。
struct LeyNode
{
    std::uint32_t cell = 0;        ///< 地表格子的线性索引
    std::uint32_t depth = 0;       ///< 埋深，格
    std::uint32_t flow = 0;        ///< 累计流量
    std::uint32_t next = kNoNode;  ///< 下游节点；汇流点与下游共用同一节点
    std::uint8_t merges = 0;       ///< 汇入本节点的通道数
    Element element = Element::none;
};

/// 一条地脉。nodes 是沿线有序的节点索引序列。
struct LeyChannel
{
    std::vector<std::uint32_t> nodes;
    std::uint32_t head = kNoNode;  ///< 源头
    std::uint32_t tail = kNoNode;  ///< 末端：入海、入湖，或闭流死端
};

/// 一条灵脉：某条地脉上的一段。
struct SpiritVein
{
    std::uint32_t id = 0;
    VeinRank rank = VeinRank::none;
    std::uint32_t channel = 0;
    std::uint32_t first_node = 0;  ///< 段首，闭区间
    std::uint32_t last_node = 0;   ///< 段尾，闭区间
    Element element = Element::none;
    std::uint32_t reserve = 0;     ///< 储量
    std::uint32_t stability = 0;   ///< 稳定年限
    std::uint32_t eye = kNoEye;    ///< 灵眼索引
    /// 已被越采。设定 §4.2 的枯墟正是「灵脉被越采，三百里地陷」，
    /// 因果上是采在先、塌在后，所以标记落在阶段 13，塌陷落在阶段 15。
    bool overmined = false;
};

/// 灵眼：灵脉的地表出露点。
struct SpiritEye
{
    std::uint32_t vein = 0;
    std::uint32_t node = 0;
    std::uint32_t cell = 0;
    std::uint32_t flow = 0;    ///< 流量：单位时间可采灵气量
    bool depleted = false;     ///< 枯眼：已抽干，不可复生
    /// 纯度不在本结构里：它取决于周边环境，由阶段 16 写进 eye_purity 网格，
    /// 读方按 eye.cell 取。
};

/// 一处历史疤痕。land_type 是它的结果，scar_kind 是它本身。
///
/// 名字带 Site 后缀：枚举已占了 Scar，结构体不能同名。
struct ScarSite
{
    Scar kind = Scar::none;
    std::uint32_t cell = 0;      ///< 中心
    std::uint32_t radius = 0;    ///< 影响半径，格
    std::uint32_t target = 0;    ///< 关联的灵脉或灵眼编号
};

/// 洞天。设定 §2.5：本质是用灵石供养的蓄电池。
struct CaveHeaven
{
    std::uint32_t cell = 0;
    std::uint32_t capacity = 0;  ///< 可锁住的灵气量
    std::uint32_t upkeep = 0;    ///< 年耗灵石
};

/// 灵潮周期状态。世界的「年」以第一轮灵潮之始为元年。
struct SpiritTide
{
    std::uint32_t year = 0;
    std::uint32_t cycle = 0;     ///< 轮次索引，0 = 元潮
    TidePhase phase = TidePhase::trough;
    std::uint32_t year_in_phase = 0;
    std::uint32_t years_to_next_tide = 0;
    std::uint8_t level = 0;      ///< 当下浓度比例 0..255
    std::uint8_t peak = 0;       ///< 本轮峰值比例 0..255
};
```

产出流量与属性。

**`land_type` 不由 `Biome` 推导**：六类地貌是灵气性质，Biome 是气候性质，两者
正交（设定 §4.1 的表与 §4.2 的地理名录是两套坐标）。

## 3. 阶段规格

### 3.1 阶段 11：`make_spirit_tide`

纯算术，不取随机数。

```
cycle           = (year - 1) / 1000
cycle_start     = cycle * 1000 + 1
offset          = year - cycle_start            // 0..999
phase           = offset < 300 ? tide
                 : offset < 800 ? decline
                                : trough
year_in_phase   = offset < 300 ? offset
                 : offset < 800 ? offset - 300
                                : offset - 800
years_to_next   = 1000 - offset
peak_ratio      = 0.9 ^ cycle                   // 每轮损耗约一成
shape           = tide    ? (year_in_phase + 1) / 300.0
                 : decline ? 1.0 - year_in_phase / 500.0
                 : trough  ? 0.0
level_ratio     = peak_ratio * (kTroughFloor + (1 - kTroughFloor) * shape)
```

**阶段边界年归后一个阶段**（`offset == 300` 算衰退期，`offset == 800` 算谷底期）。
设定把过渡年同时列在两个阶段里（「第九轮灵潮 · 灵历 8001—8301 年」与
「灵历 8301—8801 年：衰退期」共享 8301），而「灵历 8801 年：入谷底期」
明确把 8801 划给谷底期。本式按「归后一个阶段」统一处理，理由是它能同时
复现设定给的两个当代数字（见下）。

**灵潮期的 shape 加一**：相位年只有 300 个，不加一的话峰值永远差 1/300
达不到，`level` 永远略低于 `peak`。加一之后灵潮期最后一年正好取到 1.0。

`kTroughFloor` 是谷底期保留的比例（初值 0.3，经验值）。谷底期不是绝对零——
设定 §2.6 说「灵脉半死」，不是死透。

**校核**（设定 §2.6、§9 给出的当代数据）：

| 项 | 设定 | 本式 |
|---|---|---|
| 当代灵历年 | 8914 | 8914 |
| 轮次 | 第九轮 | `cycle = 8913/1000 = 8` → 第 9 轮 ✓ |
| 阶段 | 谷底期 | `offset = 913 ≥ 800` → trough ✓ |
| 谷底期第几年 | 113 | `913 - 800 = 113` ✓ |
| 距下轮灵潮 | 87 年 | `1000 - 913 = 87` ✓ |
| 第九轮峰值 | 「天下最后一次高峰」 | `0.9^8 = 0.430` |
| 下一轮峰值 | 「不足元潮四成」 | `0.9^9 = 0.387 < 0.4` ✓ |

「谷底期第 113 年」与「距下轮 87 年」都是**差值**：`8914 - 8801 = 113`、
`9001 - 8914 = 87`。本式的 `year_in_phase` 与 `years_to_next_tide` 复现的
正是这两个差值。

最后一行是设定 §2.6 的原话直接换算：`0.9^9 = 0.387`，「九轮之后，下一轮灵潮的
峰值不足元潮时期的四成」。这不是巧合，是设定用「一成损耗」这个数写出来的，
公式必须能复现它。**这条要写成断言。**

**注意轮次语义**：`cycle = 8` 表示第九轮（索引从 0 起）。`peak_ratio = 0.9^8`
是**本轮**峰值；`0.9^9` 是**下一轮**的峰值。设定说的「不足四成」指的是下一轮，
两者相差一个指数，不能写错。

### 3.2 阶段 12：`make_ley_network`

产出：地脉节点图 + 栅格镜像。

**为什么地脉不能等于河网**：设定 §2.1 说地脉「大体随山脉与水系」。「大体随」
不是「就是」。地脉走的是山体内部，河走的是地表河槽，两者在平面上应当错开；
若地脉严格等于 `downstream` 树，灵气层就只是水文层的复制品，没有任何独立
价值。

**步骤 1：源点选取（山骨）**

在陆地格中找局部极大点：8 邻域内无更高者，且
`elevation >= sea_level + kLeySourceRelief`。按 `elevation` 降序取前
`kLeySourceCount` 个，彼此间距不小于 `kLeySourceSpacing`。

`kLeySourceCount` 随图幅面积缩放（参照既有设计 §5.1 的 `kElevationFeatures`
做法：让「世界尺度」在任何图幅上都指同一件事）。

**通道数要有下界**：设定给的「1 龙 / 9 主 / 40 支」是硬数字，而一条地脉通道
至多切出一段灵脉，因此**通道数就是段数的天花板**。源点间距是控制通道数的
真正旋钮——放宽间距会同时提高「源点各自成道」的比例与源点总数，
而单纯加大源点预算（`kLeySourceCount`）效果有限：间距不变时，多出来的
预算只会挑到同一批被间距排除掉的点。

做法：先按 `kLeySourceSpacing` 选源点并追踪通道；若通道数不足
`required_ley_channels(area)`，则**逐步放宽间距**重选，直到通道数达标
或间距收到下限。`required_ley_channels(area)` 随面积缩放，因此不能是常量。

这条保证是**构造性的**（不是「阈值调得好才凑巧对」），但不是数学上的硬保证：
地形实在给不出足够源点时（极端参数、全海图幅），通道数仍可能不足。
那时按 §5 处理——**缺口是诊断信号，不是错误**。

**步骤 2：通道追踪**

自源点出发，每步在 8 邻域中择下一节点，择序：

1. **必须下降**：`elevation` 严格低于当前格，否则不进入候选。
2. 同等条件下优先**汇流量大**的邻居（跟水系）。
3. 次优先**埋深浅**的邻居（埋深是每格自身的属性，与路径无关，可以预先算好）。

终止条件：入海、入湖、步数达上限、或无下降邻居（闭流死端）。闭流死端是合法
终点——设定 §11.3 已经承认内流盆地在现实里存在。

**步骤 3：埋深**

```
relief(node)  = elevation(node) − elevation(该格汇水区最低点)
depth(node)   = kLeyBaseDepth − kReliefShallow * relief(node)
                + kFaultDepth * fault_risk(node)
```

- `relief` = 该格高出**汇水区底部**的高差。盖层（覆盖在基岩之上的岩土层）在
  山脊处薄、在盆地处厚，而地脉贴着盖层底走——因此埋深由 relief **反推**：
  高处盖层薄 → 埋得浅，低处盖层厚 → 埋得深。
  浅埋才有「灵眼在地表出露」的可能，而设定 §4.2 的玄圃、赤崖、沉渊全在山里，
  灵眼若全在河口就与设定打架。
- `fault_risk` = 地形梯度（邻域高差方差）高的地方。设定 §2.1 说「断层是
  裂口」：地脉在断层处沉入深部，通道被压低，抬升的浓度被打断——灵脉的切分
  边界由此而来。
- 埋深下限 `kMinDepth`，上限 `kMaxDepth`。

**步骤 4：汇流与属性**

节点的 `flow` = 源头流量沿通道累加，多条通道在相邻处汇合则相加。
节点的 `element` = 流经岩性决定的属性：

```
element(node) = 由 stone[z(node.depth)][cell] 映射
z(node.depth) = min(z_levels - 1, depth / z_cell_depth)
```

**下标必须夹紧**：地脉埋深可能超过世界的总格深（默认 96 格），而
`stone` 只到 `z_levels - 1`。超出部分一律取最深的岩层——那本来就是「地脉
在更深的地方」，用最深的岩性代表它。

映射表（`spirit_tables.hpp`，初值）：

| 岩性 | 属性 | 依据 |
|---|---|---|
| `sandstone` / `gravel` / `marble` | 土 | 厚重 |
| `shale` / `limestone` / `ice` | 水 | 寒润 |
| `clay` | 木 | 绵长 |
| `granite` / `slate` / `igneous_intrusive` | 金 | 刚锐 |
| `basalt` / `igneous` | 火 | 暴烈 |

映射是**一对一**的：设定说属性「由流经的岩性决定」，没有给一岩多属的机制。
`igneous` 判火、`shale` 判水，都是「就其主要气质取一」。

**异质（雷冰风光暗音毒）不来自岩性**，而是稀有注入：按**整条通道**判定，
概率 `kHeteroChance`，一旦命中则从异质集合中取一个，并把该通道**所有**节点的
属性换成它。这一条对应设定「少数地脉夹带异质：异质地脉稀有，且极难驾驭」。

**为什么异质按整条通道而不是按节点**：异质是地脉自己带着的东西，不是岩石的
性质；而下游的灵脉（`SpiritVein::element`）一条只有一个属性，灵脉又是通道的
一段。若异质按节点随机注入，同一条灵脉的属性就没有唯一定义。整条通道统一
还带来一条可断言的不变式：**异质只整条通道出现，不会只染半条**。
非异质通道的属性则逐节点由岩性给出，埋深沿通道变化，取到的岩层也跟着变，
所以同一条通道上五行属性不同是正常的。

**步骤 5：镜像导出**

把图上的每条通道按格位写进 `ley_strength` / `ley_depth` / `ley_element`。

**两处「求和」不要混为一谈**：

- **节点流量在汇流处相加**（步骤 4 的主公式）：多条通道在相邻处汇合，
  汇流节点的 `flow` 是各上游流量之和。这是「源头流量沿通道累加」的直接
  后果，不是凭空放大。
- **同一格上的镜像强度取该节点的值，不额外求和**：设定 §1.1 守恒律不允许
  凭空放大，两条地脉重叠不代表两倍灵气。实际上节点与格是一一对应的
  （一格已被别的通道占用时，本通道并入它、不另建节点），所以镜像格上
  根本不会出现两个节点，「取最大」没有可取的对象。

`ley_strength` 是 uint8 网格，流量超过 255 就截断。注意流量沿通道累加后
大部分节点的流量会越过 255，镜像的分辨率因此偏低——这只影响 PPM 导出的
观感，不影响任何阶段读取的是图上的真流量。

### 3.3 阶段 13：`make_spirit_veins`

**步骤 1：浓度得分**

设定 §2.2：灵脉是「地脉之上灵气浓度显著抬升的一段」。浓度得分由三因子合成：

```
score(node) = flow(node) × shallowness(node) × confluence(node)
```

- `flow` = 累计流量（流量越大，通道中段浓度越高）
- `shallowness` = `1 / (1 + depth / kShallownessScale)`（越浅越接近地表）
- `confluence` = `1 + kConfluenceBonus × (上游支流数)`（汇流处浓度跳升）

三因子相乘而非相加：任何一项为零则该格不成脉，符合「灵脉是地脉抬升段」。

**步骤 2：切段**

沿每条通道，把 `score` 超过 `kVeinThreshold` 的**极大连续区间**切出来，每段
是一个候选灵脉。段内取最大得分节点作为该段的**出露点**（灵眼的候选位置）。

**候选段不足目标数量时下调阈值重切**：设定给的「1 龙 / 9 主 / 40 支」是硬数字，
不能因为某张图的地形碰巧平淡就少产出几条。阈值下调以
`kVeinThresholdStep` 为步长向下走，直到段数达标或触及下限
`kVeinThresholdFloor`。下限的作用是防止在极端平坦的地形上无限下调、把整条
通道都算成一条灵脉。

这样「数量达标」是**构造保证**，而不是「阈值调得好就凑巧对」；而阈值下限
保证它不会退化成「整条通道一条灵脉」。

**步骤 3：定品阶**

设定 §2.2 给了「单位面积储量 × 稳定年限」的分四等标准，以及三个**硬数量**：
龙脉 1、主脉 9、支脉约 40、荒脉不可考。

**关键决策：品阶由排名决定，不由阈值碰巧产生。**

把所有候选段按 `储量 × 稳定年限` 降序排，取前 N 段为灵脉，其余为荒脉。
排名区间由 §4.2 的数量公式决定，不是写死的：

| 排名 | 品阶 |
|---|---|
| 第 1 | 龙脉 |
| 第 2 .. 第 `1 + main` | 主脉 |
| 第 `2 + main` .. 第 `1 + main + branch` | 支脉 |
| 其余 | 荒脉 |

这样「1 / 9 / 40」是**保证成立**的性质，而不是「阈值调得好就凑巧对」。
荒脉数量不定，与设定「不可考」相符。

**数量随图幅缩放**：

```
dragon = 1
main   = min(9,  round(9   * area / kReferenceArea))
branch = min(40, round(40  * area / kReferenceArea))
```

`kReferenceArea = 256 × 256`，即默认预设下恰好产出 **1 龙 / 9 主 / 40 支**。

**这个 9 有一处独立佐证**：设定 §8.1 的七宗持股是太玄宗 3 条主脉 + 丹霞谷 2 +
寒江 1 + 万兽山 1 + 青囊谷 1 + 九幽宫 1 + 天机阁 0 = **9 条**，与「天下九条
主脉」精确吻合。支脉约 40 也对得上 §4.2「玄圃：九条支脉自此辐射，其中三条
终成主脉」。设定内部的数字是自洽的，代码必须复现这个自洽。

**步骤 4：灵眼**

每条灵脉（龙/主/支）出露**一个**灵眼，位置取该段的出露点（最大得分节点）。

- **流量** = 该节点的累计流量。流量是这条脉的**物理吞吐**，不随潮位变；
  潮位缩放的是环境浓度场（阶段 14）。两处都乘就等于把灵潮算了两遍。
- 荒脉不出露灵眼（储量太低，采不出东西）
- 纯度不在本阶段产出，见 §3.6

**步骤 5：越采标记与枯眼**

设定里有两处「先被采，后出事」的因果，都必须在本阶段定下**被采**的那一步：

1. **越采标记**：灵脉储量低、或已被采过，则标记 `overmined = true`，
   并按 `kOverminePenalty` 削减其储量。设定 §4.2 的枯墟是「太清宗旧址的
   灵脉被越采，三百里地陷」——采在先，塌在后，所以塌陷（阶段 15）必须能
   找到「被采过的脉」来放，地陷不会凭空出现。
2. **枯眼**：设定 §2.3「抽干灵眼需要数十年；抽干后只剩枯眼，不可复生」。
   当代有多少枯眼，设定未规定，本设计取 **枯眼数 = 灵眼数 ×
   `kDepletedRatio`**（经验值，初值 0.15），四舍五入取整。灵眼数是固定的
   （有品阶的脉恒为 1+9+40 = 50 条，每条一眼），所以枯眼数也是固定的
   （50 × 0.15 = 7.5 → 7 或 8 条）。被选中的灵眼：

   - `SpiritEye::depleted = true`
   - `eye_flow` 置 0
   - 该脉的 `stability` 骤降（被采过就伤了，设定 §2.2 的「稳定年限」）

   **枯眼不可复生**是一条必须能断言的不变量：已枯竭的灵眼在本轮生成后不得
   恢复流量。它同时是**跨轮次的语义**——若将来支持多轮模拟，枯眼状态必须
   持久化，不能每轮重新掷骰子。

**两处「被采」是两条独立的因果，各打一个品阶因子**：

- **越采 `overmined`**：判据是候选段的身份哈希，概率 `kOverminedChance`；
  `reserve` 按 `kOverminePenalty` 削减。定的时机：**排名前**。
- **枯眼 `depleted`**：判据是灵眼身份哈希，恰好取 `灵眼数 × kDepletedRatio` 条；
  `stability` 骤降到 `kStabilityMined`。定的时机：排名后（灵眼集合确定时）。

**「越采」必须在排名之前定**：若等排名完了再决定哪些被采，排名用的
「储量 × 稳定年限」就成了一圈套——被采的脉稳定年限下降、排名靠后，
而「哪些被采」又要看排名。

本设计用一个**与排名无关**的判据打破这个循环：每条候选段按**自身哈希**
判定是否被越采（`kOverminedChance` 概率）。哈希只看段的身份，不看它的名次，
因此可以在排名前完成。

被越采的段：`reserve` 按 `kOverminePenalty` 削减。**结果是被越采的脉自然
排名靠后**——设定 §2.2 的荒脉是「残余矿化，储量极低」，正是被采空之后的
残骸。荒脉的成因因此不是「本来就没油」，而是「曾经有油，被采完了」。

**为什么枯眼反而排在排名之后**：枯眼是「灵眼被抽干」的后果，而灵眼只出露在
有品阶的脉上——灵眼集合本身就是排名的产物。若让枯眼在排名前定，它的
「稳定年限骤降」会把这些脉挤出名次之外，枯眼反而无从产生（越采也一样：
把它排在龙/主/支之外就没有眼可枯）。所以枯眼在**灵眼集合确定之后**挑，
挑中的脉的稳定年限随之降低——那是「本轮看到的状态」，不回灌本轮的排名。
这与设定 §2.3「不可复生」不冲突：枯眼一旦生成就固定，下一轮不再重掷。

**哈希必须是均匀的**：越采与枯眼都是「抛一次硬币」，用插值噪声当随机源会
失真——`value_noise` 是四个格点哈希的插值，样本集中在 0.5 附近，拿它跟 0.15
比，实际只命中约 3%。因此这两处一律用 `Pcg32` 的均匀抽样，判据是段/眼的
**身份**（与名次无关），不是遍历顺序。

**稳定年限的来源**：设定 §2.2 说品阶按「单位面积储量 × 稳定年限」分四等，
但没有给历史事件表，稳定年限没有物理量支撑。本设计用**持续长度**近似：
`stability = kStabilityBase + kStabilityPerNode × 段长`——浓度持续得越久，
这条脉越稳定。龙脉「稳定万年」对应最长最富的段，支脉「郡县级」对应短的段，
与设定的品阶描述方向一致。

**这是构造出来的近似，不是历史模拟**（见 §8.7）。真正的历史需要 §0.1 列的
非目标那一层。

### 3.4 阶段 14：`make_spirit_domains`

**步骤 1：浓度场**

红线 1（不可凭空造灵气）决定了浓度场的算法：它必须是灵眼的函数。

```
concentration(x, y) = Σ_eyes  eye.flow × exp(−dist(x, y, eye) / λ_eye)
```

`λ_eye = kDomainRadius × sqrt(eye.flow / kReferenceFlow)`：流量大的灵眼影响
半径更大。指数衰减保证浓度处处连续，没有硬边。

`kReferenceFlow` 与 `kDomainRadius` 是经验值，在 `spirit_tables.hpp` 里。

**步骤 2：分等**

| 分等 | 浓度阈值 |
|---|---|
| 废域 | < `kThinThreshold` |
| 薄域 | `kThinThreshold` .. `kMediumThreshold` |
| 中域 | `kMediumThreshold` .. `kThickThreshold` |
| 厚域 | `kThickThreshold` .. `kBlessedThreshold` |
| 福地 | ≥ `kBlessedThreshold` |

**步骤 3：潮位缩放**

浓度场整体乘 `spirit_tide.level / 255`。这让**同一个 seed 在不同时点渲染出
不同的世界**：设定 §2.6 的「灵潮期：泉涌、洞天自生、福地扩张」与「衰退期：
荒脉接连枯竭」，在这个模型里就是同一个地脉网络在不同潮位下的两种读法。

福地面积随潮位变化是设定的直接要求，不是修饰。

**步骤 4：标定值与分布**

`kDomainRadius = 16`、`kReferenceFlow = 2000`、衰减截断 `3λ → 1.5λ`，
阈值阶梯 `8 / 24 / 60 / 120`。256×256、5 种子平均的实测分布：

| 潮位 | 废 | 薄 | 中 | 厚 | **福** | 饱和 | 福地连通块 |
|---|---|---|---|---|---|---|---|
| 灵潮期末(9300, 99) | 57.6% | 9.6% | 19.3% | 10.6% | **2.91%** | 0.1% | **9.4** |
| 元潮期(300, 255) | 57.5% | 0.3% | 9.0% | 14.1% | 19.08% | 5.0% | 19.8 |
| 谷底期(8914, 33) | 66.4% | 23.4% | 9.8% | 0.5% | **0%** | 0% | 0 |

（256²，5 种子平均。**福地面积对种子集极其敏感**：7 组不同的 5~6 种子集下，
灵潮期末福地占比在 **1.38%**（种子 101..105）到 **4.38%**（种子 201..205）
之间摆动，3.2 倍的差距。同期废域 56.7%~62.1%、厚域 8.6%~12.2%、福地连通块
7.6~9.4 都稳得多。⇒「几处福地」这句话由**连通块数**承载，不由面积承载；
标定回归断言也据此把福地面积下界取 1.0% 而不是 3%，并用**废域占比
（≥45%）与厚域占比（≤14%）**当背景高原回归的哨针——那两条在正确标定与两个
回归态之间完全不重叠，而福地面积的两个区间是重叠的。）

两条数字有设定依据：

- **福地连通块 9.4 ≈ 9 主脉 + 1 龙脉**。设定 §2.2 是 9 条主脉、1 条龙脉
  （玄圃即龙脉所在），所以「一条主脉一处福地」是这套模型自然长出来的形状，
  不是凑出来的。设定 §4.2 的「三处福地」是其中最重要的三处。
- **元潮期福地是灵潮期末的 6.5 倍**——设定 §2.6「福地扩张」。

**截断为什么是 1.5λ 而不是 3λ**：单眼而言 exp(-3)≈0.05 确实可忽略，但
50 只眼叠起来 `0.05 × 50 = 2.5` 倍于一只眼的峰值，于是叠出一片**背景
高原**（中位格恰好 60，压在厚域阈值上），福地阈值 120 只有高原的
1.3~1.7 倍——地图的上四分位就被判成福地，「福地」的语义退化成
「≥7 只眼的尾巴叠到此处」而不是「强眼所在地」。1.5λ 时 exp(-1.5)≈0.22，
尾巴仍留 22% 是为了让浓度场**处处连续**（指数衰减没有硬边），而不是为了
让覆盖范围铺满全图。

**谷底期没有福地，是模型的表达而不是缺陷。** 潮位缩放是纯乘子，于是
未饱和时「谷底期字节 = 灵潮末字节 ÷ 3」；又因字节上限 255，
「谷底期有福地」要求 `3T ≤ 255` 即 `T ≤ 85`，而实测 `T = 80` 时灵潮期末
福地已经 8%。所以**「谷底期有福地」与「灵潮期末福地 ≤ 6%」在当前模型下
不可兼得**。选前者会让福地覆盖 1/7 张图，直接撞上红线 8。

设定站在谷底期这一边：§2.6 谷底期「灵脉半死」，灵潮期才「洞天自生、
福地扩张」。代价是当代地图上没有福地也就没有洞天（见 §3.7），
这条作为未决问题留在 §9。

### 3.5 阶段 15：`make_historical_scars`

设定给了三处具名的历史伤疤，本阶段把它们变成机制。

本阶段**只做「放疤」**，不做「谁被采」——被采的灵眼与越采的灵脉在阶段 13
就定好了（§3.3 步骤 5）。因果方向是「先被采，后塌陷」，所以标记在前、
疤在后。

- **`sinkhole`**（枯墟 §4.2：太清宗旧址越采，三百里地陷）——落在**被越采的灵脉**上（`overmined`），且地势低平；
  后果是圆形塌陷区，`land_type = 死地`。
- **`tribulation`**（渡劫失败 §5.2：劫云溃散时灵脉受损，百年内沦为死地）——落在厚域/福地附近（高阶修士才渡得起劫）；后果是小范围死地。
- **`turbid`**（沸海 §4.2：灵潮搅动，潮起潮落皆为灵气乱流）——**临水的活灵眼**；后果是浊域区：浓度高、纯度也高，但灵气混乱不可修行。
- **`depleted_eye`**（枯眼 §2.3：抽干后只剩枯眼，不可复生）——围绕阶段 13 标记为枯竭的灵眼；后果是周边成死地。

**数量**：各疤痕的处数由 `kScarCount` 控制（经验值）。沉陷区半径按
`kSinkholeRadius`（枯墟「三百里地陷」是设定给的参照量，但换算成格数取决于
图幅比例，属于调参项），其余半径更小。

**浊域的候选与半径**（2026-10-20 复审后修订）。触发条件原写作「大流量灵眼与
水体相邻」，实测这条把沸海挤成了稀缺物：21 个世界（7 种子 × 3 年份）里浊域
候选 141 个有 118 个被挡，自由率 16%，8 个世界一处沸海也没有。而沸海是设定
§4.2 点名的具名地貌、天下最纯的原料产地，不该是稀有物。

设定原文对沸海的定义是「灵潮搅动之地，潮起潮落皆为灵气乱流」——**搅动的
是整片水域，与单口灵眼的流量无关**。因此触发条件修订为「**临水的活灵眼**」，
不设流量门槛；「大流量」改由**选点规则**体现：浊域取自由候选中流量最大的
那只临水眼，所以「大流量灵眼与水体相邻」在数据上依然成立。

候选**不按流量截断**。临水活眼只占活眼的一小部分（实测 2~20 / 42），先按
流量取前一半再筛邻水等于二次砍杀：实测任何截断（前 4/6/8/12、前一半）都只
能放到每世界 1 处浊域，不截断才放得下 2 处。

浊域半径 `kTurbidRadius` = 14。两处沸海要求中心距 ≥ 2×半径，半径决定第二处
沸海放不放得下。**但沸海的「处数」对半径不敏感**：沸海提前占位后，第一个
总落在唯一那只自由候选上，第二个够不够得着另说。实测 256² 图幅、
early 顺序下 r14 与 r20 都是 39 处（早期记录的 r20 = 24 是「沸海排在最后」
那一版的旧值，已作废）。所以半径这条规格由「每处沸海的半径 == 14」钉住，
不由处数钉住。

**「活眼」的口径**（三种写法统一成一种）：**未枯竭且流量非零的灵眼**。
实测每个世界的零流量眼全部是枯竭眼，两个条件当前等价；代码里两个都查是
为了不依赖这个巧合——万一将来出现流量为 0 的活眼，它不该被算成候选。

放置顺序固定为 枯眼 → **浊域** → 沉陷 → 渡劫。

顺序不是随便定的：**渡劫废墟与沉陷是历史残留，沸海是当世现象**（灵潮搅动）。
让当世现象给历史残留让路是顺序倒置，所以沸海先占位。

更实际的理由是结构性的：沸海提前后只需避开枯眼疤，而枯眼疤的落点完全
确定（遍历灵眼序，不消耗 rng）。于是「只要有一只临水活眼不在枯眼疤的
24 格挡路范围内，那个世界就必定有一处沸海」——**世界有没有沸海不再
取决于随机数落在哪**。若把沸海排在沉陷与渡劫之后，它就会被那两者的
圆盘挡掉：实测 21 个世界里有 1 个（种子 1 @ 灵历 9300）因此一处沸海也没有，
而那个世界只有两只临水活眼。

**疤痕会压制灵气**：死地之所以是死地，是因为那里的灵气真的没有了。疤痕在
`spirit_suppression` 上留下一个 0..255 的压制量，中心最强、向外衰减到 0。
有效浓度 = `domain_concentration × (255 − spirit_suppression) / 255`。

这条压制让「疤痕压过福地」在数据上真正成立，而不是靠规则表硬压：设定 §7.2
说「一处**福地**灵眼枯竭，附近灵兽失去灵气来源，被迫向下游迁徙」——兽潮
的前提正是**福地变成了死地**。若福地标签总能压过死地，这条设定就没有发生
的余地。

**渡劫废墟对灵脉的损伤未直接建模**：渡劫失败会「使该地灵脉受损」
（设定 §5.2），但渡劫的**时机**是随机的，发生在灵脉生成之后，因此阶段 15
无法回头改阶段 13 的储量。当前只体现为地表死地与局部压制。见 §8.5。

### 3.6 阶段 16：`make_land_types`

六类地貌的判定是**有序规则**，第一个命中的生效：

```
1. scar == sinkhole | tribulation | depleted_eye   → 死地
2. scar == turbid                                 → 浊域
3. domain_grade == blessed                        → 福地
4. 毒属性地脉覆盖                                 → 瘴域
5. 暗（阴）属性地脉覆盖                           → 阴地
6. 其余                                           → 凡地
```

规则的顺序有理由：

- **死地优先于一切**。死地的定义是「灵气枯竭，寸草不生」——它是一个**否定**，
  否定压过任何正面属性。一个曾经是福地、后来被采塌的地方，死地标签必须赢。
  这条直接对应设定 §7.2「兽潮是灵脉经济的外溢成本」：凡人对修士越采记账，
  记的就是这块地变死地。
- **浊域优先于福地**。设定 §4.1 说浊域「灵潮搅动，灵气混乱」——浓度不低，
  但**不可修行、易失控**。它是「高浓度但坏掉」，与福地「高浓度且可居」
  性质相反，不能被福地规则吃掉。
- **瘴域/阴地依赖地脉属性而非浓度**。瘴域是「毒瘴弥漫，灵气含毒」，阴地是
  「死脉腐坏，阴气积聚」——两者都是**性质**问题，不是多少问题。一片浓度很高
  的毒脉区是瘴域，不是福地。
- **凡地是兜底**，不是「低浓度」的显式判定——它表示「前五条规则都没命中」，
  是一张**性质**分类表，不是浓度表。设定 §4.1「凡地：几近无灵」是对凡地
  **主流情形**的描述，不是它的判定条件。实测（21 个世界，256×256，合计
  1376256 格）：

  | 分等 | 总格数 | 凡地 | 瘴域+阴地 | 死地 | 浊域 |
  |---|---|---|---|---|---|
  | 废域 | 881972 | 95.758% | 0.220% | 4.017% | 0.004% |
  | 薄域 | 221161 | 80.688% | 1.648% | 15.398% | 2.265% |
  | 中域 | 189516 | 70.121% | 2.036% | 22.603% | 5.240% |
  | 厚域 | 65803 | 53.143% | 2.822% | 35.108% | 8.927% |
  | 福地 | 17804 | 0 | 0 | 31.100% | 13.795% |

  两处张力都要记在账上：废域里有 4.017% 落在死地（死地压过一切，是规则 1
  的**有意**后果），另有 0.220% 落在瘴域或阴地（毒脉、阴脉本来就可以长在
  废域里，规则 4、5 优先于「无灵」）；反过来，中域与厚域里分别有 70.1% 与
  53.1% 被标成凡地——凡地不承诺那一格真的稀薄。要给凡地加浓度上界，就得让
  「浓度够、但没被别的规则命中」的格子换一张地貌标签，而设定 §4.1 只给了
  六类，所以本设计不加（见 §9 未决问题 8）。

**`domain_grade` 与 `land_type` 会有意不一致**：前者是地脉网络给出的浓度分等，
后者是叠加了历史与属性后的最终地貌。一个福地塌成死地之后，
`domain_grade` 仍是 blessed，`land_type` 却是 dead。

这不是数据不一致，是**设定要求的不一致**：设定 §7.2 的兽潮前提正是「一处
福地灵眼枯竭」——灵域还是那个灵域，地已经死了。读取方想知道「这里现在能
不能住」，看 `land_type`；想知道「这里的灵气网络有多强」，看 `domain_grade`。

**灵眼站在死地上也是自洽的**：实测 21 个世界里 882 只活眼有 282 只（31.97%）
落在死地格上。疤压的是**地表的有效浓度**（`spirit_suppression` 参与
`effective_concentration` 的计算），灵眼的 `flow` 是**地脉网络的供给量**，
两者不是同一个量：一条未被越采的脉照样从枯墟底下穿过，它的地表出露点可以
被渡劫废墟或沉陷疤盖住。这条不改阶段 15 的落点，只记在这里，免得后来者
看到「灵眼站在死地里」当成 bug 去修。

规则 4、5 读的是 `ley_element`，因此判「该格附近有没有毒脉 / 阴脉」需要一次
邻域查询：以该格为中心取 `kLandProbeRadius` 范围内的地脉属性，有毒即瘴域、
有暗即阴地。探测半径是经验值。

**纯度计算（阶段 16 的第二件事）**

设定 §2.3：灵眼有「纯度（杂质含量）。纯度决定能炼出什么丹、养什么灵植」。
纯度是**相对周边环境**定义的，因此必须在周边环境定下来之后才算：

```
purity = 基线纯度(element) − 污染扣减(周边地貌)
```

- **基线纯度**由地脉属性给：五行脉高纯，异质脉低纯（设定 §2.1「异质地脉
  稀有，且极难驾驭」——难驾驭的代价就是纯度低）。
- **污染扣减**来自周边：毒脉附近大幅扣减，阴地附近中度扣减。扣减按「窗口内
  每个污染格各计一次」累加，窗口是灵眼周围的 17×17 格（探测半径 8，方邻域）。
  幅度取 **8 / 4**（保持「大幅 : 中度 = 2 : 1」）。毒脉与阴脉在图上各是一块
  13×13 的方块（地貌探测半径 6），它与 17×17 窗口的交集**最少 1 格、最多
  169 格**。幅度若取 60 / 40，一格污染就扣掉基线 200 的三成，瘴域四格、
  阴地六格就扣穿到 0：实测 1050 只眼里有 88 只被扣成 0，扣减表在行为上
  退化成布尔量，污染的多寡再也看不出来。8 / 4 之后同样这 1050 只眼只有
  57 只归零，中间带从 5 个取值扩到 21 个（出现 96 这类「窗口内 13 格
  瘴域」的中间值），幅度重新成为可测的旋钮。
- **浊域不扣减**：它是「高纯度原料产地」（设定 §4.1）——**浊域不降纯度，
  反而是原料最纯的地方**，但纯得 unusable。

最后一条是个反直觉但设定明确的点：沸海的原料是天下最纯的，因为灵气在那里
被搅动而非被污染。扣减表与「浊域反而高纯」这一条都要写进 `spirit_tables.hpp`
并配注释，否则后来者会当成 bug 修掉。

**纯度写在阶段 16 而非阶段 13**，是为了守住「每个字段只有一个写入者」。
阶段 13 只产出流量与属性；阶段 16 产出地貌与最终纯度。

### 3.7 阶段 17：`make_cave_heavens`

设定 §2.5：洞天是福地之上人工开辟的小空间，**把外界的灵气收进来锁住**，
代价是维持阵法所需灵石。

**选址**：只在 `land_type == blessed` 的格上。

**数量与容量**：

```
洞天数 = 福地面积 / kCaveHeavenArea
capacity = 该处浓度 × kCaveHeavenCapacity
upkeep   = capacity × kCaveHeavenUpkeep
```

`upkeep` 就是红线 9 的兑现：开一座洞天要多花灵石，那灵石就少了。洞天的年耗
应当能被后续的灵石收支模块直接取用。

**位置选择**：在福地内按浓度降序取前 N 格，且彼此间距不小于
`kCaveHeavenSpacing`（洞天不是贴着开的）。

设定 §5.1 说筑基以下「不能开辟洞天」、§2.5 说福地「可开洞天」——所以洞天
的资格门槛是福地，而筑基以上才能开，是**后续模拟层**的事，不在本模块。

**当代（灵历 8914，谷底期）洞天数为 0。** §3.4 步骤 4 解释了为什么：
谷底期没有福地，而洞天只在福地上开。设定 §2.6「灵潮期：洞天自生」说的
正是这个——洞天随灵潮出现。

洞天数按**地貌**算，不是按分等算：`land_type == blessed` 才是能开洞天的
福地，死地与浊域按地貌规则 1、2 压过分等里的福地。实测（256x256，7 个
种子 {1,2,3,7,42,101,777}）。潮位按 §3.1 的式子算：9100 落在第十轮
灵潮期（偏移 99 < 300），不是衰退期；衰退期是灵历 9301~9800。

| 年份 | 潮位 | `land_type == blessed` 格数 | 洞天 |
|---|---|---|---|
| 8914 谷底期 | 33 | 0~286 | 0 座 |
| 9100 灵潮期第 100 年 | 53 | 0~929 | 0~2 座 |
| 9300 灵潮期末 | 99 | 274~3745（均值 1195） | 0~9 座，多数种子 1~3 座 |
| 9550 衰退期中段 | 64 | 0~1455 | 0~3 座 |
| 0300 元潮期末 | 255 | 5377~10018 | 13~25 座 |

分等里的 `domain_grade == blessed` 比上表多：灵潮期末实测 15545 格、
地貌福地 8366 格（均为 7 个种子合计），约 46% 被死地与浊域压掉——这正是
「死地压过福地」那条规则的代价。

这条代价记在 §9 未决问题 6。

## 4. 参数与随机流扩展

### 4.1 `WorldParams`

```cpp
/// 灵历年。世界的「年」以第一轮灵潮之始为元年。
/// 当代为灵历 8914 年（谷底期第一百一十三年）。
std::uint32_t spirit_year = 8914;
```

`is_valid()` **要改**：灵历年 0 会让 `cycle` 的计算下溢（见 §4.3），因此加一条
`spirit_year >= 1`。这符合 `is_valid()` 既有职责——「拦下会让计算失去意义的
参数」。

### 4.2 随机流

`Stream` 枚举新增七条，`kStreamIds` 数组同步扩容。既有 10 条流号不动，
保证既有阶段的确定性不受影响。

| 流名 | 流号 | 阶段 |
|---|---|---|
| `tide` | 10 | 11 灵潮状态（不取随机数，编号先占住） |
| `ley` | 11 | 12 地脉网络 |
| `vein` | 12 | 13 灵脉与灵眼 |
| `domain` | 13 | 14 灵域 |
| `scar` | 14 | 15 历史疤痕 |
| `heaven` | 15 | 17 洞天 |
| `land` | 16 | 16 地貌（不取随机数，编号先占住） |

「全局唯一」由 `enums.hpp` 现有的 `static_assert(stream_ids_are_distinct())`
钉住，新增流必须同改 `kStreamIds`。

### 4.3 灵历年的下界

`cycle = (year - 1) / 1000` 在 `year == 0` 时下溢（`uint32` 减法回绕成
`0xFFFFFFFF`）。两种处理：

1. `is_valid()` 里加 `spirit_year >= 1`
2. 计算时用 `year == 0 ? 0 : (year - 1) / 1000`

**建议取 1**：`WorldParams::is_valid()` 已经是「拦下会让计算失去意义的参数」的
唯一关口，把灵历年放进同一道关口比在每个使用点加特判更省事。

## 5. 错误处理

沿用既有设计 §6：`generate_world` 返回 `std::expected<World, WorldError>`，
唯一的可预期失败是 `invalid_params`。

灵气层**不引入新的失败模式**：

- 灵脉数量由「下调阈值重切」保证达标（§3.3 步骤 2），因此默认预设下
  1 / 9 / 40 是**恒成立**的，不存在「这次地形平淡所以少几条」。
  只有当阈值降到下限仍不够时才会少——那是极端参数下的退化，不是错误。
- 地脉网络可能为空（极端参数下源点选不出）——世界仍然有效，只是没有灵气。
  这与「凡地：几近无灵」是自洽的。

**数量不足是诊断信号，不是错误。** 硬约束（1 / 9 / 40）靠生成侧保证——
源点选取给通道数设下界，切段阈值有地板——但地形极端时仍可能凑不齐。
这时世界照常生成，缺口由查询函数报出来：

- `vein_census(world)`：逐品阶给出**实得**、**应得**与**缺口**
  （应得来自 `vein_targets(area)` 与 `round(灵眼数 × kDepletedRatio)`）。
  它能直接回答「实得 1/9/33，缺 7 条支脉」这种问题；
  `VeinCensus::total_shortfall()` 是龙、主、支三条定额缺口的合计
- `veins_complete(world)`：这一轮的灵脉数量够不够（纯查询，
  等价于 `total_shortfall() == 0`）

**不做成 `generate_world` 的失败**。理由有二：设定给的是「天下九条主脉」，
不是「生成失败」；而「灵气层不引入新的失败模式」这条一旦破例，调用方
（尤其既有十阶段的测试与 demo）都要开始处理灵气层的错误分支。缺口是
「这个世界少了几条脉」，是数据事实，不是调用错误。

小图幅按面积缩放（§9 未决问题 2），因此「应得枯眼数」
`round(灵眼数 × kDepletedRatio)` 在灵眼只有个位数时会取 0——枯眼红线
在小图幅上不成立，这是缩放的必然结果，同样由诊断量显示为「应得 0，实得 0」。

第 31 条是本模块最有价值的一条测试：它证明**灵潮周期是真正的参数，而不是
写在文档里的背景**。第 25 条次之：它证明「福地可以塌成死地」不是文档里的一句
话，而是数据里真实会发生的事。

**第 22 条为什么带「潮位 ≥ 71」这个条件**：眼格浓度至少是这只眼自己的贡献
`flow × 潮位 / 参考流量`。潮位 33 的谷底期，`flow ≤ 400` 的弱眼只有
`400 × 33 / 2000 = 6.6`，够不到薄域门槛 8。实测（60 个种子 × 3 图幅）：
谷底期 256² 最小眼格浓度 5、违反 9 次，64² 最小 7、违反 13 次，128² 最小 8、
零违反；潮位 71 / 99 / 255 各档**零违反**，最小 11 / 15 / 20。

这不是实现的缺陷，是「灵脉半死」的读法——谷底期连一只弱眼的灵域都够不到
薄域门槛，灵气稀薄到那个地步正是设定要的状态。若要让第 22 条无条件成立，
得把上游眼流量下限抬到 500（`500 × 33 / 2000 = 8.25`），那是阶段 13 的
标定改动，不在阶段 14 的范围里。

既有 `tests/test_world_determinism.cpp` 需要扩展，把灵气层的字段一并纳入
逐字段比较。

## 8. 已知限制与风险

### 8.1 地脉属性只采样一列岩性

地脉节点有埋深，理论上应采样该埋深处的岩性。但节点的**地表投影**与它实际
经过的地下位置未必重合（地脉在平面图上是一条线，在地下是沿走向延伸的
三维曲线）。

本轮用「地表投影列在该埋深处的岩性」近似。误差来源是山体陡峭处地表投影
与地下走向的偏移。缓解：地形平缓处误差小，而灵眼（浅埋）多在平缓处。

### 8.2 地脉是平面图 + 埋深，不是完整三维体

地脉的地下走向用「地表投影 + 单值埋深」表示，不是真正的三维曲线。这意味着
两条地脉在地下可能相交而平面图上不相交，或反之。

本轮接受这个近似：地脉网络的用途是**划分灵域、定位灵眼、定品阶**，三者
都是面上的量。真正需要三维地脉的场景（洞天的地下连通、跨洞天的灵气导流）
不在本轮范围。

### 8.3 地貌与群系正交，UI 需要两张图

六类地貌与 Biome 正交，调试时要看两张图。既有 demo 的 `biome.ppm` 之外
新增 `land_type.ppm`，两者不叠加。叠加显示留待渲染层。

### 8.4 纯度与地貌互为因果，被拆成两个阶段

纯度依赖周边地貌，地貌依赖灵域，灵域依赖灵眼。纯度与地貌之间存在真实的
循环依赖。

本设计的处理：**灵眼纯度整条挪到阶段 16**，与地貌同阶段计算，而不是在阶段
13 算好再在阶段 16 改写。这样守住了「每个字段只有一个写入者」。

代价是 `eye_purity` 的计算逻辑和「六类地貌」挤在同一个阶段里。若将来地貌
规则继续膨胀（要读更多层的字段），应把纯度单独拆成阶段 18，代价是引入一条
真实的回边，届时要显式取舍。

### 8.5 渡劫废墟对灵脉的损伤没有建模

设定 §5.2 明说渡劫失败「使该地灵脉受损」。但渡劫的**时机**是随机的，发生在
世界生成之后，因此阶段 15 无法回头改阶段 13 算出的储量。

当前只体现为地表死地。若后续模拟层要跑「渡劫 → 灵脉受损 → 百年后沦为死地」
的动态过程，需要在模拟层引入灵脉储量的可变状态，那时 `SpiritVein::reserve`
要变成可写字段，本设计的一写入者不变式会在这条链上被打破——这是有意的，
因为那时写它的是模拟层而不是生成层。

### 8.6 阈值与分档全是经验值

与既有设计 §11.2 同样的处境：浓度分档、域半径、源点间距、埋深系数、疤痕
半径、洞天密度，全都无法从原理推出，只能看着 demo 导出的 PPM 调。

缓解与既有设计一致：常量集中在 `spirit_tables.hpp` 与各阶段文件顶部。

### 8.7 灵脉品阶的「稳定年限」是构造出来的

设定 §2.2 的品阶标准是「单位面积储量 × 稳定年限」。储量可以算，稳定年限
没有物理量支撑——它取决于「这条脉上次被大采是什么时候」，而设定没有给历史
事件表。

本轮的处理：稳定年限由「该脉上是否有枯眼」推导（有枯眼 → 近几十年被采过 →
稳定年限低）。这是设定能支撑的最强推导，**不是**历史事件模拟。
真正的历史需要 §0.1 列的非目标那一层。

### 8.8 `domain_grade` 与 `land_type` 有意不一致

见 §3.6。福地塌成死地之后，`domain_grade` 仍是 blessed，`land_type` 是 dead。
这是设定要求的（兽潮的前提是「福地灵眼枯竭」），不是数据缺陷。

代价是读取方必须知道该看哪个字段。本设计在 `spirit.hpp` 里给两个查询函数
（`is_blessed_land(world, x, y)` 读地貌、`domain_grade_of(world, x, y)` 读分等），
并在字段的 doxygen 里写明「最终地貌看 land_type」。

### 8.9 有效浓度是派生量，不是字段

`spirit_suppression`（阶段 15）与 `domain_concentration`（阶段 14）分属两个
阶段，因此「有效浓度」只能是读时计算的派生量：

```
effective = domain_concentration × (255 − spirit_suppression) / 255
```

`World` 上不存这个值。理由是它一旦成为字段，就会有第二个写入者。

代价是每个消费者都要自己算一遍，或者调用 `spirit.hpp` 提供的查询函数。
实现时应当提供该函数，而不是让调用方各写一份公式。

## 9. 未决问题

以下几项设计上有多个合理解释，本设计各选了一种并写明理由，但需要拍板。

1. **灵眼是一脉一眼还是一脉多眼？**
   设定 §2.3 说「灵脉在地表的最高出露点」（单数），但 §2.1 说地脉「有方向、
   有流速、有压差」，压差意味着沿程可能有多个涌出点。
   本设计取**一脉一眼**（唯一出露点），因为「最高出露点」是单数表述，且
   一眼一眼地对应一条脉，才能保证「流量」与「枯眼」的语义干净。

2. **主脉/支脉的数量在非默认图幅下如何缩放？**
   本设计取「按面积线性缩放，并以 9 / 40 封顶」。另一种取法是「恒为 9 / 40，
   小图幅里少排出几条」。前者适合「这张图就是全世界」的用法，后者适合
   「这张图是全世界的一块」的用法。默认预设下两者结果相同。

3. **荒脉是否出露灵眼？**
   本设计取**不出露**（储量太低采不出东西）。设定 §8.3 说散修会去「盗采荒脉」，
   暗示荒脉也能采——那么荒脉究竟有没有枯眼？若有，枯眼的总数会显著上升。

4. **浊域是空间属性还是潮位属性？**
   本设计取**空间属性**：沸海是灵潮搅动的一片固定区域。
   另一种取法是「所有地方在灵潮期都是浊域，谷底期才恢复」——这更贴近
   「灵潮搅动」的字面意思，但会让六类地貌在潮位变化时整体重排，
   与 §1.1「不回写群系」的边界也会更模糊。

5. **是否需要「渡劫场」这一维？**
   设定 §5.2 说「各大宗门争夺的渡劫福地」，意味着「适合渡劫的地点」是
   灵域之上的一个子集（可能是厚域里的某些格）。本轮只在阶段 15 用了
   「厚域附近」作为渡劫废墟的触发条件，没有产出「渡劫场」这个可查询的概念。
   若后续模拟层需要显式的渡劫选址，应当补一维。

6. **谷底期到底该不该有福地？**
   这是 §3.4 步骤 4 标定之后暴露出来的模型级取舍，不是实现 bug。
   潮位是纯乘子，未饱和时「谷底期字节 = 灵潮末字节 ÷ 3」；又因字节
   上限 255，「谷底期有福地」要求 `3T ≤ 255` 即 `T ≤ 85`，而实测
   `T = 80` 时灵潮期末福地已达 8%。所以**「谷底期有福地」与
   「灵潮期末福地 ≤ 6%」不可兼得**。

   | 方案 | 灵潮期末福地 | 谷底期福地 | 洞天（灵潮末 / 谷底） | 代价 |
   |---|---|---|---|---|
   | **A（本设计采用）** | 2.91%，9.4 块 | 0 | 0~9 座 / **0 座** | 当代地图无福地故无洞天；§4.2「三处福地是骨架」在谷底期不成立 |
   | B | ≈8.05% | ≈0.09%，多数种子 0 块 | ≈13 座 / 0 座 | 福地涨到 1/12 张图；谷底期仍不稳定、仍 0 洞天 |
   | C | ≈13.5% | ≈0.51%，1~2 块 | ≈22 座 / 0 座 | 福地覆盖 1/7 张图，红线 8 明显受损；22 座洞天与七宗量级不符 |

   本设计取 **A**：设定 §2.6 把福地与洞天写成随灵潮出现并扩张的东西
   （灵潮期「洞天自生、福地扩张」，谷底期「灵脉半死」），谷底期争夺的是
   **灵脉**（§8：九条主脉的分布是伐脉之战的结果），不是福地格子。
   若要让谷底期必有福地且洞天 ≥1 座，必须改模型本身——把潮位响应改成
   压缩函数（如 `sqrt`）并重定 `kCaveHeavenArea`——那是设计层改动。

7. **跨图幅的浓度场统计量不可比。**
   λ 用的是绝对格数，而灵脉数按面积缩放但以 9 / 40 封顶，于是同一套
   设定在不同尺寸的合法世界上给出不同的分布（灵潮期末福地占比：
   64² 0.00% / 128² 0.81% / 256² 2.91% / 512² 3.29%）。本轮只把极差
   从 36 个百分点收窄到 3.3 个，**没有解决**。真正的解法要么是让 λ 与
   域半径随图幅线性缩放，要么是给 `WorldParams::is_valid()` 加尺寸下界
   并写明「灵气层只支持 ≥128²」。这与未决问题 2 是同一个根因的两面。

8. **凡地要不要加浓度上界？**
   本设计取**不加**：凡地是「前五条规则都没命中」的兜底，是性质分类而非
   浓度分类。代价是中域与厚域里分别有 70.1% 与 53.1% 被标成凡地，与设定
   §4.1「凡地：几近无灵」的字面意思有张力（§3.6 有完整实测表）。另一种
   取法是给凡地加浓度上界，于是「浓度够、但没被别的规则命中」的格子需要
   第七张地貌标签——而设定 §4.1 只给了六类地貌。

## 0. 总览

### 0.1 主题一句话

**守望者注视下的演化史诗。** 玩家不是上帝，而是翻书人——看到的不是写实的世界，而是被风翻开的水墨长卷，和纸页上剪出来的众生相。

### 0.2 视觉关键词 Mood Board

> 在画第一笔之前，先用词语锚定视觉气质。这些词与最终所有美术决策做交叉校验。

- **材质词**：纸、墨、剪纸、烫金、烫银、矿物颜料
- **气氛词**：静、远、肃、留白、仪式感
- **回避词**：塑料、金属冷光、HDR bloom、体积光、写实草地

**情绪参考方向**（不照搬风格，只锚定"气质"）：

| 维度 | 参考方向 | 取什么 | 不取什么 |
|------|---------|------|--------|
| 水墨质地 | 中国画写意散点透视、林风速写、宋画小品 | 墨色阶、留白、晕染 | 工笔细描、重彩青绿 |

### 0.3 三层风格分工

| 层 | 风格 | 资产形态 | 程序化机制 |
|---|------|---------|----------|
| **生物层** | 手绘剪影 + 平涂冷暖色 | 256×256 PNG 部件，6 类（head / torso / forelimb / hindlimb / tail / horn / wing） | 部件 PNG + HSL tint |
| **环境层** | 水墨晕染（程序化噪声 + 渐变） | 程序化 tile | Simplex 噪声 + 纪元色板 + per-tile 渐变 |
| **UI 层** | 剪纸 + 烫金/烫银字体 | 程序化绘制（无外部纹理） | 几何面板 + 阴影叠加 + 金属描边 |

### 0.4 三层之间的视觉关系

```
+------------------------------------------------+
|                  UI 层（顶层）                 |  ← 烫金描边、剪纸分隔
+------------------------------------------------+
|                                                |
|              生物层（剪影 + tint）             |  ← 浓黑描边、平涂冷暖色
|              在环境层之上渲染                  |
|                                                |
+------------------------------------------------+
|        环境层（水墨 tile，作为底色）            |  ← 程序化噪声 + 渐变
+------------------------------------------------+
```

**色阶呼应**：环境层提供最浅的灰阶底色，生物层是最深最实的剪影，UI 层是唯一的金属高光（烫金/烫银）。这样三层互不抢戏，扫描顺序天然清晰：先看世界（环境），再看众生（生物），最后读叙事（UI）。

**视觉权重（60-30-10 法则）**：
- **60% 环境层**：决定基调，决定第一眼质感
- **30% 生物层**：决定可读性，决定第二眼信息
- **10% UI 层**：决定仪式感，决定要不要停下来

### 0.5 工具链与文件组织

> 美术资源的可追溯性与可复现性比"画得漂亮"更重要——尤其在程序化生成与手绘混合的栈里。

**工具清单**：

| 阶段 | 推荐工具 | 用途 | 输出格式 |
|------|---------|------|---------|

| 资源打包 | PNG Gauntlet / oxipng | 压缩与 mipmap | 优化后 PNG |
| 版本管理 | Git + LFS（PNG / 二进制） | 美术资产 diff | 文本 diff + LFS |

## 1. 生物层：手绘剪影

### 1.1 设计原则

1. **剪影优先**：把每个部件 PNG 当剪影读。alpha 通道是形状来源，alpha 外的区域透明
2. **单色描边 + 平涂内填**：每个部件 = 一圈深色外轮廓（≈ 2 px @ 256）+ 一个平涂色块（冷暖倾向）
3. **轮廓不可中断**：手绘剪影的"断续感"是手绘风格的生命线——但 outline 必须连续，不能有锯齿或断裂
4. **部件独立可读**：每个部件单独看也得能识别（缩略图大小可识别）
5. **剪影温度感**：冷色相偏蓝绿（兽类底栖）、暖色相偏赭红（陆栖猛兽/火系）、中性色相（中性物种/混血）
6. **生物"性格 = 比例 + 形态"**：用 silhouette 暗示性格，不依赖装饰——例如：草食 = 颈长 + 体型中央化；猛兽 = 肩胛高 + 吻短粗

### 1.2 部件规范

#### 1.2.1 画布与锚点

- **画布尺寸**：256×256（每张 PNG）
- **bbox**：每张图在 256×256 上有实测 bbox（白底处理后，写入 `_manifest.json`）
- **attach 点**：每类部件一个连接点（torso 双点），坐标也是 256×256 画布坐标
- **连接方向**：四向（Top / Bottom / Left / Right）
- **padding**：四角各留 ≥ 8 px 安全边，避免缩到 64 px 后贴边丢失像素

#### 1.2.2 六类部件清单

| 类目 | zOrder | 单/双连接点 | 用途 | 备注 |
|------|--------|-------------|------|------|
| torso | 0 | 双（front / back） | 身体主干，先画 | 居中铺底 |
| hindlimb | 1 | 单（back） | 后肢 | 默认朝下 |
| forelimb | 2 | 单（front） | 前肢 | 默认朝下 |
| tail | 3 | 单（back） | 尾部 | 与后肢同 anchor，背向 |
| head | 4 | 单（front） | 头部 | 最后画，覆盖在最上 |
| horn | 5 | 单（top） | 角/冠 | v2，未启用 |
| wing | 5 | 单（back） | 翼 | v2，未启用 |

> zOrder 升序即绘制顺序：torso → tail → hindlimb → forelimb → head。horn/wing 留待 v2。

#### 1.2.3 部件视觉规范

| 项 | 规格 |
|---|------|
| **外轮廓色** | 浓墨 `#1A1815`（几乎黑，略偏暖） |
| **外轮廓粗细** | 2 px（@256 画布），缩放到 64 px 后约 0.5 px 视觉粗 |
| **填色策略** | 平涂单色（Hue 由基因决定），不用渐变、不用阴影 |
| **阴影/高光** | 内部允许 1 处 2 px 的暗化区域（不是阴影，是结构提示），禁止高光 |
| **alpha** | 抗锯齿（边缘平滑），背景透明（白→透明处理流程） |
| **bbox padding** | 至少 8 px（@256），避免缩到 64 px 时贴边 |
| **内填饱和度上限** | 普通生物 ≤ 60%；精英/Boss 在 §1.4 例外 |
| **方向约定** | 朝 Left（脚朝观察者右侧、身体朝左），后续组件镜像不重画 |

> **方向约定** 比"双套朝左右"省一半资产——所有部件朝左画，渲染时按 sex/朝向轴镜像翻转。

#### 1.2.4 部件动画差分（v1.1 新增）

> 不画骨骼动画，但要让生物"看着活"。每个部件至少有 **idle 呼吸 + walk 迈步** 两组差分。

| 状态 | 帧数 | 帧率 | 部件差异化 | 备注 |
|------|------|------|-----------|------|
| **idle 呼吸** | 4 | 6 fps | torso 上下 ±1 px；head 同步 ±0.5 px | 微微的"吸—呼—吸—停"节奏，不是真 4 帧均分 |
| **walk 迈步** | 6 | 12 fps | forelimb / hindlimb 左右交替 ±2 px | 抬腿顺序：后左 → 前左 → 后右 → 前右（标准四拍）|
| **attack** | 4 | 12 fps | forelimb 前伸 +4 px，head 微前倾 | 命中帧 = 第 3 帧 |
| **death** | 3 | 6 fps | 整体沉降 +2 px，head 微下垂 | 不做爆炸，纯"塌" |
| **hit** | 2 | 12 fps | 整体闪白（tint value +60 × 0.1s）| 1 帧用 tint 变白即可 |

**性能约束**：所有状态共享同一个部件 PNG，状态间靠 `attach_y_offset` 与 `tint_mod` 实现。
**禁止**：引入新贴图 / 新帧 = 新部件。所有动画差分都从同一份 256×256 部件 + 数学变换产出。

### 1.3 染色规则（HSL Tint）

HSL 参数被转换为乘性 tint，作用于整个部件（不改 alpha）。

**这是生物层实现"演化 = 颜色变化"的关键机制：同一个部件图，通过 tint 表现不同的物种和纪元。**

| 参数 | 范围 | 用途 | 典型值 |
|------|------|------|--------|
| `hue_offset` | 0–359° | 主导色相（生物"皮肤色"） | 0–360 全谱，饱和大群时会撞色 |
| `saturation_mod` | −100…+100 | 饱和度调整（精英/灾厄会有饱和偏移） | 普通 0，精英 +20，灾厄 −40（灰败） |
| `value_mod` | −100…+100 | 明度调整 | 普通 0，精英 +10，Boss +20（更亮） |
| `tint_secondary` | HSL | 暗化区域色（用于"结构提示"那一处 2px 暗色块的微调）| 默认 `value−15` |

**禁止**：
- ❌ 用 tint 做"夜晚滤镜"——那是环境层的事
- ❌ 用 tint 改变 alpha——只改 RGB
- ❌ 用 tint 把剪影变成"完整彩绘"——剪影就是剪影
- ❌ 用 tint 制造"光晕"——烫金留给 UI 层

### 1.4 精英怪 / Boss / Champion 的视觉等级

| 等级 | tint_override | 饱和/明度调整 | 其他视觉处理 | 触发与稀有度 |
|------|--------------|-------------|------------|------|
| 普通 | 不覆盖，用基因 tint | 0 / 0 | 剪影原色 | 日常 |
| **Champion（强化）** | 不覆盖 | +10 / +5 | size ×1.1 + 头部加银圈 `kSilverHi` | < 5% 概率 |
| **Elite（精英）** | `#FFE060`（金黄）+ 头部加金圈 `kGoldHi` | +20 / +10 | sprite 基础尺寸 | < 1% 概率 |
| **Mini-Boss** | `#D08030`（橙铜）+ 名字"M"标记 | +5 / +15 | sprite ×1.25，背部加烫金纹章 | 每纪元 2–3 只 |
| **Boss** | `#FF6060`（朱红）+ 名字"B"标记 | −40 / +20 | sprite ×1.5，背景层 `kScrim` | 章节级，约 12–20 场一次 |

> **视觉升级单调升级**：Champion < Elite < Mini-Boss < Boss。在 viewport 同时出现多个等级时，等级高的必须"显著"更高——这是 Boss 设计的基本直觉。

### 1.5 组合 sprite 的渲染规则（v1.1 新增）

> 6 类部件拼成一只生物时，要解决的 3 个工程问题。

1. **zOrder 强制**：同名部件同 zOrder 时，按"体型大者后画"——避免小部件盖住大部件产生误读
2. **attach 偏差容忍**：拼装时允许 ±2 px 的 attach 微调，但累计偏差 ≤ 4 px，否则是 manifest 出错
3. **同色共振**：同 tier 内多只生物近距离出现时，强制 `hue_offset` 错峰 30° 起步，避免一屏撞色

### 1.6 Silhouette Test（v1.1 新增）

**每个新部件上架前必须通过 silhouette test**——这是剪影风格生死线：

1. 把部件 PNG 涂成纯黑，丢进 64×64 的画框
2. 让一个**没见过这只生物**的人看 1 秒，问"这是什么"
3. ≥ 80% 答出"头/身/腿/尾"四类中至少 3 类 → 通过
4. 不通过 → 回到 Krita 重画轮廓，不允许用"贴细节"蒙混

记录归档至 `assets/_qa/silhouette_<part>_<date>.png`，每个部件一份。

## 2. 环境层：水墨晕染

### 2.1 设计原则

1. **程序化为主，手绘为辅**：tile 颜色 = 噪声 + 渐变 + 纪元色板，不需要额外纹理资产
2. **晕染边缘柔和**：生物群系交界处用噪声做羽化，不用硬边界
3. **墨分五色**：每个 tile 是 5 级灰阶之一（灰 → 淡墨 → 中墨 → 浓墨 → 焦墨），纪元色板决定是哪种"墨"（青/赭/朱/玄）
4. **纪元跃迁有仪式感**：每纪元色板切换时，世界用 2–3 秒的渐变过渡（环境层独立的事件）
5. **环境不动，生物动**：环境的"静"是为了让生物剪影的"动"成立——禁止环境里加粒子 / 流动贴图

### 2.2 Tile 渲染机制

每个 tile 有 4 个标量（elevation / temperature / moisture / biomass）和 1 个 biome 枚举。最终颜色由 4 步决定：

1. 由 biome 选出基础墨色（来自纪元色板）
2. 用 elevation / temperature / moisture 做 ±N 级的微调
3. 用 biomass 做 0..1 的"明度提升"（食物多的地方墨色更浓 = 更显眼）
4. 与 4 个邻居做噪声插值（羽化边缘）

### 2.3 Biome 基础色板（按纪元切换）

每个纪元（Era）有独立的 11 色板，下表是**第一个纪元（创世）**的初版，仅作锚点；其它纪元按 §2.5 派生。

| Biome | 创世纪元 RGB | 视觉描述 |
|-------|--------------|---------|
| DeepOcean | (16, 38, 78) | 深海墨蓝 |
| Ocean | (28, 58, 110) | 海面深蓝 |
| Beach | (200, 178, 122) | 沙滩米黄 |
| Grassland | (132, 168, 86) | 草原草绿 |
| Forest | (52, 110, 58) | 森林深绿 |
| Rainforest | (32, 90, 50) | 雨林墨绿 |
| Desert | (218, 188, 122) | 沙漠赭黄 |
| Swamp | (68, 92, 60) | 沼泽灰绿 |
| Tundra | (172, 184, 174) | 苔原灰白 |
| Mountain | (134, 130, 124) | 山岩灰褐 |
| Snowcap | (236, 240, 244) | 雪顶银白 |

**视觉风格校验**：对比"墨分五色"——每个色都偏中低饱和（≈ 30–60% sat），明度从 30%（深海）到 95%（雪顶）拉开。所有色相饱和度都被刻意压低，是为了让生物剪影的冷暖 tint 在环境之上更跳。

#### 2.3.1 墨分五色的灰阶定义（v1.1 新增）

> "墨分五色"是这版水墨语法的核心——纪元色板的"墨色系"映射规则。

五级灰阶的视觉权重与典型 RGB：

| 墨阶 | 视觉 | RGB (luma) | 用于 |
|------|------|-----------|------|
| **焦墨** | 最深、最重 | (24, 24, 24) | 边界、轮廓、tile 内最暗处 |
| **浓墨** | 重墨 | (66, 66, 66) | 主生物群系色 |
| **中墨** | 中度 | (118, 118, 118) | 过渡色、次生 |
| **淡墨** | 浅淡 | (180, 180, 180) | 邻接色、远景 |
| **灰** | 留白 | (232, 232, 232) | 极远处、雪顶 |

纪元色板的映射规则：**每种 biome 的"基础色"对应一种墨阶**——例如 Genesis 中 `Forest` 用浓墨阶映射到墨绿、`Beach` 用淡墨阶映射到米黄。每跨越 1 个墨阶，luma 差 ≈ 50。

### 2.4 程序化噪声参数

| 参数 | 值 | 用途 |
|------|---|------|
| 噪声类型 | Simplex（或 Perlin，2D 即可） | — |
| 频率 1 | 0.02 像素/单位 | 大尺度（生物群系形状） |
| 频率 2 | 0.10 像素/单位 | 中尺度（山脊/海岸） |
| 频率 3 | 0.50 像素/单位 | 小尺度（墨韵纹理，tile 内部） |
| 八度 | 3–4 | — |
| Lacunarity | 2.0 | — |
| Gain | 0.5 | — |

**用途分工**：
- 大尺度 → Biome 选择
- 中尺度 → tile 颜色的 ±1–2 级微调
- 小尺度 → 仅用于纪元过渡期的 2–3 秒渐变（详见 §2.6）

### 2.5 纪元色板派生

每进入下一纪元，色板按公式整体偏移：

| 字段 | 说明 |
|------|------|
| `biome[11]` | 11 种 biome 的基础色 |
| `saturation_scale` | 纪元整体饱和度乘子 |
| `value_bias` | 纪元整体明度偏移 |
| `tint_overlay` | 整屏色调（如灾厄纪元偏红） |
| `ink_offset` | 墨阶偏移量（−2…+2，影响"墨分五色"整体深度）| v1.1 新增 |

**派生规则**：
1. 基础偏移：朝下一纪元的目标色相旋转 N°
2. saturation_scale：繁荣→1.1，灾厄→0.7，混沌→1.3
3. value_bias：繁荣→+5，灾厄→−10
4. tint_overlay：灾厄 = (60, 0, 0, 40)，混沌 = (40, 20, 60, 30)
5. ink_offset：繁荣→+1（更浓），灾厄→−1（更淡），混沌→+2 + tint 偏紫

**纪元类型**：

| EraKind | 触发条件（示例） | 视觉特征 |
|---------|----------------|---------|
| Genesis 创世 | 第一个纪元 | 平衡、墨绿+米黄主导、中墨阶为主 |
| Flourishing 繁荣 | Boss 为守护者结局 | 饱和度↑，整屏偏暖金，墨阶加深 |
| Calamity 灾厄 | Boss 为灾厄结局 | 饱和度↓，整屏罩红，墨阶变淡（焦墨减少）|
| Chaos 混沌 | 混沌 Boss 结局 | 饱和度↑，紫青罩染，浓/焦墨显著增加 |

### 2.6 纪元过渡

进入下一纪元的视觉流程：

1. **t=0**：旧纪元色板 + 屏幕全屏 `tint_overlay`（alpha 从 0→180，0.8s）
2. **t=0.8s**：色板 swap（瞬间）
3. **t=0.8–3.0s**：新色板 + tint_overlay alpha 180→0（1.2s）
4. **t=3.0s**：恢复正常

期间生物剪影 tint 不变（剪影始终是"客观存在"，不受屏幕 tint 影响）。

### 2.7 水墨 shader 思路（v1.1 新增）

> 不强制使用具体语法，写下来是约束实现时的方向。

**核心要点**：

1. **采样**：对每像素同时采样 2 个频率的 Simplex：`elevation`（大尺度）+ `moisture`（中尺度）
2. **色板选择**：用 `(moisture, temperature)` 双线性插值在 11 色 biome 板中取色 → 落到"墨阶"（见 §2.3.1）
3. **羽化**：与 4 邻居色做 `mix(threshold, mix_weight)`，mix_weight 由 2 个 tile 中心的距离噪声决定
4. **不要做**：normal map、AO、specular、bloom、流动贴图——这是水墨，不是 3D 写实
5. **可缓存**：tile 颜色按 (world_seed, x, y, era) 哈希缓存，第一次进入地图一次性渲染到位图层

## 3. UI 层：剪纸 + 烫金

### 3.1 设计原则

1. **唯一的"金属高光"层**：UI 是画面里唯一出现烫金/烫银的位置；其它层保持哑光
2. **剪纸分隔**：UI 面板之间用"撕边"效果分隔（用 2 段贝塞尔/折线代替直边）
3. **字体有"刻"的质感**：烫金描边 + 微微凹进底板（阴影偏移 1 px）
4. **仪式感时刻专属**：世界祝福 / Boss 诞生 / 纪元跃迁 三个时刻必须出现烫金特效
5. **几何 & 折线 & 米色**：所有面板用矩形 + 折线修饰，不用圆角椭圆（破坏"剪纸"几何感）

### 3.2 字体规范

| 用途 | 字体风格 | 颜色 | 描边 |
|------|---------|------|------|
| 普通 HUD 文本 | 等宽 | `#DCDCDC` 浅灰 | 无 |
| 面板标题 | 等宽 | `#1A1815` 浓墨 | 1 px `#C9A961` 烫金（详见 3.4） |
| 关键数据（资源、tick） | 等宽 | `#DCDCDC` | 无 |
| 仪式时刻标题 | 等宽 | `#1A1815` | 2 px `#C9A961` 烫金 + 1 px 阴影 |
| Boss / 精英名字 | 等宽 | `#1A1815` | 1 px `#C9A961` 烫金 |
| 祝福文字 | 等宽 | `#1A1815` | 1 px `#D4D4D4` 烫银 |

**字号（pc 端标准，1080p 基准）**：

| 用途 | 字号 | 行高 |
|------|------|------|
| 资源 HUD | 14 pt | 18 pt |
| 面板标题 | 22 pt | 28 pt |
| 仪式大标题 | 64 pt | 72 pt |
| Boss 名字 | 36 pt | 44 pt |
| 图标下标签 | 12 pt | 14 pt |

> 字体保持等宽风格；不要用衬线/手写体破坏剪纸的"几何感"。等宽还能省下"对齐"心智——HUD 数字跳动不抖。

### 3.3 颜色 token

| Token | RGB | 用途 |
|-------|-----|------|
| `kPaperLight` | (245, 240, 226) | 米色纸底 |
| `kPaperMid` | (228, 220, 200) | 纸面分隔 |
| `kPaperDark` | (200, 188, 160) | 暗面 |
| `kInkDeep` | (26, 24, 21) | 浓墨（与生物层一致） |
| `kGoldHi` | (201, 169, 97) | 烫金高光 |
| `kGoldLo` | (140, 110, 50) | 烫金阴影 |
| `kSilverHi` | (212, 212, 212) | 烫银高光 |
| `kSilverLo` | (120, 120, 130) | 烫银阴影 |
| `kScrim` | (0, 0, 0, α=200) | 仪式时刻遮罩 |
| `kInkGhost` | (26, 24, 21, α=80) | 半透明墨（次要文字） |

> Token 必须**代码 + 文档同源**——任何视觉改动要先改 `ui_tokens.json`，再让它生成的 C++ const，确保 git diff 双向同步。

### 3.4 烫金描边实现

烫金不是单色描边，而是**渐变描边**——外侧暗金、内侧亮金，模拟金属反光。当前文本不支持渐变描边时，采用**叠两层文字**的近似实现：

- **阴影层**：1 px 偏移的暗金 `#C9A961`
- **主体层**：原位的亮金 `#C9A961` 的高亮版本

未来若引入 TTF 字体，可以做成真正的烫金渐变（横向渐变 + 1 px 描边）。

### 3.5 剪纸面板规范

1. **面板底**：米色 `kPaperLight` 平涂 + 1 px `kPaperDark` 描边
2. **撕边效果**：把 4 边的直线替换为折线（每 16 px 一段，±1 px 随机偏移），给"手撕纸"感
3. **面板分隔线**：用 1 px `kInkGhost` 横线，不用实色
4. **重要面板（祝福/图鉴）**：底色用 `kPaperMid`，四角加烫金小三角（4 个 4×4 的 `kGoldHi` 三角形）

### 3.6 三类仪式时刻的 UI 规范

| 时刻 | 触发 | UI 表现 |
|------|------|---------|
| **世界祝福** | 玩家选择祝福类型 | 屏幕中央弹出"卷轴"：米色纸底 + 烫金"祝福·繁荣/灾厄/蜕变/诅咒"标题 + 4 个可选项（每个选项的图标 = 该祝福的视觉符号，烫金或烫银描边） |
| **Boss 诞生** | elite 蜕变为 boss | 屏幕全屏 `kScrim` 半遮罩 + 中央烫金大标题 `[Boss 名]` + 副标题"灾厄/守护者/混沌"（烫银） |
| **纪元跃迁** | 阶段结算完成 | 全屏 `tint_overlay` 渐变（见 §2.6）+ 顶部烫金纪元名 banner |

**v1.1 新增仪式时刻**：

| 时刻 | 触发 | UI 表现 |
|------|------|---------|
| **生物死亡**（生态叙事用） | 物种灭绝、关键个体死亡 | 屏幕底部半透明剪纸条 + 烫银小字，1.5s 后淡出 |
| **首次发现新 biome** | 玩家首次踏入新 biome | 中央小卷轴弹出，烫金字 + biome 名 + 烫银一行小字描述 |

### 3.7 HUD 布局规范（v1.1 新增）

> HUD 是 UI 的"基础设施"——它错了，整个游戏的"剪纸"都会变成塑料。

**布局原则**：
- **左下**：资源 HUD（粮食 / 生物数 / tick）—— 永远是数据，不是故事
- **右上**：通知 / 时间戳 —— 玩家随时知道这是第几 tick
- **中央上**：纪元名 banner（只在 §2.6 过渡期出现）
- **不打扰**：未触发事件时 HUD 占比 ≤ 15% viewport

**网格（1080p 基准）**：

```
+---------------------------------------------------+
|                                       [时间戳]  ← 顶部 24px 安全边
|                                                   |
|                                                   |
|                                                   |
|                                                   |
|                                                   |
|                                                   |
| [资源HUD]                                          | ← 左下 320×120
+---------------------------------------------------+
```

**禁止 HUD**：
- ❌ 大数字（>4 位）显示——会"溢出"破坏米色纸面
- ❌ 圆角按钮——破坏"剪纸"几何
- ❌ 任何渐变色块——HUD 是哑光的
- ❌ emoji / 写实图标（见 §5）

### 3.8 图标 / 状态条 / Minimap 规范（v1.1 新增）

#### 3.8.1 图标规范

| 用途 | 风格 | 尺寸 |
|------|------|------|
| 资源图标 | 米色剪纸几何 + 烫金/烫银描边 | 32×32（@HUD 1×）、48×48（@HUD 2×） |
| 技能图标 | 米色剪纸几何 + 浓墨单色内填 | 48×48 |
| 通知图标 | 仅 2 种颜色：`kInkDeep` + `kGoldHi` | 24×24 |
| 祝福/诅咒 | 烫金或烫银单色剪纸符号 | 64×64 |

**禁止**：
- ❌ 多色渐变图标
- ❌ 写实图标 / emoji
- ❌ 同一图标出现 2 种以上的"金色 vs 银色"组合

#### 3.8.2 状态条

| 状态条 | 底色 | 进条色 | 边框 |
|--------|------|-------|------|
| 生命 HP | `kPaperDark` | 浓墨 `kInkDeep` | 1 px 浓墨 |
| 饥饿 / 能量 | `kPaperMid` | 烫金 `kGoldLo` | 1 px 浓墨 |
| 仪式进度 | `kPaperMid` | 烫金 `kGoldHi`（带微闪烁） | 1 px 烫金 |

**禁止**：
- ❌ 红绿血条——传统约定俗成，但与"墨色系"违和
- ❌ 渐变进条
- ❌ 数字跳动 > 1 fps——会眩晕

#### 3.8.3 Minimap

- **形状**：矩形，撕边 4 边
- **底色**：`kPaperMid`
- **生物点**：3×3 单色剪影示意色（用 tint 的色相，不画细节）
- **Biome 块**：直接渲染 §2 的墨色，不二次加工
- **视口框**：1 px 烫金

### 3.9 配色比例（60-30-10）（v1.1 新增）

> 这是把"墨色系"翻译成具体画面权重的尺子。

| 比例 | 内容 | 在三层中的体现 |
|------|------|--------------|
| **60%** | 环境（米色 + 淡墨） | 整个 viewport 背景 |
| **30%** | 生物（浓墨剪影 + 中等饱和 tint） | 角色 / 关键实体 |
| **10%** | UI（烫金 + 烫银） | 面板、仪式时刻、HUD |

**铁律**：
- 烫金面积累计 > 15% viewport → 烫金泛滥，立刻重审
- 烫金 + 烫银同帧 > 20% viewport → 全屏金属，破坏水墨

### 3.10 色弱友好（v1.1 新增）

> 我们只有 2 种"角色色"在工作：烫金 vs 烫银——这恰好是色弱最危险的组合之一。

**校验清单**（每个新仪式时刻的 UI 必须过这关）：

- [ ] **红绿色盲**：本游戏的"灾厄纪元"红色 tint 是否仍能被色弱玩家识别？（靠饱和度和明度差，不用色相单一区分）
- [ ] **金属 vs 非金属**：烫金 / 烫银 是否仅靠"质感"区分？建议：烫金配深色背景（kPaperDark），烫银配浅色背景（kPaperLight）——位置分离而非色相分离
- [ ] **生物 tint**：精英金 vs Boss 红 在色弱模拟下是否仍能分辨？→ 测试方法：用 Filter Pixel / Stark 跑一遍模拟，归档至 `assets/_qa/cvd_*.png`

**功能色强制规则**：
- ❌ 不要用"红 = 危险 / 绿 = 安全"作为唯一区分
- ✅ 配合"形状 + 位置 + 文字"多通道传达

## 5. 不做什么

明确写下来，避免后续扯皮：

- ❌ **不做真实 3D 渲染**——纯 2D，部件拼装
- ❌ **不做光追/动态光照**——墨色 + 平涂足够
- ❌ **不做位图地形贴图**——环境层全程程序化
- ❌ **不做花哨粒子**——演化节奏靠"被观察"而非"被炸"
- ❌ **不做像素风**——已经明确排除
- ❌ **不做写实色彩**——所有色相被刻意压饱和
- ❌ **不用 emoji 或写实图标**——所有 UI 图标用剪纸几何
- ❌ **不做圆角 UI 元素**——剪纸几何 = 直线 + 撕边
- ❌ **不做红绿功能色单一区分**——色弱友好，参见 §3.10
- ❌ **不做 HDR / Bloom**——金属高光仅限烫金/烫银的程序化绘制
- ❌ **不做骨骼动画**——所有动画差分从同一份 PNG 用数学变换产出（§1.2.4）
- ❌ **不做后处理色相 / LUT 滤镜**——纪元变化通过色板派生，不是后处理
- ❌ **不在生物层用阴影 / 高光**——只允许 1 处 2 px 的暗化结构提示
- ❌ **不在环境层加流动 / 闪烁**——水墨的"静"是生物"动"的背景

## 6. 美术走查流程（v1.1 新增）

> 风格的"一致性"不是自然发生的——它是每次合并都被走查 1 次才守住的。

**节点**：

1. **新建部件 / 新仪式时刻** → 必须 silhouette test + 色弱模拟 + 走查人签字
2. **每 2 周** → 抽 1 帧典型 viewport，做 §4 全量 checklist
3. **每纪元切换前** → 验收色板派生公式是否与 §2.5 字面一致
4. **每次美术风格大调整** → 必须同步更新 §0.7 版本表 + §5 "不做什么" 列表

**走查人不通过**的后果：资源不进主干 → CI 红 → PR 不能合并。

# 《矮人要塞》（Dwarf Fortress）调研：游戏架构与设计思路

> 调研日期：2026-10-21
> 调研对象：Bay 12 Games《Dwarf Fortress》，官方名
> *Slaves to Armok: God of Blood Chapter II: Dwarf Fortress*
> 方法：公开资料交叉验证（官方开发页 / DF Wiki / 英文与中文维基 / 开发者访谈 / Steam 页）
> 目的：为 `gamev2`（C++23 ECS + 仙侠程序化世界生成）提供架构与设计层面的参照

---

## 0. 一句话结论

《矮人要塞》不是一款"加了模拟系统的游戏"，而是**一个持续运行 24 年的世界模拟器，
游戏只是它的一层视图**。它的全部设计压在一句话上：*把历史、物理、心理、物质
写进规则，让故事自己长出来，玩家只负责在场。* 对本项目最有价值的不是它的具体
机制，而是三条结构性决策——**数据驱动（raws）、生成期即历史（Prepare for the
Wild）、失败即叙事（Losing is Fun）**——这三条恰好能直接映射到 `gamev2` 现有的
worldgen 与灵气层设计。

---

## 1. 核心判断

1. **DF 的产品形态是"模拟器优先，交互层后置"**。塔恩·亚当斯（Tarn Adams）
   的公开目标是"故事生成器"与"Big World Project"——一个从地质形成一直模拟到
   文化衰落的完整奇幻宇宙，游戏只是玩家可以插手的一小段。官方开发页的表述是：
   *"The long-term goal is to create a fantasy world simulator in which it is
   possible to take part in a rich history, occupying a variety of roles through
   the course of several games."*
2. **深度来自规则交互密度，不来自图形精度**。DF 用了 16 年 ASCII 而不碰美术，
   把全部工时压在模拟逻辑上；直到 2022 年商业化才由 Kitfox 补上图形与音效。
   这是一条被反复验证的取舍：**先让系统成立，再谈表现**。
3. **失败是被设计进系统的**。DF 没有胜利条件，要塞终将毁灭，社区口号是
   *"Losing is Fun!"*。失败不是惩罚，是**最有生产力的叙事事件**，也是学习闭环
   的载体。
4. **复杂度必须配可读性，DF 早期欠这笔债**。DF 把"可读性"拖到 v50（2022）
   才补（鼠标支持、UI 重做、信息中心、可点击小地图、教学流程）。这意味着
   **DF 的"深度"在 2006–2021 年间并没有转化为受众**。任何想复刻这条路的项目，
   都必须把"观察层"当成同等优先级的设计对象，而不是收尾工作。
5. **DF 的架构是"数据驱动的单体"**：一个自研 C++ 内核 + 一套文本数据文件
   （raws）+ 一份共享世界状态 + 三种观察模式。这四件套是本文第 3 节的骨架。

## 2. 项目档案

### 2.1 开发者与由来

- **开发者**：Bay 12 Games，塔恩·亚当斯（Toady One，主程 / 设计）与
  扎克·亚当斯（ThreeToe，主文案 / 设计）兄弟二人。塔恩拥有斯坦福数学博士
  学位（论文方向为 Banach 空间上的平坦链），2006 年放弃德州 A&M 的博士后
  教职全职做游戏。
- **由来**：2002 年 10 月，塔恩在做前作《Slaves to Armok: God of Blood》（3D
  RPG），新项目最初只是"两个月能做完"的支线工程，写作 RPG 过程中他对世界生成
  产生兴趣，项目遂转向。2004 年 DF 成为主项目，前作被放弃。
- **资金**：近二十年依靠玩家捐赠维持。2019 年塔恩与 Kitfox Games 合作推出
  付费版，公开动因之一是为自己与家人的医疗与生活开支提供稳定保障——这件事
  在 DF 社区被广泛讨论，也是它最终商业化的关键转折。

### 2.3 现状判断

DF 至今没有 1.0，也没有任何 1.0 的时间表；塔恩将其称为"毕生之作"并明确表示
即使发布后仍会继续开发。它的问题不在于**做不完**，而在于**完成的定义是持续
扩张的模拟维度**（每 2–3 年一个大版本，每次都重写某一层）。官方开发页在
Siege Update 之后列出的是"魔法、军队、外交、据点建造、地图"——没有一条是
"收尾"。

这对我们的启示是：DF 不是"一个做完了的项目"，而是"一个把'完整'定义为
持续进程的项目的极端样本"。学它的架构，别学它的终点。

## 3. 架构分析

### 3.0 分层总览

```
┌────────────────────────────────────────────────────────────┐
│  表现层  ASCII/CP437 瓦片 → v50 图形瓦片 → 语义文本层      │
│          （同一份模拟，多种渲染）                            │
├────────────────────────────────────────────────────────────┤
│  模式层  要塞模式(Fortress) / 冒险模式(Adventure) / 传说(Legends) │
│          三者读写同一份世界状态                             │
├────────────────────────────────────────────────────────────┤
│  模拟层  需求/情绪/记忆/关系/技能/伤病 + 流体/材料/物件      │
│          + 文明/战争/历史事件（与要塞共用同一套文明系统）     │
├────────────────────────────────────────────────────────────┤
│  数据层  raws：文本文件 + [OBJECT:TYPE] + [TOKEN:VALUE]     │
│          生物/物品/建筑/文明/材料/植物/反应/交互/语言…      │
├────────────────────────────────────────────────────────────┤
│  生成层  区域图 → 文明 → 据点 → 站点地图 → 地质/矿脉/生态     │
│          + 数百年的历史推演（Prepare for the Wild）           │
└────────────────────────────────────────────────────────────┘
```

### 3.1 数据层：raws（文本驱动的内容定义）

DF 把所有内容定义放在游戏目录下 `data/vanilla/` 的纯文本文件里，官方与社区
称之为 "the raws"。语法极简：

```
[OBJECT:TYPE]
[TYPE:ID]
...键值对与嵌套内容...
```

已核实的内容类型（DF Wiki "Raw file" 条目）：

- `BODY` / `BODY_DETAIL_PLAN` / `TISSUE_TEMPLATE` / `MATERIAL_TEMPLATE`：
  身体结构与材质模板
- `CREATURE` / `CREATURE_VARIATION`：生物与生物变体
- `ITEM_*`：十余个子类（武器、护甲、食物、陷阱组件、玩具、工具…）
- `BUILDING`：自定义工坊与冶炼厂
- `ENTITY`：文明类型（种族、语言、文化、伦理、社会结构）
- `PLANT` / `INORGANIC` / `REACTION` / `INTERACTION` / `LANGUAGE` /
  `MUSIC` / `SOUND` / `PALETTE` / `TEXT_SET` / `TILE_PAGE` 等

架构上值得注意的三条性质：

1. **文件名完全无意义**，游戏按文件首行决定加载顺序。内容与文件名解耦，
   允许玩家任意重排、拆分、合并。
2. **世界生成时 raws 被复制进存档目录**（`data/save/<region>/raw/`），
   存档自带一份"当时的世界定义"，这让世界与内容版本可以各自演进。
3. **DF 不是开源程序**，所以官方口径的 modding 手段就是"改 raws 或内存修改"。
   raws 事实上就是它的官方内容接口，也是社区生态的根。

代价也很明确（DF Wiki 明确写有）：**复制 raw 文件会导致难以诊断的异常甚至
崩溃**；raw 的解析顺序会影响 `COPY_TAGS_FROM` 一类标签。

> 对 gamev2 的意义见 §5.1。

### 3.2 生成层：世界先于玩家

DF 的第一步永远是"生成世界"，这一步本身就是一段可观的内容：

- **地图**：中点位移（midpoint displacement）生成海拔，配合分形技术做降水、
  矿藏、水系与温度的叠加。
- **尺寸预设**：以地区（region）为单位，从 Pocket 17×17 到 Large 257×257，
  文明数量上限从 3（极低）到 160（极高）不等，且上限随世界尺寸变化。
- **历史长度**：玩家可指定开局的"预演历史"年数（最短 2 年），且可在中途
  **打断**——这是官方明说的设计意图（想停在某个时代、或从死灵法师塔楼开局）。
- **遗忘猛兽**：按世界尺寸从 12 只到 867 只不等，这些巨兽在预演历史里
  游荡、杀戮、被杀。
- **据点数量**：文明扩张时新建城镇、聚落、森林静居等据点的总上限。

**关键在于：世界生成完毕后，历史并没有停止。** 中文维基明确记载：世界与历史
会随游戏进程继续推进，速度约为每次会话推进两周，要塞模式与冒险模式速度
相同。也就是说——

> 玩家不是在"创建世界"，而是在"进入一个已经运行了几百年的世界"，
> 而且这个世界在玩家离开后仍会继续跑。

这一条是 DF 全部叙事的根：**玩家的要塞是历史的后来者，不是历史的起点。**

### 3.3 模拟层：把"人"也当物理系统来写

DF 的模拟对象覆盖三个尺度：

| 尺度 | 典型要素 |
|---|---|
| 物质 | 地形、矿脉（按深度分层）、水流、岩浆、温度、作物、动物、材料属性 |
| 生物 | 骨骼/组织/器官、体温、伤病、截肢、窒息、营养、疲劳、年龄 |
| 人格 | 需求、情绪、压力（v50 改进了压力系统）、短期与长期记忆、关系、爱情、偏见、才能与技能成长、崩溃（tantrum） |

几个能在变更日志里核实到的具体设计，说明它"细到什么程度"：

- **矿物按深度分层**：50.01 把赤铁矿与磁铁矿的出现层数从 2 层/1 层放宽到
  全部 4 层——意味着"深度"是一个真正被建模的维度，不只是视觉分层。
- **生态按层差异化**：每条洞穴层有独特苔藓（第一层为洞底菌，第二层为洞苔，
  第三层新增地衣）；巨型洞穴蜘蛛被从上层两层移到下层两层。
- **记忆分层且会沉淀成人格**：v0.44.10 引入短期/长期情绪记忆，v0.44.11 让
  长期记忆可以导致性格变化。
- **战斗到解剖学级别**：中文维基记载战斗日志会出现"某组织被刺穿、脂肪淤伤、
  四肢被切断"之类的记录。

而让这一切产生戏剧性的机制，是**间接控制**：

> 玩家的指令不是"让这个矮人挖矿"，而是划定作业区、设定堆栈、安排优先级与
> 工坊。矮人自己决定去做什么、去学什么、去爱谁、去发疯。

玩家下达的是**约束**，不是**指令**。系统把约束转成任务队列，矮人自主填充。
这一层间接性，正是"涌现"能够发生的技术前提。

### 3.4 表现层：同一份模拟，多种渲染

- 经典版用 **CP437 字符集 + 颜色**渲染：矮人是彩色笑脸、猫是白色 `c`、
  狗是棕色 `d`、巨型洞穴蜘蛛是灰色 `S`。
- Premium 版允许玩家**手动解锁官方 2D 图形层或导入社区 tileset**——
  即：图形层是**可替换的插件**，不是模拟的一部分。
- v50 重做了整套 UI：教程与提示、鼠标支持、滚轮切换高度、缩放、可点击
  小地图、显示情绪的人口面板、常驻显示食物/饮料量与日期月相天气、
  新的信息中枢、带想法与记忆的角色面板、区域与房间统一的"zone"、
  可暂停的"burrow"、更好用的矿车搬运系统、把医院从 zone 升格为 location、
  列表搜索与排序等。

这张清单本身就是一份**可读性设计的需求文档**：每一条都在解决"信息存在但
玩家看不见"的问题。

### 3.5 模式架构：一份世界，多种视角

DF 有三种主要模式，全部落在同一个已生成的世界上：

- **要塞模式**：殖民地经营，无预设目标，以要塞毁灭/放弃/退休收场。
- **冒险模式**：回合制 roguelike，玩家扮演冒险者，可以回访自己留下的废弃
  要塞。
- **传说模式（Legends）**：旁观者沙盒，查看地图演变、各文明兴衰、任何个体
  一生；玩家在前两个模式中的显著成就也会被记入世界历史。

架构含义：**世界状态是世界的一等公民，玩法是它的视图。** 玩家结束一个
要塞后可以换一种模式继续玩同一张地图，并探索到自己留下的痕迹。

### 3.6 工程与团队结构

- 模拟内核由塔恩一人以 C++ 长期编写，非开源、非复用现成引擎。
- 图形、音效与发行由 Kitfox Games 承担（2022 年起）。这是一种**"内核自持 +
  表现外包"**的分工，也是小团队能撑住 24 年的关键结构性选择。
- 世界模拟的**外延在持续扩张**：官方在 Siege Update（2025-11）之后列出的
  下一步包含魔法、军队、外交、据点建造，以及一次"地图重做"（历史上称
  "Big Wait"）与"神话与魔法"大版本（拟引入神话生成与魔法系统，并用
  "奇幻度"参数调节世界的魔法浓度）。

## 4. 设计思路

### 4.1 产品定位：故事生成器，而不是游戏

塔恩自己的表述最清楚：他要造的是 **story generator**——涌现出的玩法来自
"数千个微观变量的相互碰撞"；他同时把"Big World Project"（从地质形成模拟
到文化衰落的完整奇幻宇宙）作为终极目标。

这一定位带来一个反直觉的推论：**游戏内容不需要被"完成"，只需要世界足够
丰富。** 于是 DF 的开发方式不是"加关卡、加敌人、加剧情"，而是"加一层模拟
维度"——加 z 轴、加记忆、加文明互动、加情绪、加魔法。每一次都是**扩宽
可能性的空间**，而不是**填充既定的空间**。

### 4.2 无胜利条件与失败主义

DF 没有胜利条件。每一座要塞，无论多成功，最终都会以某种方式毁灭。中文
维基把这句话写得很直接：*"由于在这款游戏中并没有'获胜'的方式……"*，
社区把它凝练成口号 **"Losing is Fun!"**。

DF 官方快速入门指南反复重申这条原则：*"Always remember that losing is fun!
Be prepared to lose a few fortresses before you get all the way through this
guide… losing means that next time, you'll remember how you lost. In a big way,
Dwarf Fortress uses the principle of learning from one's mistakes."*

这里的设计意图有两层：

1. **学习闭环**：失败是反馈通道，不是惩罚。玩家的成长不在数值，在"我这次
   是怎么死的"。
2. **叙事生产**：失败事件（岩浆挖穿、哥布林攻城、食物断供、亲戚被咬死、
   一次崩溃引发的连锁）恰恰是最有戏剧性的素材——因为它是**真实因果链的
   终点**，而不是作者安排的桥段。

把"失败"从终局重新定义为**产出**，是 DF 最重要的一次设计转向。

### 4.3 涌现与二阶设计

游戏设计理论里最常引用 DF 的一个案例，是著名的**猫死事件**：

> 猫喝到了洒出来的酒 → 酒精有致醉效果 → 猫呕吐 → 脱水 → 死亡 →
> 全堡陷入混乱。

这个事件**从未被设计过**。它是若干条各自简单到可笑的规则（猫会喝液体、
矮人会洒酒、酒精有致醉效果、脱水会致死）相互作用的产物。设计理论中称之为
**二阶设计（second-order design）**：作者写的是规则，玩家与系统共同生产了
故事。

同一逻辑的更狠版本是 **Boatmurdered**（2007 年 1 月）：玩家在一场论坛接力
赛中用岩浆防御、大象踩踏等手段抵御一波波哥布林入侵，最终要塞仍然覆灭。
这个故事后来成为 DF 涌现叙事的文化符号。

**可操作的判据**：如果一个事件能被写进剧本，它就不是涌现；如果它只能由
规则碰撞产生，它才是涌现。因此在 DF 的架构里，**剧本的位置极小**。

### 4.4 间接控制与玩家角色

玩家的动词不是"操作角色"，而是"设定环境与约束"。DF 的经典操作是：
划作业区、指定堆栈、设定优先级、安排工坊、组织小队、指定研究/训练方向。

这带来两个后果：

- **系统的自主性成为内容主体**：NPC 的行为本身就是可观看、可追溯、可复述的
  对象——"你看着有名字的 NPC 在更长的时间里彼此互动，比你在 RPG 里看排程
  NPC 仔细得多"（塔恩的表述）。
- **玩家的失败从"操作失误"变成"结构误判"**：因为系统一直在按你给的约束
  自主行动，崩盘往往源于你给的约束组合本身不合理。

### 4.5 历史先于玩家

上文 3.2 已述。设计上它有两个作用：

- **让世界有惯性**：玩家进场时，文明已经崛起又覆灭过若干轮，遗迹、神器、
  宿敌都带着来历。要塞不是建在真空里，是建在一段历史的地质层上。
- **让结束有意义**：玩家的要塞最终会毁灭，但它的毁灭会**写回世界的历史**，
  被后来者在冒险模式或传说模式中读到。**一次游戏的结局是另一个游戏的开场。**

### 4.6 深度不靠图形

Tarn 保持 ASCII 界面 16 年的公开理由是：不让开发时间被美术分流。这条取舍
的直接结果是 DF 的深度**全部**来自系统交互密度，而不是资产量——这也正是它
能在两人团队、零预算条件下做出 MoMA 藏品的根本原因。

反面是：ASCII 也让信息传达极慢。**这是一笔用 16 年利息换来的架构优势，
代价在 2022 年才用一整轮 UI 重做来偿还**（见 §4.7）。

### 4.7 深度必须配可读性（DF 的欠债与偿还）

DF 的受众问题是一个被反复证实的教训：

- 2006–2021 年，DF 是硬核小众，社区口口相传、教程靠论坛帖子、Wiki 顶礼
  膜拜，但**绝大多数人过不了第一关**。
- 2022 年 v50 才系统性补上：教程与提示、全鼠标支持、可点击小地图、
  信息中枢、带想法与记忆的角色面板、常驻状态显示、列表搜索与排序、
  区域统一、新手流程。
- 2024–2025 年冒险模式以 beta 形式先行测试（2024-04-17 起、2025-01-23 止），
  边测边把大量非冒险功能反哺进主线分支；2025 年起由 Kitfox 主导推送
  定期补丁。

**设计结论**：降低门槛 ≠ 降低深度。v50 的做法是**增加信息呈现层**，而不是
删系统。这与 DF 一贯的"加维度"哲学并不矛盾——观察层也是一"层"。

### 4.8 学术与行业评价

- DF 是游戏设计文献中被引用最多的涌现式设计案例，塔恩本人著有
  *"Emergent narrative in dwarf fortress"*（收于 *Procedural Storytelling in
  Game Design*，CRC Press，2019）与 *"Secret Identities in Dwarf Fortress"*
  （AIIDE 2017）。
- 研究者另有专文分析其叙事：Cartlidge, *Interpreting Dwarf Fortress:
  Finitude, Absurdity, and Narrative*（*Games and Culture* 19(2), 2024）；
  Fordyce, *Dwarf Fortress: Laboratory and Homestead*（*Games and Culture*
  13(1), 2018）。
- 社群侧则有 Games and Culture 对 DF 玩家"epistemic practice"（为科学
  而科学）的分析，以及 Archania 把 DF 描述为"layered computational ecology"
  ——地形、天气、文明、生物、神器、记忆、创伤、工作、流体与社会压力全部
  成为玩家可操作的象征材料。

行业影响方面，Notch 在《我的世界》开发期间公开称 DF 为直接灵感来源；DF 于
2012 年入选 MoMA 永久收藏；RimWorld 与 Prison Architect 团队均承认 DF 对
其模拟设计思路的影响。

## 5. 对 gamev2 的映射

本仓库现状：`src/world/` 下已有 17 个阶段的世界生成（阶段 1–10 地质水文，
阶段 11–17 灵气层），`src/ecs/` 是独立的 C++23 ECS 模块，
`doc/2026-10-19-worldgen-design.md` §10 已有「与 DF 的差异」对照表，
`doc/2026-10-20-worldview-xianxia.md` §10.2 已给出「故事引擎」的约束式设定。

> **本节已于 2026-10-21 落地。** §5.2 的建议被采纳为新模块「时序层」，
> 第一刀是**灵脉产权与开采台账**，设计文档见
> `doc/2026-10-21-history-layer-design.md`；灵气层设计文档 §9 的八条未决
> 问题同日拍板，其中第 5 条追加了阶段 18「渡劫场」。

### 5.1 raws 式数据驱动：把设定从代码搬到资产

**现状**：`include/gamev2/world/tables.hpp` 用 `inline constexpr` 承载群系查表
与矿脉定义，是"编译期内数据"；`spirit_tables.hpp` 同理。但仙侠设定中的
物种、九境、七宗、灵材、丹药、词条目前散落在代码与文档中。

**可借鉴**：DF 的 raws 证明了内容定义可以完全脱离代码迭代，且**能被外部
工具（包括 AI）批量生成与审校**。对 gamev2 的具体形态建议：

- 内容定义（物品/灵材/物种/宗门/词条/建筑）走**带 schema 的数据文件**，
  加载期解析成强类型表，仿真期只读表。
- **文件名无意义 + 按首行决定加载顺序**这条规则值得直接抄：它让内容可以任意
  拆分合并而无需维护 include 顺序。
- **仿照 DF 的"生成时快照"**：世界生成时把当次的内容定义随世界一起存档，
  使世界与内容版本解耦。

**需要避开的坑**（DF Wiki 明确记载）：复制/重名 raw 会导致难以诊断的异常；
raw 之间的加载顺序会影响 `COPY_TAGS_FROM` 一类继承语义。建议在数据层加
**加载期校验**（ID 唯一性、引用完整性、循环继承检测）——DF 缺这一环，
玩家用脚本报错代替了 schema 校验。

### 5.2 生成期即历史：把"人"放进生成阶段

**现状**：阶段 15 `make_historical_scars` 已经在生成期留下**地质性**的历史
痕迹（渡劫废墟对灵脉的损伤，见 spirit-layer 设计文档 §8.5），但世界里
还没有**活着的历史主体**——宗门与修士目前是静态设定标签。

**可借鉴**：DF 的"Prepare for the Wild"意味着——玩家进场时，世界已经自己
运转了几百年。gamev2 的灵气层已经具备产生这种"前史"的所有物理条件
（灵脉品阶、灵潮周期、历史疤痕、洞天），缺的是**把宗门与文明作为生成期
的活跃模拟体**，让它们在生成阶段就互相消耗灵脉、互相开战、互相覆灭。

**实现路径上的关键选择**：DF 的文明系统与要塞模拟**共用同一套实体系统**
（围城、贡赋、征兵、劫掠据点都是同一套文明/生物规则在跑）。因此 gamev2
若要生成宗门史，应当**复用 `src/ecs/` 的实体与系统框架**，而不是在
worldgen 里另写一套推演逻辑——否则"生成期的宗门"和"游玩期的宗门"将是
两套不能互相验证的模型。

### 5.3 涌现优先于剧本

**现状**：worldview §10.2 已经用**资源守恒律**取代了剧本化事件：

> 想救一方百姓 → 那方地正在枯竭的灵脉下；想阻止魔修 → 阻止的代价要由某个
> 具体的人承担。"这四句话就是本作的全部戏剧性来源。"

这与 DF 的路径完全同构——**戏剧性来自存量约束，不来自事件脚本**。

**建议保持并强化**：新增玩法时优先问"这个功能与既有的存量约束如何互相
咬合"，而不是"这个功能触发什么剧情"。DF 的判据可以直接借用：如果一个
事件能被写进剧本，它就不是涌现。

### 5.4 失败是产出，不是终局

**可借鉴**：DF 没有胜利条件，要塞毁灭后其历史仍留在世界里被后来者读到。
对应到修仙题材：

- 渡劫失败、宗门覆灭、灵脉枯竭**不应是 game over**，而应成为**世界史的
  一条目**，可在编年史/传说式中被检索、被后来者读到。
- "失败即学习"这条要落到机制上：失败后需要给玩家**可归因的复盘**——
  是哪条约束先绷不住、哪次资源再分配把人逼到绝路。DF 用 Boer 的
  "learning from one's mistakes" 循环，本质是要求游戏**能把失败讲成因果链**。

### 5.5 一份世界，多种视角

**可借鉴**：DF 三模式共享一份世界状态，玩家的要塞成为世界历史的一部分。
对应到修仙题材天然成立：

- 宗门经营视角（建造/分工/传承）
- 散修游历视角（回合制 roguelike，可在旧址寻访前人遗迹）
- 编年史视角（回看任一宗门/修士的一生与灵脉变迁）

**架构含义**：`gamev2` 的世界状态应当是**一等公民**，玩法是它的视图。
这与本仓库"世界不进 ECS"的决策（worldgen 设计文档 §8.1）**并不冲突**——
那条决策讲的是"生成期用规则访问比 ECS 更合适"，与"世界状态是否值得长期
保存并被多视角读取"是两个问题。前者已定，后者是后续需要决定的。

### 5.6 三条反面教训

1. **不要把可读性留到最后。** DF 拖了 16 年才补 UI，代价是十五年的受众
   局限。gamev2 的 ECS + worldgen 已经具备"信息很多"的条件，观察层
   （日志、归因、状态可视化）应当与生成层**同期设计**，而不是等生成稳定了
   再补。DF 的 v50 变更日志本身就是一份现成的需求清单。
2. **难度不要做成断崖。** DF 早期的劝退曲线陡到只能靠 Wiki 与老玩家带。
   降低门槛应走"加信息呈现、加教学、加默认建议"，而不是删系统。
3. **深度不等于细节数量。** DF 的深度来自**交互密度**：矿物分层、生态分层、
   记忆分层都是"同一维度上的差异"，而不是"多一个子系统"。对 gamev2 的
   具体风险是——继续加阶段（现在已 17 个）而不加"阶段之间的冲突"，
   世界会变得可生成但不可玩。§5.3 的"存量约束"其实就是冲突的来源。

### 5.7 DF 已验证、本项目已部分落地的模式

以下几条 DF 用 24 年验证过，且 `gamev2` 的现有设计已经同构，可视为
"路线已确认"：

| 模式 | DF 的做法 | gamev2 的对应 |
|---|---|---|
| 深度分层 | 矿物按深度分布；每条洞穴层独特苔藓；巨蛛层级分布 | `strata` + `deposits` 分层；灵气层按深度分等（龙/主/支/荒） |
| 生成期留痕 | 历史长度可预设、可中途打断；文明互相攻伐后留下遗址与神器 | 阶段 15 历史疤痕；灵潮周期 |
| 数据驱动内容 | raws 文本定义 + 类型化标签 | `tables.hpp` / `spirit_tables.hpp`（尚在编译期内） |
| 共享世界 | 三模式读写同一世界状态 | 待决策（§5.5） |
| 涌现式戏剧 | 规则碰撞生成故事，剧本位极小 | worldview §10.2 资源守恒律 |

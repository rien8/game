## 0. 本文定位

### 0.1 这个模块是什么

**众生层**（`gamev2::life`）是这个世界里第一层**玩法**：玩家在推演完成
的当代格局（8914）里选一个身位——某宗的弟子、长老、宗主，或一个散修——
接管这个人的年度决策，世界继续自行演化，人也自行演化，直到寿元耗尽，
再从自己培养的后继者里挑一个接着玩。

它之前的三层（worldgen / history / faction）全部声明「不是玩法」。本层
是它们之上的第一层玩法，但它自己**仍然不是游戏**：没有界面、没有存档、
没有胜负。它是一个**规则引擎**——决策接口 + 年循环推演 + 状态导出，
由 demo 文本驱动验证。UI 是后续纵切。

### 0.2 已拍板的总决定（2026-10-26，逐条有理由）

| # | 决定 | 理由 |
|---|---|---|
| 1 | **当代 8914 开局，向未来演化** | 8300→8914 是历史（既有推演作初始条件）；8914 之后是活的推演，派系层第一次跑「未来」 |
| 2 | **职位决定接管程度** | 弟子只是门里一个人；宗主接派系层该宗的决策（提案/表决）；散修完全不碰派系层 |
| 3 | **全面模拟人生** | 修炼、政治、人际、寿命与传承全要；范围大，故实现必须切纵切（§11） |
| 4 | **全员个体模拟**（DF 路线） | 每宗数百、散修数百、魔修数十，全部个体逐年演化；凡人抽象为聚落人口数 |
| 5 | **传承接管** | 玩家死后接手自己培养的后继者，一局跨几百年，与世界演化同步 |
| 6 | **先做规则引擎** | 无界面；决策接口 + 推进 + 导出；与仓库既有验证节奏一致 |
| 7 | **纯沙盒，无胜负** | 玩家自定目标（飞升、篡位、开宗、苟到灵潮）；引擎只负责把世界演化好 |
| 8 | **架构：双引擎、单向数据流** | 角色层把人口与用度交给派系层，派系层把配额与格局交回角色层；保住派系层既有验证资产 |
| 9 | **角色是厚属性模型** | 性格、能力、地位等多维属性驱动行为；用户明确定调「属性越多越好」，反对极简 |
| 10 | **属性全定档，不搞连续参数** | 性格 1..5、资质 1..9；档位来自种子，行为来自规则——「定性差异来自设定，数值差异来自状态」的延伸 |

### 0.3 本总设计做与不做

| 本设计覆盖 | 本设计不做（后续纵切） |
|---|---|
| 修士个体：境界、厚属性、职位、关系、灵石账 | 凡人个体化、王朝、鬼修、妖修、兽潮 |
| 年循环：9 步角色层 system + 派系层交接 | 月/旬粒度（年是最小步进） |
| 玩家接管：决策注入、宗主注入、传承、观察者 | UI、存档序列化（重放即存档） |
| 灵石经济：铸造、分配、断供、烧毁、守恒 | 市场、物价、交易撮合 |
| 战斗：一步判定（境界×体魄×档位+随机） | 回合制战斗、功法/神通/法器实体 |
| 渡劫接入：角色行动触发 history 层劫损结算 | 声望反馈派系层、决策 DSL、模组化 |

## 1. 总体架构与时间模型

### 1.1 三个引擎、一条年轴

1. **角色层**（本层，新）：全部修士个体住 `life` 自己的 `ecs::World`。
   **凡人不个体化**——他们是九成人口、不参与灵气经济主循环，按聚落
   抽象成人口数（散修聚落、王田、城邑）。修士总量数百到数千：七宗各
   百余人、散修数百、魔修数十。
2. **派系层**（已有，改造接入点）：6 个 system 照旧。**历史段
   （8300→8914）保持常量用度不动**，台账等价性回归测试原样成立；
   **未来段（8914 起）**的 `AssessSystem` 用度不再读常量，改读角色层
   上年汇总的各宗人口年度需求。这是对派系层唯一的结构性改造。
3. **数据流接口**（单向、每年一次）：两个纯数据结构——
   `FactionDemand`（各宗人口与需求，上交）与 `FactionOutcome`（产出
   清单、格局变化事件，回流）。两边是独立 ECS 世界，互不触碰内部状态。

### 1.2 年循环次序（一拍一年）

```
角色层（life，9 步，固定顺序）：
 1. ClockSystem          年 +1
 2. AgingSystem          年龄、寿元判定、伤病老化
 3. BirthSystem          聚落人口推演 + 伪灵根发现（修士补员来源）
 4. CultivateSystem      修炼：资源消耗、境界进度；突破判定
    ——玩家指令窗口（被接管者写 Motive）——
 5. DecideSystem         全员年度决策 → 写 Motive
 6. ActSystem            执行 Motive：历练、社交、经营、政事、盗采、夺位、寻仇
 7. EconomySystem        灵石结算：分配、克扣断供、散修营生、烧毁
 8. SummarizeSystem      汇总各宗人口与年度需求 → FactionDemand
——交接派系层：Assess..Resolve 六步推演一年——
    ——宗主玩家窗口（提案与否、表决意向）在 ResolveSystem 前——
 9. ReceiveSystem        派系层结果回流：产出入账、格局变化改写归属与
                          Standing、触发反应事件
```

**年粒度的理由**：与派系层同拍，整局可复算，接口无缝；「一局跨几百年」
的尺度里，年的信息密度已够（DF 的 legends 模式也是年）。月/旬粒度留给
UI 纵切时再议。

### 1.3 依赖与命名

- 命名空间：`gamev2::life`。
- CMake 目标：`life`（静态库）、`life_tests`（可执行）。
- 依赖：`life → faction → history → worldgen`，外加 `ecs`。
- 只读边界照旧：`life` 读 `World` 与 `Ledger`，不回写；对 `faction`
  是双向年交换但只经两个纯数据结构。

### 1.4 开局流程

```
worldgen 生成 World
  → history 推演台账（8300→8914，常量用度，既有测试守住）
  → faction 推演当代格局（8300→8914，既有测试守住）
  → life 从当代格局初始化众生：
      七宗按规模生成人口；境界分布按设定 §6.1 消耗金字塔反推
      （炼气众、筑基次之、金丹少、元婴寥寥）；
      属性档位由 (seed, 实体id) 无状态生成
  → 导出众生名册 → 玩家选身位（见 §5.1）
```

## 2. 角色数据模型：厚属性驱动行为

### 2.1 组件表（单一写入者纪律与派系层同规）

| 组件 | 内容 | 谁写 |
|---|---|---|
| `SoulId` | 姓名、性别、出生年、宗门归属或无主 | 出生/建实体时写一次（迁移是经批准的例外，§4.3） |
| `Cultivation` | 境界（九境枚举）、境界内进度、灵根资质 | 修炼 system 写 |
| `Aptitude` | 能力四轴：悟性、神识、体魄、韧性（各 1..9 档） | 建实体时由种子生成，此后不变（资质天生） |
| `Temper` | 性格五轴：贪婪-节制、怯懦-勇烈、守序-悖逆、仁厚-酷烈、慵懒-进取（各 1..5 档） | 建实体时生成；大事可缓慢推移，±1 档上限、十年缓变 |
| `Mortal` | 年龄、寿元上限（由境界定，设定 §5.1 表）、健康/伤势/暗疾 | 老化 system 写 |
| `Purse` | 灵石账（按品级折算成统一记账单位）、欠账 | 经济 system 写 |
| `Office` | 职位、在位年数、上位途径（继承/晋升/夺位） | 任命与继承 system 写 |
| `Standing` | 声望（七宗各一维 + 散修圈一维）、罪名记录 | 事件 system 写 |
| `Bonds` | 关系边：师徒、亲缘、道侣、恩义、仇怨（带强度与年份），存边、两端同写 | 社交 system 写 |
| `Motive` | 当年意图（行为决议），年后清空 | 决策 system 写，行为 system 读；玩家的接管点即此 |

**厚属性的纪律**：属性轴**全部定档**（性格 1..5、资质 1..9），不搞 0.73
这种连续参数。档位来自种子，行为来自规则。设定给了数值的地方逐字用
设定（寿元表、吸纳表、突破门槛资源）；设定没给的地方（性格分布、资质
分布）由开局人口标定决定，进世界常数表（§6），并写明是标定值。

### 2.2 属性如何驱动行为——判定式，不是效用函数

每个 NPC 每年一次**年度决策**。不做打分排序的效用最大化，做**按序
短路的属性阈值判定**（可复算、可读、可测试）：

```
判据（按序短路）：
1. 寿元危机（剩余寿元 < 突破所需年限）
     → 优先突破；贪婪轴 > 中值且无路可走时选盗采
2. 缺口（宗门断供 / 灵石 < 年消耗）
     → 守序轴高者做任务营生；悖逆轴高者盗采
3. 亲缘/师徒有难（Bonds 里有人重伤/被夺）
     → 勇烈轴 > 中值者去救/去报仇；怯懦者记仇（加仇怨边）
4. 声望收益机会（Standing 可升）
     → 仁厚者结善缘；酷烈者立威
5. 默认：修炼；慵懒-进取轴决定闭关 vs 历练的偏好
```

**性格轴是岔路选择器**：同样的处境，不同性格走不同分支。**能力轴
决定成败**：突破判定 = 悟性 × 资源充足度；历战斗判定 = 境界 × 体魄 ×
法器档位。**声望决定被谁看见**：夺位、提名、散修投靠都读 `Standing`。

**战斗是一步判定**：境界差 × 体魄 × 档位 + 无状态随机；越级手段
（阵法/符箓/燃寿，设定 §5.3）第一版不进判定，留给后续纵切。

### 2.3 职位阶梯：权限与资源，不是荣誉头衔

| 职位 | 资源分配权 | 政治权 | 玩家接管点 |
|---|---|---|---|
| 宗主 | 宗门灵石分配、洞天使用 | 派系层决策注入（提案/表决/越采默许） | 派系层 `ResolveSystem` 的该宗决策 |
| 长老 | 供养配额高 | 提名权（影响宗主继承人推举） | 角色层：提名、门内经营 |
| 内门弟子 | 标准供给 | 无 | 角色层：修炼/历练/社交 |
| 外门弟子 | 糊口供给 | 无 | 同上，目标是升内门 |
| 散修 | 无供给，全靠自己 | 无 | 角色层 + 经济层；可盗采（风险自担） |

**上位与换代**：状态驱动，无性格参数门槛——境界够了、上一任死了/
突破了、没有更年长者压着，就晋升。宗主之位由长老团推举（读
`Cultivation` + `Standing` + 亲缘）；`Temper.悖逆` 高且有实力的长老可
**夺位**——成功率读境界差与门内声望，失败按对方酷烈程度被杀或被逐。
玩家在继承序列内时，接任权交给玩家选择。

### 2.4 突破与寿元

突破 = **资源门槛 + 概率**两轴：

- 资源门槛逐字用设定 §5.1：引气一枚下品；筑基结基灵物（20~30 中品）；
  金丹要**厚域位置约束**（必须在厚域格闭关，接 worldgen 的
  `SpiritDomain` 等级）；元婴百年闭关（`Motive` 锁死、有被仇家寻衅的
  风险）。
- 概率读 `Aptitude.悟性` 与资源充足度，失败损资源不损命（渡劫另说，
  §3.6）。
- 寿元表用设定 §5.1：引气 120、炼气 150、筑基 300、金丹 600、元婴
  1200、化神 2400、炼虚 5000、合体 10000、大乘近乎无穷。

## 3. 经济层：灵石账与两层的接口

### 3.1 一本账：灵石从脉里来，被修炼烧掉

设定 §6.1 的致命特性——灵石既是钱又是燃料——就是经济层的骨架。
灵石流动是单向河：

```
灵脉开采（派系层逐年产出）
  → 铸入宗门金库 / 散修私囊（分配）
    → 修士吸纳、法器运转（烧毁）
      → 消失（紧缩）
```

**不建模市场**：无商品价格表、无交易撮合。修士间灵石转移（供给、
赏赐、抢夺）是账面转移；「买东西」用固定换价（设定 §6.4：一枚下品
折两千两、灵砂二十两）。做半套市场比没有更坏。

### 3.2 换算系数 kVeinToStone：全局唯一、单向换算

派系层的 `VeinStock::taken` 是无量纲指数（派系设计 §8.7），灵石是
计数单位。全局唯一系数：

```
当年天下脉总产出 × kVeinToStone = 天下灵石总产出
标定锚点：设定 §6.1.1 天机阁年度估算——天下年产 4200 中品
```

**纪律与派系层 `F` 系数同源**：系数只写一份，放 `life/economy.hpp`；
派系层不认识灵石，角色层单向换算。这是标定值，进世界常数表（§6）。

### 3.3 宗门分配：Office 切蛋糕，制度即固化

宗门金库年收入 = 该宗名下脉的合法产出换算。分配是**制度性固定份额**
（份额表是设定给定常量）：宗主最高优先、长老高份额、内门标准份、
外门糊口份。

**断供机制**是经济层压回角色层的力：派系层算出的该宗产出不足时，
份额**从底层往上克扣**——外门先饿，内门次之，长老宗主不动。被克扣
者触发 §2.2 判据 2（搞钱/盗采）。这是「宗门衰落时最先跑的是外门
弟子」的机制来源。

### 3.4 散修经济：设定 §6.4 的数学原样入账

散修没有供给，收入三条路：**营生**（猎兽采药押镖，年入约六十两）、
**盗采**（无主脉私采，扣 `Standing` 与派系层的发现判定——被发现是
角色层横死来源）、**卖命**（受雇/药奴，抽象收入流）。

**三十三年一枚下品的绝望数学不调参、原样保留**——它是散修路线的
难度设定，砍了它散修就不是散修。

### 3.5 守恒与对账

角色层经济自己的恒等式，逐年结算后校验：

```
Σ(所有金库 + 所有私囊) = 累计铸造 − 累计烧毁
当年：Σ收入 = 脉产出 × kVeinToStone（没有第二个来源）
```

灵石不与派系层的脉守恒式（`quota_total == stock + extracted`）混算
——脉的守恒在派系层，灵石是它下游的影子账。两层各自守恒、在接口处
对一次账：派系层 `FactionOutcome` 的产出清单逐宗求和 == 角色层收入的
铸造总额。这条进测试（§8 守恒类）。

### 3.6 渡劫接入：历史事件变成行动后果

渡劫成功率的判定第一版只看**境界门槛资源是否备齐**，失败概率标定。
渡劫失败触发的是 history 层**已有的劫损机制**（`tribulation`）——
渡劫不再只是历史层按候选池抽样的事件，而是角色层玩家/NPC 行动的
后果：`渡劫(尝试, 地点)` 决策 → 结算成败 → 失败则逐脉劫损入账。
这是两层接上的第二个点。

## 4. 世界演化引擎：推演循环与确定性

### 4.1 确定性：全员随机必须无状态派生

个体规模数千、每步都可能掷骰（突破、遭遇、性格推移、生子）。沿用
`world/rng.hpp` 铁律：**随机流按 `(seed, 流号, 年, 实体id)` 派生，与
遍历顺序无关**。新增 `Stream::life = 19`（`kStreamIds` 同步扩到 20，
`static_assert` 守重复）。**不共用既有任何流**：混流会让调 life 层
参数扰动 history/faction 的既有 fixture。

同一实体在任何遍历顺序下抽到同一个性格、同一个突破结果。同 seed
重跑，**全部个体的全部字段逐年逐位相同**——这是 life 层确定性测试
的断言形态。

### 4.2 性能预算

数千实体 × 9 system × 数百年 ≈ 10⁷~10⁸ 次基本操作，串行毫秒~秒级
一年，可接受。**不引入并行**（继承派系设计 §3.13 的结论：
`each_parallel` 在 system 批内的行为不确定），可复算性优先于吞吐。
若日后某步成为瓶颈，纵切再加并行且必附「并行不改结果」的等价性测试。

### 4.3 格局变化怎么落到人身上（步 9 ReceiveSystem）

派系层的格局事件（换主、公有化、枯竭、重勘通过）落到个体：

- **脉被夺**：该脉供养的修士整体改宗归属。`SoulId` 归属本属「建实体
  写一次」纪律，此处开**经批准的迁移写入者**——迁移事件是唯一写入源。
- **重勘通过**：受益宗加供、受损宗减供，`Standing` 按损益推移。
- **宗门覆灭**（派系层此刀未做，接口预留）：名册整体变散修。

### 4.4 存档即重放

第一版**不做序列化存档**：确定性 + 玩家决策序列 == 存档。一局 =
`(seed, params, 开局身位, 逐年玩家决策序列)`，重放得到同世界。接口
上只保证「玩家决策」可序列化（决策枚举 + 参数），第一版决策日志留
内存。存档格式是后续纵切。

## 5. 玩家接管、决策注入与传承

### 5.1 玩家不是特权实体——是「被接管者」

玩家角色与 NPC 数据上**零差别**：同样的组件、同样的判定。区别只有
一条：每年步 5 前被接管者的 `Motive` 由玩家输入写入，而非判定式生成。
引擎里没有「玩家」实体，只有**本年接管表**（`entity_id → 决策` 的小
表），是引擎唯一对外的接口。

**开局选择器**：当代格局初始化后导出众生名册（按宗门、职位、境界
过滤），玩家挑一个身位，或选「散修新生」——在散修池生成一个新个体
（伪灵根、低资质）从零开始。名册选择意味着继承那个 NPC 的全部
`Temper`/`Bonds`/`Standing`——选宗主就是接盘太玄宗的霸权与它的仇家。
**职位不是难度选项，是处境。**

### 5.2 决策注入的表达

玩家决策是可序列化的枚举 + 参数，动作集与 NPC 的 `Motive` **共用**：

```
修炼(地点) / 闭关(年限) / 突破(尝试) / 历练(区域) / 盗采(脉)
社交(对象, 方式) / 经营(营生) / 政事(提名/表决意向) / 渡劫(尝试, 地点)
夺位(挑战对象) / 收徒(对象) / 传位(继承人)
```

**指令受身位约束**：弟子下不了政事指令，散社交里动不了宗门资源。
越权指令被拒绝并报诊断——引擎没有「玩家可以作弊」的暗门。

### 5.3 宗主的派系层注入：意愿，不是算术

宗主玩家在派系层 `ResolveSystem` 前有两个决策：

- **提案**：是否提前发起重勘（受 `kEarlyRedraftInterval` 约束）；
- **表决意向**：本宗对清单投赞成/反对。

注入方式与角色层同构：`faction_id → 决策` 的表。**清单生成规则不变**
——提案者按余力构造，NPC 宗主与玩家宗主同一条规则；玩家能**否掉**
规则想提的案、能对清单表态，**不能手改清单**。玩家接管意愿，不接管
算术——脉律的试算、配额、守恒照旧，防止玩家绕开经济层的稀缺性。

### 5.4 传承接管

被接管者死亡（寿元、横死、渡劫失败、夺位失败）时：

1. **后继者提名**：引擎按 `Bonds`（亲缘 > 师徒 > 道侣）与 `Standing`
   生成候选序列，玩家挑一个接管，或放弃此局进入观察者模式。
2. **继承结算**：灵石账按惯例分配（无继承人入宗门金库）；
   **`Bonds` 跟人走**——你接管的弟子，他的仇家就是你现在的仇家；
   **`Standing` 是个人的，不继承**，新人从头攒。
3. **无候选**（孤家散修死在荒野）：按开局选择器重新挑身位，相当于
   半局重开——散修路线的真实风险。

### 5.5 观察者模式

任何时刻玩家可「放下」接管（或死后不选后继），引擎继续无玩家推演
——「世界自行演化」的裸形态，也是调试与测试通道：demo 驱动引擎跑
数百年无决策注入，产出众生兴衰的编年文本。

## 8. 测试策略

沿用 `tests/test_framework.hpp` 的 `TEST` / `CHECK_EQ`，先写失败的测试。
断言分五类：

| 类 | 用例形态 | 守什么 |
|---|---|---|
| **确定性** | 同 seed 重跑数百年，全员全字段逐年逐位相同；换遍历顺序结果不变 | 随机无状态派生这条命根子 |
| **守恒** | 灵石恒等式逐年校验；接口对账：铸造额 == 产出清单×kVeinToStone | 两本账不串 |
| **涌现验收（招牌）** | 固定 seed 当代开局跑 300 年**无玩家注入**：① 至少一次宗主换代非脚本；② 至少一次断供引发的底层出走（外门变散修）；③ 至少一次盗采/夺位/寻仇类冲突事件；④ 人口金字塔随灵潮年变化（衰退期修士总量下降） | 「角色自行演化」不是空代码 |
| **标定值** | 散修攒灵石速率 ≈ 33 年一枚下品的量级；元婴年消耗 ≈ 天下年产八分之一的量级 | 世界常数锚定设定 |
| **退化路径** | 空世界、当代早于纪元、开局身位死于首年、全员死亡 | 诊断量报出，不崩溃 |

- **图幅**：测试用 128×128（history 层已验证该尺寸灵脉/渡劫场非空）；
  fixture 种子实施时用探针实测后钉死，不靠推算。
- **涌现验收必须能自动判定**：比对的是「事件类型出现与否」与「人口
  统计的形状」，不是某个写死的具体人物命运。
- **变异要求**照既有规矩，每条招牌断言能被变异打红：性格轴不参与
  判定 → 涌现断言红；灵石烧毁不扣账 → 守恒红；断供不克扣 → 出走断言红。
- **派系层等价性回归**：历史段（8300→8914）逐位相等的既有测试必须
  原样成立——life 层接入不得影响历史段半分。

## 9. 已知限制（写明，不假装做了）

1. **凡人是人口数字**：无个体凡人；王朝、鬼修、妖修、兽潮不进第一版。
2. **不做市场**：固定换价；散修「卖命」是抽象收入流。
3. **功法/神通/法器不是实体**：法器只是战力判定的一个档位。
4. **战斗是一步判定**：越级手段（设定 §5.3）留给后续纵切。
5. **无存档序列化、无 UI**：重放即存档；demo 是文本编年。
6. **未来段的派系行为因人口波动而不同**——这是特性不是 bug，要守卫
   测试防止有人把它「修」回去。
7. **声望不反馈派系层**：`Standing` 只影响角色层；声望→派系实力留给
   后续（派系设计 §8.2 的限制在本层仍然成立）。
8. **决策集封闭**：动作枚举固定，模组化决策 DSL 不做。
9. **元婴百年闭关期间的「被寻衅风险」**只做概率判定，不做闭关中
   反击的战斗细节。
10. **渡劫失败的概率**沿用标定值 0.3；角色层不区分四关口（与
    history 层 §9.4 同决定）。

## 11. 实施计划预告：纵切分刀

范围太大，一刀做完无法验证。总设计先行，实现按既有节奏分刀，每刀
独立可验、先写失败的测试、每刀报告后等用户提交指令（**不执行
`git commit`**）。建议切法：

1. **刀 1：骨架与开局**——组件、ECS 世界、从当代格局初始化众生、
   开局名册导出。验：确定性初始化（同 seed 同名册）、人口金字塔形状。
2. **刀 2：修炼与寿元**——Cultivate/Aging、境界推进、寿元死亡。
   验：无决策注入跑百年，人口金字塔随年演化、寿元表逐字对设定。
3. **刀 3：经济**——Purse、kVeinToStone、宗门分配与断供克扣、散修
   营生、守恒。验：灵石恒等式、接口对账、33 年一枚下品的标定测试。
4. **刀 4：决策与行为**——厚属性、判定式决策、Motive/Act、战斗一步
   判定、盗采与横死。验：涌现验收招牌断言（四条）。
5. **刀 5：派系层接入**——FactionDemand/Outcome、未来段用度接变、
   格局变化落到人。验：历史段等价性回归原样成立、未来段人口反哺可见。
6. **刀 6：玩家与传承**——接管表、决策注入、身位约束、宗主注入、
   传承接管、观察者模式。验：玩家指令管线、越权拒绝、传承 Bonds 跟人走。
7. **刀 7：渡劫接入与编年**——渡劫决策触发 history 劫损、demo 编年。
   验：渡劫行动 → 劫损入账的因果链、编年可导出。

每刀实施计划届时另出（`doc/plans/`），本预告只定切法与验证面。

## 0. 本文定位

### 0.1 这个模块是什么

**派系演化层**是把「已经生成好的世界」放进一个**活的状态里**、往前推演六百年、
产出**当代格局**的模块。

它的产物不是地图，也不是账，而是**六百年里谁手里还剩多少、谁被夺了、
谁在越采、哪年枯的、格局在哪一年变过**。

它不是玩法。它不产生玩家操作，不产生胜负，不产生画面。

### 0.2 为什么不是第 19 个生成阶段

时序层设计 §0.2 已经把边界画出来了：worldgen 产出的地形与灵气分布是
时间推演的**初始条件**，不是推演本身。派系演化层遵守同一条边界，并再加两条：

1. **它不回写 worldgen 的任何字段**——与时序层同规。
2. **它有状态**。时序层是一次性推演：算完就散；派系演化层的状态**六百年
   一直在变**，而且它是**下一年的输入**。

第 2 条决定了它的形态：一次性推演用不着状态容器，一个函数就够；有状态的
推演需要「谁在什么时候能改什么」的纪律——这正是 ECS 提供的东西。

### 0.3 本轮只做第一刀

本模块的完整形态很大（宗门兴衰、结盟、兽潮、渡劫、鬼修、魔修、王朝），
但那些是**后续纵切**。本轮只做一条纵切，且刻意把它做到能独立验证：

| 本轮做 | 本轮不做 |
|---|---|
| 用 ECS 承载活状态（脉、派系、洞天、时钟） | 人口与弟子规模 |
| 8300 → 当代 614 年的逐年推演 | 推演未来（当代之后） |
| 用度与供给的缺口 | 灵石经济与洞天的产能 |
| 合法开采、越采、私采 | 跨派系偷采与追查 |
| 枯竭、公有化、阴脉采出即衰 | 派系覆灭、结盟、叛出 |
| 脉律重勘程序：提案、清单、表决 | 战争、战斗、伤亡 |
| 当代格局、事件表、与台账的对照 | 灵脉恢复、渲染、存档、UI |
| 对照表：与设定参照布局的差异 | 王朝、兽潮、渡劫实体化、鬼修与魔修实体 |

纵切选择的理由：**当代格局是设定 §10.1 四个冲突的物证**。设定说
「老配额不公是所有冲突的起点」，但老配额是怎么变成今天这个样子的，
台账答不了——台账设计 §8.1 承认了这一点：「持有格局是设定给定的，
不是涌现的」。

这一刀要让持有格局**变成涌现的**：太玄宗怎么保住龙脉的，寒江剑府怎么
变成没脉的，九幽宫怎么把自己的脉抽干。做到了这一点，设定 §10.1 的
「枯墟之谜」与「魔修复起」才不是文本，而是可复算的结果。

### 0.4 这一刀的产物长什么样

三样东西，对应三类读者：

1. **当代格局表**：每个宗派现在有几条脉、多少余额、供给多少、缺多少、
   越采多少、被夺过什么。读者是人——它要被当成"这份天下现在归谁"来读。
2. **事件表**：六百年里每一次枯竭、公有化、重勘提案、表决、越采被发现。
   读者是史官——它是一条条带年份的事。
3. **对照表**：当代格局 vs 台账基准推演的差异。读者是要判断"派系行为
   到底让天下烂了多少"的人。基准是无派系的理想世界，现实是有派系的
   天下，两者之差就是派系的代价。

对照表同时报出**当代持有表与设定 §8.1 参照持有表的差异**。本层不保证
复现设定给定的当代布局：设定给的是 **8300 年的分配**（时序层的起点），
当代的实际持有是六百年推演的结果。两张表不一样是正常的，差异本身就是
产物（§8.5）。

## 1. 与既有框架的关系

### 1.1 读 worldgen 与台账，不回写

本层读两样东西：

- **worldgen 的 `World`**：灵脉、灵眼、洞天、灵潮。这些是初始条件。
- **时序层的 `Ledger`**：8300 年的持有格局与配额快照。这是**制度**——
  六百年前《脉律》核定的结果，是本层的出发点而不是本层的产物。

本层**不回写**这两个对象里的任何一个字段。它的全部状态住在自己的
`ecs::World` 里。这条纪律与灵气层的「纯追加，不回写」、时序层的
「只读，不回写」同源：**一个字段只有一个写入者**。

### 1.2 与台账的关系：基准与现实

时序层的台账是一份**无派系的基准推演**：持有格局设定给定，开采被配额
封顶，越采是按年份抽样认领的。台账回答的是「按制度推演，六百年后
应该是什么账」。

派系演化层是**有派系的现实**：持有格局会变（公有化、转让），缺口会
驱动越采与私采，配额会因重勘而重新分配。

两者的关系是**对照组**：

- 两者共用同一套原语（有效流速、总量配额、潮位折算）与**同一个标定
  系数**（§3.2），所以数字可以直接对照。
- 守恒恒等式在两套推演里都成立，只是口径不同：台账是「配额封顶」，
  本层是「余额封顶」（余额不会变负）。
- 差值 = 派系行为的代价。

§1.2 的推论有一条硬约束：**本层不允许重新标定流速**。两边各算一套
系数的话，对照表立刻失去意义——台账代码里对「越采削减比例」的处理
（`ledger.cpp` 顶部「共享的那一份」注释）就是这个教训。

### 1.3 纪元与跨度

- **纪元 8300**：《脉律》核定的年份，沿用时序层的 `epoch`。
- **当代 8914**：`world.params().spirit_year`，沿用台账的 `now`。
- **跨度 614 年**：逐年推进，年份区间 [8300, 8914)。

当代早于纪元时（`spirit_year < 8300`）本层为空，与台账同规（台账
§5）：没有「从 8300 推到当代」这件事，硬推出来的格局没有意义。

### 1.4 命名、目标与依赖

- 命名空间：`gamev2::faction`。
- CMake 目标：`faction`（静态库）、`faction_tests`（可执行）。
- 依赖：`faction` → `history` → `worldgen`，外加 `ecs`。

**`faction` 依赖 `history` 不是为了借类型方便，是为了让两边共享原语**
（§3.2、§3.10）：换算系数与阴脉判定各写一份，两边会静默错位，而这种
错位在结果里看不出来。

## 2. 数据模型

### 2.1 为什么状态住在 ECS 里

三条理由，第三条最实际：

1. **DF 调研 §5.7 的结论**：世界状态是世界的一等公民，玩法是它的视图。
   本层的产物（当代格局）就是「世界状态的一个切片」。
2. **单一写入者**：脉的余额与归属会被多方主张。若这些量散在一个
   `std::vector` 里，谁都能写，纪律靠自觉；放在 ECS 组件里，写入者
   由 system 的读写集限定，冲突由调度器检出。
3. **每件事的归属清楚**：谁在改脉的余额、谁在改脉的归属、谁在表决，
   在调度计划里一眼看得见。一次性推演函数做不到这一点——它把所有
   规则塞进一个几百行的循环里。

**但本层不追求并行**。规模是 8 个派系、约 50 条脉、614 年，总工作量
十万量级，串行跑完是毫秒级。ECS 在这里的价值是**所有权纪律与系统
分解**，不是吞吐。这一点必须写明，否则后人会误以为本层需要调
`each_parallel`，而那一路在本层是错的（§3.13）。

### 2.2 实体与组件的对应

| 实体 | 组件 | 谁写 |
|---|---|---|
| 派系 | `FactionId`、`FactionBalance`、`FactionIntent` | 建实体时写 `FactionId`；`FactionBalance` 见 §3.13；`FactionIntent` 只有 `ResolveSystem` |
| 脉 | `VeinId`、`VeinProfile`、`VeinRight`、`VeinStock`、`VeinOwner`、`VeinRemainder` | 见 §3.13 |
| 洞天 | `CaveHeavenId`、`CaveHeavenState` | 建实体时写 `CaveHeavenId`；`DepleteSystem` 写 `CaveHeavenState` |
| 时钟 | `SimClock` | `ClockSystem` |

**建实体时写一次、此后只读的组件**：`FactionId`、`VeinId`、
`VeinProfile`、`VeinRight`、`VeinRemainder`、`CaveHeavenId`。
它们的唯一写入者是建实体的那一步（`setup`），此后没有任何 system
改它们——这条「一个字段只有一个写入者」在实现时要有据可依，不能
只写一半。

**例外**：`FactionIntent` 建实体时写下 `may_propose`，但 `proposed_year`
由 `ResolveSystem` 在提案时改——它不是只读组件。

**两处已知的记账缺口**（留给最终整枝审阅分诊，导出层已用列名与口径注
标出）：

- `VeinStock::public_year` 是**幂等凭据**而不是一张账：`ResolveSystem`
  靠它判断「这条脉公有化过了没有」，否则每年会重复记一笔公有化事件。
  它不进报告——报告里的公有化年份在事件表里。
- `CaveHeavenState::owner` 停在 8300 的持有者，脉转手时不跟着走。
  「洞天跟随脉」在当前的写入者纪律下无处安放（`CaveHeavenState` 只有
  `DepleteSystem` 写），所以本层按「洞天归 8300 的主人」记，导出的
  列名与口径注都写明这一点。

**脉为什么是实体而不是数组里的一个 struct**：脉的归属会变（公有化、
转让），而余额会被多方读取。放在数组里，`veins[i].owner` 就成了
「所有派系都能写」的一个字段；放进 ECS，它的写入者只有一个 system。

**时钟为什么是实体**：ECS 没有单例。本层不引入单例机制（那是一个
新抽象，且只有一个使用者），而是把时钟做成一个专属实体上的组件，
各 system 在构造时拿到它的 `EntityId`。

### 2.3 组件定义

```cpp
namespace gamev2::faction {

/// 派系身份。复用时序层的 Sect 枚举：两个枚举会静默错位，
/// 而台账的持有格局正是本层的初始条件。
struct FactionId
{
    history::Sect sect = history::Sect::unowned;
};

/// 派系的年度账。
struct FactionBalance
{
    /// 用度：门人每年要采出的量。制度量，固定不变。
    ///
    /// 无上限用度的派系（魔修、散修）这一项恒为 0，改由
    /// `unbounded_demand` 表达：用度没有上限，就没有可比较的数。
    std::uint32_t demand = 0;
    /// 用度无上限（魔修与散修：设定 §8.2「资源当取尽」、§8.3 过剩人口）。
    bool unbounded_demand = false;
    /// 当年合法开采到的量。
    std::uint32_t supply = 0;
    /// 缺口 = demand − supply。
    std::uint32_t deficit = 0;
    /// 累计开采（含越采）。
    std::uint32_t extracted = 0;
    /// 累计越采。
    std::uint32_t overmined = 0;
    /// 未登记脉上的累计开采（合法 + 越采）。
    ///
    /// 口径与台账的 `Ledger::unregistered_extracted` **一致**——同一件事
    /// 必须同名同义：这份报告的用途是让人裁决哪个格局算数（§8.10），
    /// 一个同名不同义的列会让人拿它跟台账对，对不上就判定模型坏了。
    ///
    /// 散修的私采**不**计在这里：它记在「无主」这个派系的 `extracted`
    /// 名下（散修就是无主的持有者）。「未登记」说的是脉律的册子，不是
    /// 所有权。
    std::uint32_t unregistered = 0;
    /// 表决权重：8300 年名下脉的总量配额之和。
    std::uint32_t vote_weight = 0;
};

/// 派系的提案权。执掌盟约者（太玄宗）可以提前发起脉律重勘。
struct FactionIntent
{
    bool may_propose = false;
    /// 已经提出重勘的年份，0 表示还没提。
    std::uint32_t proposed_year = 0;
};

/// 脉的身份。生成后不变。
struct VeinId
{
    std::uint32_t id = 0;
};

/// 脉的固有属性。生成后不变。
struct VeinProfile
{
    world::VeinRank rank = world::VeinRank::none;
    world::Element element = world::Element::none;
    /// 阴脉：采出即衰（设定 §8.1）。
    bool yin = false;
    /// 洞天挂在这条脉上。
    std::uint32_t cave_heaven = world::kNoCaveHeaven;
};

/// 脉的制度性权利。《脉律》核定的结果，本层不改。
struct VeinRight
{
    /// 8300 年核定的总量配额。
    std::uint32_t quota_total = 0;
    /// 8300 年核定的安全流速。
    std::uint32_t quota_rate = 0;
    /// 该脉的配额是否登记在册（九幽宫那条不登记）。
    bool registered = true;
    /// 8300 年的持有者。建实体时写下，此后不变。
    ///
    /// 它与 `VeinOwner::owner` 分开是有原因的：归属会变（公有化、转让），
    /// 而「格局变化了多少」要拿当代的归属与 8300 的归属比。若只留一个
    /// 字段，转让之后就分不出「当初是谁的」与「现在是谁的」。
    history::Sect initial_owner = history::Sect::unowned;
};

/// 脉的物理状态。唯一的「真账」。
struct VeinStock
{
    /// 当代余额。
    std::uint32_t stock = 0;
    /// 累计开采（含越采）。
    std::uint32_t extracted = 0;
    /// 累计合法开采（不含越采）。
    ///
    /// 与台账的对照只能比这一项：本层的越采是缺口驱动的连续行为，
    /// 台账的越采是按年抽样的定额，两者的累计开采不可能相等。
    std::uint32_t legal_extracted = 0;
    /// 累计劫损：天地抽走的那部分。
    ///
    /// 它不进 `extracted`：台账的口径是「天地抽走的没有人该负责」，
    /// 两件事分开记。守恒式因此是「余额 + 开采 + 劫损 == 配额」。
    ///
    /// 台账是劫损的唯一来源（候选池、排期、覆盖比例都在那边算完），
    /// 本层按台账记的账在对应年份重放一遍。
    std::uint32_t tribulation_loss = 0;
    /// 当年开采量：ExtractSystem 赋值，OvertakeSystem 累加。
    ///
    /// 重勘的试算要拿「这条脉今年被抽了多少」与「转手之后会被抽多少」
    /// 比，所以当年开采量必须留在数据里，不能靠事后重算——重算时
    /// 余额已经扣过，算不出原值。
    std::uint32_t taken = 0;
    /// 当年的有效流速：ExtractSystem 算一次并记下，OvertakeSystem 复用。
    ///
    /// 一年只算一次，是「衰减率在年内不变」这条规则的落地：衰减率由
    /// 累计开采量决定，而累计开采量在年内被改写——若每个 system 各算
    /// 各的，同一条脉在同一年里会有两个衰减率，缺口与越采的分摊比例
    /// 就会用不同的分母。
    std::uint64_t eff = 0;
    /// 枯竭年，0 表示未枯竭。
    std::uint32_t depleted_year = 0;
    /// 余额被公有化的年份，0 表示未公有化。
    std::uint32_t public_year = 0;
    /// 这条脉的越采是否已经被发现过。一条脉至多报一次。
    bool overmine_reported = false;
};

/// 脉的归属。只有 ResolveSystem 写它。
struct VeinOwner
{
    history::Sect owner = history::Sect::unowned;
};

/// 年度开采量的小数余数。跨年保留，所以它是状态。
///
/// 挂成独立组件而不是塞进 VeinStock：余数是「算术的余数」，
/// 不是「账上的量」，混在一起会让守恒恒等式的代码读起来含混。
struct VeinRemainder
{
    std::uint64_t value = 0;
};

/// 洞天。
struct CaveHeavenId
{
    std::uint32_t cell = 0;
    std::uint32_t vein = 0;
};

struct CaveHeavenState
{
    history::Sect owner = history::Sect::unowned;
    bool alive = true;
};

/// 时钟。
struct SimClock
{
    std::uint32_t year = 0;
    std::uint32_t level = 0;
};

}  // namespace gamev2::faction
```

`world::kNoCaveHeaven` 是新加的哨兵，仿 `spirit.hpp` 里 `kNoVein` /
`kNoEye` 的做法：哨兵常量，不加 `optional`。

### 2.4 身份的来源：设定表与可变状态分离

派系的**不可变身份**（角色、立场、是否执掌盟约）来自设定，不进组件，
放在一张静态表里：

```cpp
/// 派系的角色。决定用度规则与开采规则。
enum class Role : std::uint8_t
{
    /// 正派宗门：用度 = 8300 年实际可采量，采到配额上限就停。
    sect,
    /// 魔修：用度无上限，采尽为止（设定 §8.2「资源当取尽」）。
    demonic,
    /// 散修与无主：用度无上限，无约束开采。
    free_cultivator,
    /// 无地（天机阁）：用度为零，不开采，不参与争夺。
    landless,
};

/// 派系的立场。决定它参不参与争夺，以及**能不能被夺**。
enum class Stance : std::uint8_t
{
    /// 参与争夺：可以提案，也可以被夺（太玄、丹霞、寒江、九幽）。
    contesting,
    /// 中立：不提案，且**不可被夺**（青囊谷三家共管、保持中立；
    /// 天机阁无地，本来也没有可夺的）。
    neutral,
    /// 孤立：不提案，**可以被夺**（万兽山与妖族共生、与人族最疏远，
    /// 没有别家来援，夺它没人拦）。
    isolationist,
};
```

角色与立场是**定性**的，不是数值旋钮：没有一个派系拥有自己的
「贪婪度 0.73」这种参数。定性的差异来自设定，数值差异来自状态。
这是本层与「每宗一组性格参数」的分界线。

**立场只管七宗之间的事**。「不可被夺」说的是七宗之间的争夺：青囊谷
三家共管，夺它要过三家那一关。无主（散修）不是一个「可以被夺的持有者」，
它是**公有池**——它的脉没有主人，谁开采得动谁接走，不需要谁同意
（§3.9）。

身份表是一处**设定给定的常量**：

| 派系 | 角色 | 立场 | 提案权 |
|---|---|---|---|
| 太玄宗 | sect | contesting | 有（执掌盟约） |
| 丹霞谷 | sect | contesting | 无 |
| 寒江剑府 | sect | contesting | 无 |
| 万兽山 | sect | isolationist | 无 |
| 青囊谷 | sect | neutral | 无 |
| 天机阁 | landless | neutral | 无 |
| 九幽宫 | demonic | contesting | 无 |
| 无主（散修） | free_cultivator | neutral | 无 |

### 2.5 与台账原语的同源

三个原语必须共用，不许各写一份：

1. **标定系数**（§3.2）：台账用它算有效流速，本层也用它。
2. **阴脉判定**：台账按「这条脉占的格子里有没有阴地」判定，本层用同
   一条规则，否则两层的「阴脉」不是同一批脉。
3. **有效流速公式**：`rate × level × F`。

实现上把这三个抽成 `history` 命名空间里的公共函数，本层调用。
这是对既有代码的**唯一**改动，且改动理由是防止两份实现静默错位，
不是重构。

## 3. 经济规则

### 3.1 潮位

潮位是纯函数：`world::compute_spirit_tide(year).level`。

三个必须记住的数：

| 年份 | level | 含义 |
|---|---|---|
| 8300 | 110 | 第九轮灵潮的峰值年。脉律的基数就编在这一年。 |
| 8301–8800 | 110 → 33 线性下行 | 衰退期 |
| 8801–8914 | 33 | 谷底期。灵脉半死，争夺最烈（设定 §2.6）。 |

潮位从 110 掉到 33，是这一刀全部戏剧性的来源：**供给缩到三成，
用度不变**。

### 3.2 有效流速与标定系数

```cpp
// 全世界的标定系数：让「若不设配额上限」的推演在当代恰好把存量采干。
// 台账与本层共用同一个值，两套推演的数字才可比。
F = sum_total / (sum_rate * integral)
```

其中 `sum_total` 是天下脉的 8300 总量配额之和，`sum_rate` 是流速配额
之和，`integral` 是 [8300, 当代) 的潮位积分。

一条脉在某年的**有效流速**：

```
eff_rate(v, y) = quota_rate(v) × level(y) × F × decay(v)
```

`decay` 是阴脉的采出即衰（§3.10），其余脉恒为 1。

台账实现里等价的形式是 `rate × level × kNum / (255 × 2^16)`，其中
`kNum / (255 × 2^16) = F`。定点累加的小数余数处理沿用台账的做法
（`kFixedScale = 1 << 16`），否则年度开采量会被截断成 0。

### 3.3 用度

**用度**是「这个派系每年要采出多少」，是需求的度量。

```cpp
// f 的脉取 8300 的持有格局（台账快照），此后不变。
demand(f) = Σ_{v ∈ f} min(eff_rate(v, 8300), quota_total(v))
```

锚在 8300 年，因为脉律是 8300 编的：**它规定的年采额，就是 8300 年的
实际开采量**。这一句是「配额之争」的数学形式。

**这条公式是实数的，而数据里存的是整数**。存法：**逐脉算出实数、按 2^16
定点累加、最后取整**。

- 逐脉取整再相加是**错的**：8300 年每脉的有效流速只有零点几个单位，
  逐脉取整会把每宗两到四条脉的小数全扔掉，用度系统性低估两到四倍，
  某些派系甚至归零——**用度归零的派系永远不会有缺口，也就不会行动**。
- 定点累加后取整保住了两件事：① 纪元那年的用度与供给是**同一个实数**
  （需求按 8300 定义、供给在 8300 也等于它），取整后仍相等 → **纪元那
  年的缺口恰好是 0**；② 每宗的用度不会因为逐脉取整而掉到 0。

**用度是常量，逐年不变，且不随持有变化**：派系失去一条脉之后，门人
还在，用度不会跟着掉。所以失脉直接变成更深的缺口——这是「宗门没了地
会怎样」在模型里的唯一表达方式。

本层不建模人口增长（已知限制，§8.4）。

角色的用度规则：

| 角色 | 用度 |
|---|---|
| sect | 上式 |
| demonic | 无上限（采尽） |
| free_cultivator | 无上限（采尽） |
| landless | 0 |

魔修与散修的「无上限」是设定给的：设定 §8.2 魔修「抽脉炼血」、§8.3
散修「每十年多一批，每百年灵脉少一批」。它们是过剩人口与过剩欲望，
制度管不住。

### 3.4 供给

```cpp
supply(f, y) = Σ_{v ∈ f} min(eff_rate(v, y),
                             quota_total(v) − extracted(v),
                             stock(v))
```

三个上限各有各的来历：

- `eff_rate`：物理吞吐。潮位折算后，脉今年能给出多少。
- `quota_total − extracted`：**制度上限**。脉律规定「采至配额上限须停采」。
  这一项在潮位低的年份用不掉，恰恰是老配额不公的第一个表现。
- `stock`：物理存量。不会变负。

### 3.5 缺口

```cpp
deficit(f, y) = demand(f) − supply(f, y)
```

缺口是本层唯一的驱动力。所有行为（越采、私采、提案、放弃）都由它触发。
缺口为零的派系不行动——**这一刀没有「主动扩张」的派系**，只有
「缺了才动」的派系。

### 3.6 合法开采

```cpp
take(v, y) = min(eff_rate(v, y), quota_total(v) − extracted(v), stock(v))
extracted(v) += take(v, y)
stock(v)     −= take(v, y)
```

这一步与台账逐位同构。**回归测试点**：把本层的越采与私采关掉，两套
推演对同一批脉的 `extracted` 序列必须逐位相等（比较范围见 §6.1）。

### 3.7 越采

**触发**：缺口 > 0，且本派系的行为规则允许。

- `demonic`（九幽宫）：随时可以。它不受脉律约束，采尽为止。
- `free_cultivator`：随时可以（同上，散修不受制度管）。
- `sect`（正派宗门）：**必须先走完重勘程序**（§3.11）才允许越采——
  当年是重勘年（或执掌盟约者当年已提过案）而程序没能满足它的缺口，
  它才越线。非重勘年，正派只能按配额采。
  正派的越采是被逼出来的，这一点与设定 §8.2 呼应：同一个真问题，
  正派先走程序，程序走不通，只好越线；魔修压根不走程序。

**越采量**：缺口先在派系名下各脉之间按**有效流速的比例**分摊（产能大的
脉多担一点），分摊后每条脉各自封顶：

```cpp
share(v)    = deficit(f) × eff_rate(v, y) / Σ_{u ∈ f} eff_rate(u, y)
over(v, y)  = min(share(v), eff_rate(v, y) × kOvertakeFactor, stock(v))
```

分摊的除法用定点做，不做浮点：同一个世界里，浮点误差会让两条脉的
分摊差一格，而这一格会顺着枯竭年传播到整份事件表。

**份额要落到整数上，落地方式必须写死**：越采是「采出多少个单位」，
余额是整数，份额因此也要是整数。分摊用**最大余额法**：各脉先取比例
份额的下界，剩下的单位按小数部分从大到小补齐。于是份额之和恰好等于
缺口，各脉的份额与它的比例份额相差不超过一。

两种简单的做法都不行。**逐脉截断**：缺口小于脉数时（缺口 3 分给 12
条脉，每脉 0.25）每一脉都截成 0，缺口整段消失——正派于是永不越采，
「越采被发现」这条事件线也永不触发。**逐脉四舍五入**：同一情形下每脉
0.25 会各得 1，总量四倍于缺口，报告里会出现越采远大于缺口的读数。

**分母只算还采得出的脉**：余额为零的脉按流速分到的那一份会被余额封
顶成 0，把它算进分母只会稀释别人那份，缺口于是凭空少一块。

`kOvertakeFactor` 是世界常数（取 2，标定项，§8.6）：越采能采到比流速
更多的量，因为它是强行抽取，代价是把这口井抽废。

**代价**：

1. 余额更快归零 → 枯竭更早 → 公有化更早（§3.9）。
2. **被发现**：登记在册的宗派越采会被仲裁发现。发现按年判定，
   每年 1/8 的概率；**一条脉至多报一次**（报过就不再报）。不登记的
   （九幽宫那条、散修的私采）不被发现。

   概率是 1/8 而不是「每年必报」：发现在本层只是读数（§8.2 声望
   没有后果），报得太密会把事件表淹掉；至多一次又保证它不会
   变成一条每年重复的噪音。

**本层不建模声望的后果**：发现只产生事件与输出，不改变行为。这是一条
诚实的限制（§8.2），因为「声望 → 实力 → 争夺能力」需要一整套声望模型，
而这一刀的核心是格局。

### 3.8 私采

**私采 = 无约束开采**，本层只有一种：散修与无主对无主脉的开采不受
配额约束。

**这里本层与台账不同，必须说清楚**：台账的实现里，无主脉仍然受它
自己的总量配额约束（台账的 `quota_left` 封顶对所有脉一视同仁），
台账设计 §9 的「无主脉按潮位比例开采，不设配额上限」说的是「不设
宗门的份额」，不是「采到脉干为止」。本层取**后者**：散修的用度无上限
（§3.3），他们会越过配额开采，把无主脉抽干。

这是刻意的分歧：本层要算的是「散修的过剩人口把天下公有资源吃光」
（设定 §8.3），而台账是制度基准，不该替散修越权。差异在 §6.1 里被
明确排除在等价性比较之外。

**跨派系偷采本层不做**（散修盗采他人名下的脉）。理由：偷采需要追查、
仲裁与惩罚，是一整套司法机制，属于后续纵切。做半套比不做更坏：
它会让「越采被发现」的规则出现第二个含义。

荒脉的盗采也不做：荒脉无灵眼、不可采（台账 §3.1），没有可抽的存量。

### 3.9 枯竭与公有化

```cpp
if (stock(v) == 0 && depleted_year(v) == 0) depleted_year(v) = y;
```

枯竭的脉**不可复生**（设定 §2.3：枯眼不可复生）。它随即**公有化**：
归属变为「无主」，因为一个已经抽干的脉对原持有者没有价值，而它也不
该继续占着一个名字。

公有化是**物理程序，不需要表决**：没有产出的东西不构成政治利益。
这是本层格局变化的主要来源之一。

公有池里的**已枯竭**脉不再分配：库存为零，分配给谁都没用。公有化的
意义是「这个名字空出来了」——它让格局变化在数字上可见（持有脉数、
持有余额），也让派系的用度失去支撑（§3.3 的用度是 8300 年定的常量，
派系失去了脉，供养门人的能力却不会消失 → 缺口更深）。

但**无主派系名下未枯竭的脉是可以被转移的**：它们是散修手里的活脉，
而散修的余力为零（采尽为止，余力自然归零）→ 按 §3.11.3 的清单规则，
它们会被有余力的派系接走。设定 §8.3 说「散修最大的敌人不是宗门，是
资源恒定而人数增长」——本层把「宗门」这一条算出来了：**收编公有支脉
就是散修出路的关闭**。

### 3.10 阴脉的采出即衰

设定 §8.1：寒江剑府所持的是「一条阴脉（采出即衰）」。

```cpp
decay(v) = yin(v) ? max(0, quota_total(v) − extracted(v)) / quota_total(v) : 1
```

即：阴脉的产出随累计开采线性衰减，采完为止。非阴脉的 `decay` 恒为 1。

**这是物理属性，不是派系性格**：阴脉采出即衰是地脉的性质，寒江只是
恰好分到一条。于是寒江的结构性赤字**从状态里长出来**，不需要给
寒江写任何参数——它会自己越来越穷、越来越铤而走险。

### 3.11 脉律重勘：提案、清单、表决

设定 §6.5：「脉律每二百年重勘一次——上一次重勘在灵历 8300 年前后，
距今六百余年」。

**注意这条设定的推论**：8300 + 200 = 8500，+ 200 = 8700，+ 200 = 8900。
按「每二百年一次」，当代之前应该已经重勘过两次。但设定同时说
「上一次重勘在 8300 年前后」——**当代的格局还是 8300 年定的**。

这两个说法只有一种调和：**重勘提了**。至于通过与否，本层的模型给出
的答案与最初的设想不同——**提案会通过**（§3.11.5 的规则），所以推演出来
的当代格局**不是** 8300 的那个格局：十九条脉换了主人。

也就是说，设定 §8.1 的参照持有表与本层的推演结果**不一致**。本层不为了
迎合那张表去改规则（那会让模型变成设定的复述），而是把差异摆在台面上：
导出的格局文本里并列两边的持有脉数，由人裁决哪个算数（§8.10）。

#### 3.11.1 一个必须先讲清的事实

**转移一条脉，不改变世界的总供给，也不改变总缺口。**

- 总需求 = Σ demand(f)，而 demand 是 8300 年定的常量（§3.3）。
- 总供给 = Σ_v min(eff_rate, quota_left, stock)，**与归属无关**：
  脉给谁都是那个产出。

所以「重新分配能不能让天下过得好一点」这个问题，在总量上的答案是
**否**。表决不能看总量——看总量的话，任何提案都通不过，僵持就变成
死局，而不是推论。

**归属真正改变的是分配效率**：同一口井，给一个开采不动它的派系，
和给一个开采得动的派系，一年下来抽走的量不一样。

#### 3.11.2 余力：还有多少井底子可以慢慢采

```cpp
// 当年开采量（含越采）。
take_all(v, y) = take(v, y) + over(v, y)

// 余力：名下脉的存量，减去当年已经开采掉的部分。
// 余力大 = 井还满、且这个派系采得动（它的开采还没把井底子掏空）。
slack(f) = Σ_{v ∈ f} stock(v) − Σ_{v ∈ f} take_all(v, y)
```

三种典型：

| 派系 | 余力 | 含义 |
|---|---|---|
| 太玄宗 | 大 | 井还满，它采得动（缺口是需求大，不是没得采） |
| 寒江剑府 | 接近 0 | 它的井在衰，它在拼命抽 |
| 无主（散修） | 0 | 采尽为止，井底子早空了 |

**余力是候选排序的依据，不是表决的依据。** 表决看的是总量口径下的
开采变化（§3.11.4）。

#### 3.11.3 提案与清单

**提案的触发**：

- 例行：每 200 年（8500、8700、8900）。
- 提前：执掌盟约者（太玄宗）可以提，但**两次重勘的间隔不得小于 50 年**
  （`kEarlyRedraftInterval`）。提案与表决是大事，不能年年开；50 年
  是「一代人的功夫」这个量级的程序性间隔，不是经济参数。

**表决的权重**：**配额份额**——该宗在 8300 年名下脉的总量配额之和，
按整数份额比较。

不用「用度份额」的理由：魔修与散修的用度无上限（§3.3），拿它当权重
算不出比例；而配额份额是制度里的既成事实——《脉律》本就按配额分派。

**无主的权重恒为 0**：它不在盟约里，没有席位。天机阁无地，权重也是 0；
而魔修的用度虽然无上限，它的**配额**是有数的，所以它有票。

**清单的生成**（提案者按状态构造，逐条脉评估）：

对每条脉 v，现任持有者 O，最优候选 C（候选按余力降序、派系编号升序
取第一个；候选的立场须为 contesting，且不能是现任持有者 O——把脉转给
自己不是转手，试算的前提就没有了）：

```
试算：把 v 转给 C 之后，C 对 v 的当年开采量（合法 + 按 C 的缺口分摊
      的越采）是否小于 O 当年对 v 的开采量 take_all(v, y)？
是 → 列入清单
```

**受益方由余力决定，不由提案决定**：提案者（执掌盟约的太玄宗）只是
发起者，不是优先者——它握着最大的余力，却收不回自己开采不动的那几条
脉，那些脉会落到别的有余力的派系名下。这是规则算出来的结果，不是
bug：规则说的是「把开采不动的东西交给开采得动的人」（§3.11.3），
受益方是谁由当下的余力排序决定。设定 §8.1 的参照持有表因此**不保证
被复现**（§8.10），差异摆在导出的对照表里由人裁决。

**谁能被夺**：

| 现任持有者 O | 能否转手 |
|---|---|
| 七宗，立场 `contesting` 或 `isolationist` | 能。受损方在表决里反对，但没有否决权。 |
| 七宗，立场 `neutral`（青囊谷三家共管） | 不能。夺它要过三家那一关。 |
| 无主（散修） | 能。**公有池不是「谁的私产」**，它没有主人，也就没有人要同意。它不在表决里（没有席位，§3.11.3）。 |

**这是一个小试算，不是重跑全年**：只涉及受影响的两个派系与这一条脉。

试算里的越采份额按 §3.7 的定点比例份额取整（四舍五入）：小试算算不
出候选名下其他脉的下界，给不出最大余额法的最终份额，只能给比例份额
的舍入值——与真实分摊相差至多一个单位。

理由：把开采不动的东西交给开采得动的人，抽走的量变少，**世界留下的
存量变多**。这正是设定 §6.5「按实际承载力重新分配」的字面意思。

**提案者为什么这么干**：太玄宗是最大的持有者，潮位下行时它的缺口也
最大；它的余力也最大（井还满，它采得动）。所以它构造出的清单通常就是
「把开采不动的派系的脉收过来」——**既自利，又在算术上成立**。

#### 3.11.4 表决

每一宗对整份清单表态：

- **受益方**（清单里得到脉的）：赞成。
- **受损方**（清单里失去脉的）：反对。
- **无利害方**：赞成当且仅当**清单生效后当年的总开采量不增加**
  （世界少抽一点，存量多留一点）。

**通过门槛**：赞成的配额份额 > 全部配额份额的一半。

**受损方没有否决权**：盟约是「七宗共推」的机构（设定 §6.5），表决是
多数决，不是全体一致。

**这条判据的诚实说明**：清单的构造规则（§3.11.3）已经只收「转移后
开采量下降」的条目，所以无利害方在实践中总是赞成。表决实际由
**受损方的用度份额能否拖过一半**决定。

判据仍然写明，有两个用处：它是对清单构造的**校验**（试算与清单
不一致时，表决会把它否掉而不是放行），以及它让「重划」这件事有
一条公开的、所有人都能自己算的准绳——不是「盟约说了算」。

#### 3.11.5 这个规则会得出什么

- 太玄的提案把脉从「开采不动」的派系转给有余力的派系 → 当年总开采
  下降 → 无利害方赞成 → 太玄（约四成配额份额）加上无利害方 → **通过**。
- 受损方（寒江等）反对，但反对不占多数 → 抵制失败。
- **僵持的两种来源**：
  1. 受损方的配额份额过半（被夺的是大宗）→ 否决。
  2. 所有人都没有余力了（世界已经榨干）→ 清单为空 → 没有可重划的
     东西 → 提案空转。

第二种在谷底期是必然的：**全天下都榨干之后，脉律就无从重划**。
设定 §10.1 说「老配额不公」，而重划通道堵死，正是「不公」能持续
六百年的原因。

于是设定 §10.1 的第一个冲突被算了出来：**太玄宗主张「按实际承载力
重新分配」，这个主张在数字上是对的**——它确实让天下剩下的存量更多；
而它同时也是在自肥。设定 §8.2 说「正派确实在用『公义』掩盖『垄断』」，
本层把这句话变成一条可复算的算式：**分配的效率，而不是总量，决定
谁能重划。**

**驳回也要记事件**：提案被否的年份与理由（总开采将增加）要出现在
事件表里——史官要知道这件事发生过。

### 3.12 洞天

洞天绑在它所在福地的灵脉上（按 `cell` 反查 `vein_id` 网格）。

- 该脉枯竭 → 洞天失效（事件）。
- 洞天失效**不改变动力学**：灵石供养与洞天产能本层不建模（§8.3）。

洞天在本层是**读数与事件**，不是驱动量。理由：设定 §2.5 说洞天
「是用灵石供养的蓄电池」，要让它影响经济就必须先有灵石账，而灵石
账是本层明确不做的那一块。做一个半吊子的「洞天产能」比不做更坏：
它会让人以为算过了。

### 3.13 每年的系统序列与读写集

一年的推演是 7 个 system 按固定顺序跑。**顺序由 `System::order` 显式
声明**：每个 system 写死自己在这 7 步里的次序，下表的序号就是它的
`order` 值。`Scheduler::plan` 先按 order 稳定排序再贪心分层，冲突者
自动落到后一批，读者自动落到写者之后。

order 只在两个 system 本来就会冲突时才兑现批次先后。这 7 对两两冲突
——时钟被所有人读，`VeinStock` 与 `FactionBalance` 被多人写——所以
order 说的就是批次先后。注册顺序只作同 order 时的次级键。

早先这里写的是「注册顺序即冲突系统的执行顺序」。那是把语义押在注册
代码不动上：调度器一改分层规则，次序就静默漂移，而漂移不报错，只改数
字。改成显式 order 之后，次序写在 system 自己身上。

| # | System | 读 | 写 |
|---|---|---|---|
| 1 | `ClockSystem` | — | `SimClock` |
| 2 | `TribulateSystem` | 时钟、脉的物理状态 | `VeinStock` |
| 3 | `AssessSystem` | 全部脉、派系身份 | `FactionBalance` |
| 4 | `ExtractSystem` | 时钟、脉、脉的归属 | `VeinStock`、`VeinRemainder`、`FactionBalance` |
| 5 | `OvertakeSystem` | 时钟、缺口、脉 | `VeinStock`、`FactionBalance` |
| 6 | `DepleteSystem` | 脉 | `VeinStock`、`CaveHeavenState` |
| 7 | `ResolveSystem` | 全部 | `VeinOwner`、`VeinStock`（公有化年份）、`FactionIntent`（提案年） |

**劫损排在开采之前**：劫云在年内抽干，被抽走的那部分配额不该再被
人采走——台账的年序是「越采 → 劫损 → 正常开采」，本层的越采在开采之后，
但劫损必须赶在开采之前。这条顺序错了，劫损就只剩一个不影响任何数字的
装饰：被劫过的脉照样能被人采到满配额，两层的余额也就永远对不上。

**劫损的来源只有台账**：候选池、排期与覆盖比例都在时序层算完（那里是
唯一知道劫云在哪、圈住哪些脉的地方），本层按台账记的账在对应年份重放
一遍。重放的是**记账值**（当年抽走多少），不是覆盖比例：同一个劫云，
抽走的量是既成事实，不是本层要重算的量。本层的余额若装不下那一笔
（多半是自己的越采先抽走了一部分），按余额封顶并计入诊断量
`tribulation_shortfall`——两层对这条脉的余额因此不等，报出来，不假装
一样。

**`VeinStock::public_year` 是「写而不读」的字段**：公有化的年份已经在
`vein_publicized` 事件里，报告也不读它。它给 `VeinStock` 添了第五个
写入者。这条留给最终整枝审阅分诊——要么删字段，要么让它进报告。

两条纪律：

1. **唯一的写入者**：`VeinOwner` 只有 `ResolveSystem` 写。所有归属
   变更（公有化、转让）都在这一步发生，别的 system 一律不碰。
2. **不做跨实体聚合的写**：所有写入都落在「本实体自己的组件」上。
   派系级汇总是先由 `AssessSystem` 读脉写派系，不是在脉的循环里
   往派系上加。
3. **单调变化的字段可以有多个写入者**：`VeinStock::extracted` 由
   `ExtractSystem`（合法开采）与 `OvertakeSystem`（越采）各自 `+=`；
   `VeinStock::stock` 由两者各自 `-=`；`FactionBalance::extracted` 同理。
   几处都写同一个组件，写集冲突保证它们分属不同批次，不会丢更新——
   累加/递减要的是「都加上去、都减下去」，不是「谁最后写谁说了算」。
   **但读集不能因此放宽**：读集描述的是真实的数据依赖，一条不存在的
   依赖进图里，冲突图就不再是图。

**一年的快照语义**：同一年里，所有 system 看到的**衰减率**与**有效流速**
都是同一个值。

衰减率由累计开采量决定，而累计开采量在年内被 `ExtractSystem` 改写——
若每个 system 各算各的，同一条脉在同一年里会有两个衰减率：评估算的是
年初的，越采算的是开采后的，缺口的分母与越采的分摊比例就用了不同的
数。

**落法**：`ExtractSystem` 算出当年的有效流速后记进 `VeinStock::eff`，
`OvertakeSystem` 复用它，不再重算。

`AssessSystem` 在 `ExtractSystem` 之前跑，它算的是**年初口径**的供给，
用的是精确实数的定点值（§3.3/§3.4 的累加口径），**不消费真实余数**——
余数是开采量的机制（把每年的小数零头带到下一年），评估消费它就变成了
第二次开采。供给因此是「这条脉今年能给出多少」，与实采量至多差一个
截断单位，方向单一、量级可忽略。

**用度与供给都是逐脉定点、整层取整**（§3.3 的约定）：纪元那年的用度与
供给是**同一个实数**，取整后仍相等 → **纪元那年的缺口恰好是 0**。这是
要守的不变式：缺口只在潮位下行与阴脉衰减之后才出现。

**事件类型**（本层的事件表只有这几种，多了就是没想清楚）：

| 事件 | 何时 |
|---|---|
| `redraft_proposed` | 有人提出重勘 |
| `redraft_passed` | 表决通过 |
| `redraft_rejected` | 表决被否（附理由） |
| `vein_transferred` | 脉换了持有者（附年份、双方） |
| `vein_depleted` | 脉枯竭（附年份） |
| `vein_publicized` | 枯竭的脉公有化 |
| `overmine_discovered` | 越采被发现（附年份、派系、脉） |
| `cave_heaven_lost` | 洞天失效（附年份、洞天） |
| `tribulation_toll` | 劫损（附年份、脉、抽走多少；无主体） |

**为什么全部用 `each` 不用 `each_parallel`**：`View::each_parallel`
把任务提交到 `world` 的池，而批内多 system 执行时调度器会置位
`in_system_`，此时 `parallelize_allowed()` 为假，`each_parallel`
退化为串行。也就是说 `each_parallel` 的行为**依赖 system 在批内的
位置**，这让「同一套 system，不同的调度计划，结果不同」成为可能。
本层规模不需要并行，一律用 `each`：遍历顺序确定，结果可复算。

### 3.14 随机与派生的位置

本层需要随机的只有一处：**越采被发现的年份**。

（散修在无主脉之间的开采分配按有效流速比例分摊，是确定的，不需要
随机。）

**随机必须无状态派生**：按 `(年, 派系, 脉)` 哈希出种子，直接求值，
不依赖遍历顺序。这是 `world/rng.hpp` 的既有约定（无状态噪声不依赖
遍历顺序，否则仅仅调整循环次序就会换一个世界）。

新增一条随机流 `Stream::faction = 18`，并同步改 `kStreamIds`
（枚举旁的注释写着「新增一条流必须同改」）。

### 4.1 世界常数

| 常数 | 值 | 性质 |
|---|---|---|
| `kOvertakeFactor` | 2 | 标定项。越采能采到流速的几倍。 |
| `kRedraftPeriod` | 200 | 设定给定（脉律每二百年重勘）。 |

`kOvertakeFactor` 是本层唯一一个新造的数值常数，且它有明确来源：
越采是强行抽取，能采到比流速更多的量，但会把这口井抽废。它的具体

| 流 | 用途 |
|---|---|
| `Stream::faction` | 越采被发现的年份 |

沿用台账的 `kMaxSpanYears = 100000`。本层的推演跨度就是循环次数，

## 5. 错误处理与诊断量

退化不是错误，由诊断量报出，由调用方决定要不要打印。这条规矩来自
台账设计 §5 与灵气层设计 §5，本层照办。

```cpp
struct FactionDiagnostics
{
    /// 台账不可用（当代早于纪元、台账为空）。
    std::uint32_t no_baseline = 0;
    /// 换算系数整除成 0：推演不出任何开采量。
    std::uint32_t conversion_collapsed = 0;
    /// 跨度超限：按「没有推演」处理。
    std::uint32_t span_too_large = 0;
    /// 提案被驳回的次数。
    std::uint32_t redraft_rejected = 0;
    /// 提案通过的次数。
    std::uint32_t redraft_passed = 0;
    /// 公有化后仍挂在原持有者名下的脉数（内部一致性错误）。
    std::uint32_t public_release_mismatch = 0;
    /// 守恒对账不通过的脉数。
    std::uint32_t conservation_broken = 0;
    /// 台账记的劫损没有足额施加的笔数。
    ///
    /// 本层的余额比台账低——多半是本层自己的越采先抽走了一部分（散修
    /// 采尽为止，无主脉上最常见），井空了劫云就抽不走什么。两层对这条
    /// 脉的余额因此不等，报出来，不假装一样。
    std::uint32_t tribulation_shortfall = 0;
};
```

**守恒恒等式**（本层的基本正确性判据）：

```
对每条脉：quota_total + recovered == stock + extracted + tribulation_loss
```

本层不建模恢复（§8.1），所以 `recovered` 恒为 0，恒等式退化为：

```
quota_total == stock + extracted + tribulation_loss
```

越采不会让它崩：越采也是从 `stock` 里扣的，`stock` 不会变负。

**劫损是第三项，不是开采的一部分**：天地抽走的那部分没有持有者、没有
配额，谁也不为它负责。它单独占一格，报告与台账同名同义。

## 6. 测试策略

### 6.1 与台账的等价性

**核心回归测试**：本层的**合法开采**（不含越采）逐年序列，必须与台账
的合法开采逐年序列逐位相等。这一条守住「两套推演可比」这个前提。

**比较范围**：台账里 `overmined_amount == 0`、持有者不是「无主」、
且不是阴脉的脉。排除这三类各有理由：

- **越采脉**：台账的越采是一笔按年抽样的定额，本层的越采是缺口驱动的
  连续行为，两者本就不同（§3.7）。台账的越采在该年之前扣除，会压低
  该年的合法开采，所以不能整条比。
- **无主脉**：台账里无主脉仍受它自己的总量配额约束；本层的散修用度
  无上限（§3.3），会越过配额开采。
- **阴脉**：台账不建模「采出即衰」，本层建模（§3.10）。阴脉的合法
  开采在本层里逐年递减，两边必然不等。

**比较的是累计合法开采**（不含越采），不是累计总开采。台账那侧的
合法开采从事件表里取（`over_quota == false` 的事件按脉汇总）。

**劫损也要对上**：台账把劫损算进了余额（`balance = 配额 − 开采 − 劫损`），
本层若不认这一项，两层对同一条脉就给出两个余额——实测默认图幅上
太玄宗的龙脉在台账里「8859 年被抽干、余额 0」，本层却报「还剩 387、
还没枯」。可比集上每条脉的劫损必须与台账逐位相等；装不下那一笔的
（多半是本层自己的越采先抽走了一部分）按余额封顶并计入诊断量
`tribulation_shortfall`——那一条脉上两层的余额就是不等，报出来。

### 6.2 守恒

对每条脉、每一年：`stock + extracted + tribulation_loss == quota_total`；
`stock >= 0`；`extracted` 与 `tribulation_loss` 单调不减。

### 6.3 确定性

同一 seed 两次推演，事件表逐行相同。

**「并行度不同结果也相同」这条不适用**：本层不追求并行（§2.1），调度器的
工作线程数固定为 1（`View::each_parallel` 的行为依赖 system 在批内的
位置，见 §3.13）。可复算性由「无状态派生的随机 + 固定的遍历与排序
次序」保证，这两条都要有测试守着：

- 随机按 (seed, 流号, 年, 派系, 脉) 派生，与遍历顺序无关；
- 清单按脉编号升序生成、候选按余力降序再按编号升序，事件按 system
  顺序追加。

**这条测试要跑在会产生随机、也会产生格局变化的世界上**：小图幅上
年流速截断为 0、越采不触发（§3.7），全层唯一的随机源一次都不会被
调用——守着一个不产生随机的世界，等于没守。

### 6.4 涌现性

**验收标准**（用户已拍板）：

1. 固定 seed → 同一份当代格局可复算。
2. 守恒对账通过。
3. **至少一次格局变化**：当代的「脉 — 持有者」映射与 8300 的映射不同
   （至少一条脉的持有者变了，或某宗持有的脉数变了），且这个变化
   **不是代码里写死对应设定 §10.1 的**。

第 3 条要能自动判定：测试比对两张映射表，而不是比对某个具体的
「太玄宗失去了某条脉」。

### 6.5 退化路径

当代早于纪元、换算系数塌缩、跨度超限、空世界——每条都要有测试，
且诊断量要报出。

### 6.6 边界值

- 潮位最低的年份（level = 33）：供给只剩三成，是缺口最大的年份。
- 阴脉采完的那一年：`decay` 归零，供给为零。
- 重勘年（8500/8700/8900）与非重勘年的行为差异。

## 8. 已知限制与风险

以下限制在实施后仍然成立。逐条写清楚，比事后被人问起好。

### 8.1 不建模灵脉恢复

设定 §6.5「采至配额上限须停采，待灵脉自行恢复」——本层没有恢复。
余额只减不增，枯竭是永久的。台账也没有恢复（台账的模型里「采满就停」
只是不再开采，存量并不回补），两层的口径一致。

**要加恢复就必须同时改台账**，否则对照表失效。

### 8.2 声望只有事件没有后果

越采被发现只产生事件，不影响派系的实力或被夺的难易。声望 → 实力
需要一整套声望模型。本层的冲突强度由**物理**（潮位、枯竭、余额）
驱动，不由声望驱动。

### 8.3 洞天只有事件没有产能

洞天失效是事件，不是经济变量。见 §3.12。

### 8.4 不建模人口

用度是 8300 年定的常量。设定 §8.3「每十年散修多一批，每百年灵脉少
一批」的过剩人口没有建模，所以**散修的绝对压力被低估**：它只有
「无上限开采」这一条，没有需求增长。

### 8.5 台账的持有格局是设定的，不是推出来的

8300 年的起点仍然来自台账，而台账的持有格局是设定给定的（台账
§8.1）。本层只让 8300 **之后**的格局变成涌现的；8300 之前仍然是
设定。这是有意的边界：设定里 8300 之前有伐脉之战（灵历 1040），
推演它会变成凭空造设定，违反 worldview §12 红线第 1 条。

### 8.6 换算系数是标定值

`F` 的锚点（「若无配额封顶，世界在当代恰好耗尽」）是一个选择，
不是从设定推出来的。换一个锚点，枯竭的分布会平移，但格局的**结构**
（谁缺、谁富、僵持还是通过）不变。

`kOvertakeFactor` 同理：它只影响枯竭早晚，不影响谁在争夺。

### 8.7 绝对数字不可跨图幅比较

`vein.reserve` 在 worldgen 里是归一化过的无量纲指数，所以「8300 年
储量 737」这种数只在本图幅内有意义。与台账的结论同源。

### 8.8 与 worldgen 的枯竭标记不一致是预期的

worldgen 按身份哈希标枯眼，与经济性无关；本层按推演判枯竭。两者
不一致时**报冲突，不假装一致**（沿用台账的做法）。

### 8.9 没有并行收益

见 §2.1。本层的规模下并行是零收益，`each_parallel` 反而会引入
不确定性。

### 8.10 不保证复现设定 §8.1 的当代持有表

设定 §8.1 给了七宗各自的持有脉数（太玄宗龙脉 + 三条主脉，等等）。
那是**设定给定的 8300 分配**（时序层的起点），不是当代的实际布局。

本层推演出来的当代布局**可能与它不同**：太玄宗的提案若通过，它会
多拿几条脉；寒江剑府的阴脉若枯竭，它会一条不剩。这正是本层要做的
事——把设定给定的格局换成涌现的。

两张表的差异由对照表报出（§0.4）。若推演结果与设定冲突，**要人来
裁决哪个算数**，不是让代码去迎合设定。

### 8.11 余力是抽象，没有人手与器具

「余力」（§3.11.2）是把「开采能力」压缩成一个量的做法：井还满、
且这个派系还有余量去慢慢采，它就开采得动。它没有建模人手、器具、
阵法、丹药这些真正决定开采能力的资源。

这条限制的代价是：本层算不出「大宗门的开采能力也会到达上限」这种
上限效应，所以余力大的派系在本层里是**无限的**。要修这一条，得先
有资源经济那一刀（§0.3 里明确不做的那块）。

### 8.12 劫损是台账的记账值，本层不重算

劫云抽走多少由台账算好（候选池、排期、覆盖比例都在时序层），本层按
那个记账值在对应年份重放。**重放的是绝对量，不是覆盖比例**——同一个
劫云抽走的量是既成事实。

代价：本层的余额若比台账低（多半是自己的越采先抽走了一部分），那一笔
就装不下，按余额封顶。那条脉上两层的余额因此不等，由诊断量
`tribulation_shortfall` 报出。实测默认图幅上有一到两笔，多半在无主
脉上——散修在本层采尽为止，井常常先被采空。

另一个代价：**两层对同一条脉的合法开采可能差几个单位**。越采与劫损
争抢同一条脉的余额，谁先拿走哪一份两层的分配本就可能不同；余额对得上
（「余额 + 开采 + 劫损 = 配额」），拆开来的比例未必对得上。

## 9. 已拍板的决定（2026-10-22）

| # | 决定 | 理由 |
|---|---|---|
| 1 | 时间跨度：8300 → 当代 614 年 | 把设定给定的持有格局换成涌现的。推演未来是另一件事。 |
| 2 | 状态全在 ECS 组件里 | 单一写入者；ECS 第一次有真实用途。 |
| 3 | 行为来源：状态驱动 + 设定给的角色与立场 | 定性差异来自设定，数值差异来自状态。没有逐派系的性格参数。 |
| 4 | 验收：可复算 + 守恒 + 至少一次格局变化 | 「可生成」不等于「有戏」。格局变化必须能被自动判定，且不能是写死的。 |
| 5 | 复用 `history::Sect` 作派系枚举 | 两个枚举会静默错位。 |
| 6 | 派系集合 = 七宗 + 无主，共 8 个 | 与台账同口径。 |
| 7 | 抽三个原语到 `history/quota.hpp` 共用 | 两份标定系数会让对照表失去意义。 |
| 8 | 新增 `Stream::faction = 18` | 与台账的随机流不共用。 |
| 9 | 全部用 `each`，不用 `each_parallel` | `each_parallel` 的行为依赖 system 在批内的位置。 |
| 10 | 不建模灵石、人口、恢复、声望后果 | 本刀只做一条纵切。半吊子的子系统比没有更坏。 |
| 11 | 用度锚定在 8300 年的实际开采量，且此后不变 | 脉律是 8300 编的，它规定的年采额就是那年的实际开采量。 |
| 12 | 表决看**分配效率**（总开采量），不看总量 | 转移不改变总供给与总缺口，看总量则任何提案都通不过，僵持成了死局。 |
| 13 | 受损方无否决权，盟约按**配额份额**过半数 | 设定 §6.5：七宗共推的盟约，多数决而非全体一致。用度对魔修与散修无上限，不能当权重。 |
| 14 | 越采只在缺口 > 0 时发生；正派先走重勘程序 | 正派的越采是被逼出来的，与魔修的主动越采在设定里是两种东西。 |
